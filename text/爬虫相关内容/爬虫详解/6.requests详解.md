# requests 模块 详解

## 一、requests 简介

`requests` 是 Python 中最流行的 HTTP 请求库，基于 urllib 封装，语法简洁、功能强大，是爬虫开发的首选。

```bash
pip install requests
```

### 基本使用

```python
import requests

url = "https://www.baidu.com"

# GET 请求
response = requests.get(url)

# POST 请求
response = requests.post(url)

print(response.text)   # 打印 str 格式的响应内容
```

### 完整的请求参数

```python
import requests

url = "https://www.baidu.com"
my_headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...",
    "Referer": "https://www.example.com/",
}
my_data = {"username": "alex", "password": "123456"}   # POST 请求体
my_params = {"page": 2, "size": 10}                    # URL 中的查询参数
my_proxies = {
    "http": "http://12.34.56.79:9527",
    "https": "https://12.34.56.79:9527",
}

response = requests.post(
    url=url,
    headers=my_headers,     # 头信息
    data=my_data,           # POST 请求体
    params=my_params,       # 查询参数（无论 GET/POST，URL 里的参数都写这里）
    proxies=my_proxies,     # 代理地址
    timeout=10,             # 超时（秒）
)

print(response.text)
```

> 提示：`params` 与请求方式无关，凡是出现在 URL 里的参数都可以写在 `params` 里；`data` 只用于 POST 的请求体。
>
> 如果 `response.text` 是 `\uxxxx` 这种形式，说明响应是 JSON，直接用 `response.json()` 解析成字典即可。

## 二、response 常用属性

| 属性 | 类型 | 说明 |
| ---- | ---- | ---- |
| `response.text` | str | 响应体（自动解码的文本） |
| `response.content` | bytes | 响应体（原始字节，下载图片/文件用） |
| `response.encoding` | str | 响应内容的编码方式 |
| `response.status_code` | int | HTTP 状态码 |
| `response.headers` | dict | 响应头 |
| `response.request.headers` | dict | 本次请求对应的请求头 |
| `response.cookies` | CookieJar | 响应携带的 cookie |
| `response.url` | str | 访问的最终 URL |
| `response.json()` | dict/list | 把 JSON 响应解析成 Python 对象 |
| `response.ok` | bool | 状态码小于等于 200 时 True（实际为 200~299） |
| `response.apparent_encoding` | str | 从内容中推测出的编码 |

### 代码演示

```python
import requests

resp = requests.get("https://www.baidu.com")

print("状态码:", resp.status_code)
print("编码:", resp.encoding)
print("URL:", resp.url)
print("请求头:", resp.request.headers)
print("响应头:", resp.headers)
print("文本内容(前100字):", resp.text[:100])
print("字节内容(前100字节):", resp.content[:100])
print("是否成功:", resp.ok)
```

## 三、response.text 与 response.content 的区别

| 对比项 | `response.text` | `response.content` |
| ------ | --------------- | ------------------ |
| 类型 | str | bytes |
| 解码方式 | requests 根据 HTTP 头自动推测编码 | 未指定编码，保持原始字节 |
| 如何改编码 | `response.encoding = "gbk"` | `response.content.decode("utf-8")` |
| 适用场景 | 网页源码、文本 | 图片、音频、视频、文件下载 |

### 获取网页源码的通用方式（按优先级尝试）

```python
# 方法1：content 直接 decode（默认 utf-8）
html = resp.content.decode()

# 方法2：指定编码 decode
html = resp.content.decode("UTF-8")

# 方法3：text（requests 自动推测）
html = resp.text
```

> 从上到下依次尝试，基本能解决 100% 的网页解码问题。推荐优先使用 `resp.content.decode()`，因为 `content` 才是"真正的内容"，`text` 只是它的解码结果。

### 乱码的三大原因

1. **压缩格式未解压**：`response.text` 全是乱码，连 HTML 标签都是乱码 → 检查请求头是否缺少 `Accept-Encoding: gzip`，或使用 `resp.content` 后再处理；
2. **字符编码不对**：能看见标签但中文乱码 → requests 默认用 GBK 猜测，可设置 `resp.encoding = resp.apparent_encoding` 自动识别；
3. **字体缺字**：系统中没有该字符 → 换字体或用图片代替（如某些反爬字体加密）。

## 四、实战：下载图片到本地

```python
import requests

# 图片的 url
url = "https://www.baidu.com/img/bd_logo1.png"

# 响应本身就是二进制图片
response = requests.get(url)

# 以二进制 + 写入的方式保存
with open("baidu.png", "wb") as f:
    f.write(response.content)

print("图片下载完成")
```

> 下载图片、视频、PDF、Excel 等所有二进制资源，都用 `resp.content` 配合 `wb` 模式写入。

## 五、使用代理

### 1. 理解代理的过程

```
浏览器/爬虫 → 代理服务器 → 目标服务器
```

### 2. 正向代理 vs 反向代理

| 类型 | 谁在隐藏 | 举例 |
| ---- | -------- | ---- |
| 正向代理 | 隐藏客户端（服务器不知道真正客户端是谁） | VPN、爬虫代理 |
| 反向代理 | 隐藏服务器（客户端不知道真正服务器是谁） | Nginx 负载均衡 |

### 3. 代理的使用

```python
import requests

proxies = {
    "http": "http://12.34.56.79:9527",
    "https": "https://12.34.56.79:9527",
}
resp = requests.get("http://httpbin.org/ip", proxies=proxies, timeout=5)
print(resp.text)   # 返回的是代理服务器的 IP
```

### 4. 代理 IP 的分类（按匿名程度）

| 类型 | 隐藏程度 | 说明 |
| ---- | -------- | ---- |
| 透明代理 | 最差 | 服务器知道你在用代理，且知道你的真实 IP |
| 普通匿名代理 | 中 | 隐藏了真实 IP，但服务器能检测到在用代理 |
| 高匿代理 | 最好 | 不改变请求，服务器完全看不出在用代理 |

> 爬虫中**优先选择高匿代理**。

### 5. 按协议分类

- HTTP 代理
- HTTPS 代理
- SOCKS 代理

> 需根据目标网站的协议（http/https）选择对应类型的代理。

### 6. 使用代理的注意点

- **反反爬**：即使用了代理，服务器仍可通过访问频率、Cookie/UA/Referer 校验、代理 IP 库等检测爬虫；
- **随机使用**：不要每次都用一个代理 IP，应随机切换，避免被识别；
- **IP 池维护**：购买的代理 IP 很多（超过 60%）不可用，需要程序检测可用性并剔除坏 IP；
- **免费代理源**：可用性差，需要自己验证。

常见代理获取平台：

- http://www.66ip.cn
- https://ip.jiangxianli.com
- https://www.zdaye.com
- https://www.kuaidaili.com/free

## 六、Session 与会话维持

`requests.Session()` 会自动保存 cookie，在多次请求间维持登录状态：

```python
import requests

session = requests.Session()
session.headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...",
}

# 第一次请求：登录（服务器通过 Set-Cookie 下发 cookie）
session.post("https://example.com/login", data={"user": "alex", "pwd": "123456"})

# 之后的请求自动携带 cookie，保持登录状态
resp = session.get("https://example.com/member")
print(resp.text)
```

---

## 七、会话维持的三种方式（对比）

| 方式 | 实现 | 优点 | 缺点 |
| ---- | ---- | ---- | ---- |
| 复制浏览器 Cookie | 手动放进 headers | 简单粗暴 | 会过期，需频繁更换 |
| 手工传递 Cookie | `resp.cookie` 传给下一请求 | 无需登录 | 麻烦，易遗漏 |
| requests.Session() | 自动管理 | 推荐，自动保存下发 cookie | 无法维护 JS 生成的 cookie |

### 8. 主动抛异常（raise_for_status）

### 9. 获取接口的 JSON 数据（json 参数）


### 10. 异常处理（requests.exceptions）

requests 会把各种失败情况抛成异常，务必学会捕获：

```python
import requests
from requests.exceptions import RequestException, Timeout, ConnectionError, HTTPError

url = "https://example.com"
try:
    resp = requests.get(url, timeout=3)
    resp.raise_for_status()          # 4xx/5xx 时抛 HTTPError
except Timeout:
    print("请求超时")
except ConnectionError:
    print("连接失败")
except HTTPError as e:
    print("HTTP 错误:", e.response.status_code)
except RequestException as e:
    print("其他请求异常:", e)
```

> 异常层级：`RequestException` 是所有 requests 异常的父类，捕获它可兜底；再细分有 `Timeout`、`ConnectionError`、`HTTPError`、`TooManyRedirects` 等。

### 11. 连接超时与读取超时（分开设置）

`timeout` 传元组可分别设置"连接"和"读取"超时：

```python
# 连接超时 3 秒 + 读取超时 5 秒
resp = requests.get("https://example.com", timeout=(3, 5))
```

### 12. 更专业的重试机制（urllib3.Retry）

`HTTPAdapter(max_retries=3)` 只能重试固定次数，想要"按状态码/连接错误条件重试"可用 `urllib3.Retry`：

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

session = requests.Session()

retry = Retry(
    total=3,                        # 最多重试 3 次
    connect=3,                      # 连接失败重试 3 次
    read=3,                         # 读取失败重试 3 次
    backoff_factor=1,               # 重试间隔递增：1, 2, 4, 8...
    status_forcelist=[500, 502, 503, 504],   # 这些状态码才重试
    allowed_methods=["GET", "POST"],
)

adapter = HTTPAdapter(max_retries=retry)
session.mount("http://", adapter)
session.mount("https://", adapter)

resp = session.get("https://example.com", timeout=10)
```

### 18. PreparedRequest：拆解"构造 → 准备 → 发送"三步

爬虫调试时想"只构造不发送，看看请求到底长什么样"，用底层 API：

```python
import requests

session = requests.Session()

# 第一步：构造 Request（此时什么都没发生）
req = requests.Request(
    method="POST",
    url="https://httpbin.org/post",
    data={"name": "alex"},
    headers={"User-Agent": "Mozilla/5.0"},
)

# 第二步：prepare 成 PreparedRequest（完成编码、合并 session 头）
prepared = session.prepare_request(req)

# 查看最终请求（调试神器：确认参数/头是否拼接正确）
print(prepared.url)               # https://httpbin.org/post
print(prepared.headers)           # 合并后的完整请求头
print(prepared.body)              # name=alex（已编码）

# 第三步：真正发送
resp = session.send(prepared, timeout=10)
print(resp.json())
```

> 逆向/调参时，如果发现"requests 发的和浏览器抓包对不上"，用 PreparedRequest 把最终 URL/头/体打印出来对比，一步定位差异。

### 23. response.links：分页 Link 头

部分接口（如 GitHub API）用响应头 `Link` 表示"上一页/下一页"：

```python
import requests

resp = requests.get("https://api.github.com/users/alex/repos?page=1")
# Link 头长这样：<...?page=2>; rel="next", <...?page=1>; rel="prev"
```

### 24. Session 全局设置代理 / 证书

给 Session 一次性设置，之后所有请求都生效：

```python
import requests

session = requests.Session()
session.proxies = {"http": "http://112.74.90.1:8080", "https": "http://112.74.90.1:8080"}
session.verify = False          # 全局关闭证书验证（仅测试）
session.trust_env = False       # 忽略系统环境变量里的代理

resp = session.get("https://httpbin.org/ip")
print(resp.text)
```

> `trust_env=False` 很实用：本地开了代理软件（如 Clash/VPN）时，requests 会读取系统代理导致请求走到代理里，关闭它可强制走直连或你指定的代理。

### 25. 上传文件 + 附带表单字段（data 与 files 混用）

很多上传接口除了文件还要带其他字段（如 token、描述），`data` 和 `files` 可以同时传：

```python
import requests

files = {"file": ("test.jpg", open("test.jpg", "rb"), "image/jpeg")}
data = {
    "token": "abc123",          # 上传时附带的普通字段
    "description": "我的头像",
}
resp = requests.post("https://example.com/upload", data=data, files=files)
print(resp.json())
```

> 注意：一旦同时传了 `files`，请求体就是 `multipart/form-data`，`data` 里的普通字段也会一并拼进去，浏览器抓包也是这个格式。

### 26. 大文件下载 + 进度条

`stream=True` 配合 `Content-Length` 可以计算下载进度，也方便断点续传/限速：

```python
import requests

resp = requests.get("https://example.com/big.zip", stream=True)
total = int(resp.headers.get("Content-Length", 0))   # 总大小（字节）
downloaded = 0

with open("big.zip", "wb") as f:
    for chunk in resp.iter_content(chunk_size=8192):
        if chunk:
            f.write(chunk)
            downloaded += len(chunk)
            if total:
                percent = downloaded / total * 100
                print(f"\r进度: {percent:.1f}%", end="")
print("\n下载完成")
```

> `iter_content(chunk_size)` 里偶发的空 `chunk`（`b""`）要跳过（`if chunk`），否则会白写空数据。若服务器没给 `Content-Length`（如 chunked 传输），`total` 为 0 时跳过百分比显示即可。

### 27. 查看"实际发送"的请求（response.request 调试）

请求发送后，`resp.request` 记录着**真正发出去**的请求（URL、头、体），是排查"浏览器和 requests 不一致"最快的工具：

```python
import requests

resp = requests.post(
    "https://httpbin.org/post",
    params={"page": 2},
    data={"name": "alex"},
    headers={"User-Agent": "Mozilla/5.0", "X-Token": "abc"},
)

# 实际发送的完整 URL（params 已拼进去并编码）
print(resp.request.url)             # https://httpbin.org/post?page=2

# 实际发送的请求头（含 requests 自动加的 Accept、Content-Length 等）
print(resp.request.headers)

# 实际发送的请求体
print(resp.request.body)            # name=alex
```

> **逆向技巧**：浏览器抓包看到 `Content-Type: application/x-www-form-urlencoded; charset=UTF-8`，而你用 `json=` 发送 → 服务端解析失败。用 `resp.request.headers` / `resp.request.body` 对比，一眼看出差异再修正。

### 28. 连接复用（keep-alive）与性能

同一个 `Session` 默认会复用 TCP 连接（keep-alive），多次请求比每次新建连接快很多：

```python
import requests

session = requests.Session()
# 连续请求同一个域名，底层复用连接（响应头能看到 Connection: keep-alive）
for i in range(10):
    r = session.get("https://httpbin.org/get")
    print(r.elapsed.total_seconds())   # 后续请求通常更快
```

- 不要对每个请求都 `requests.get()`（每次新建连接，慢）；
- 用同一个 `Session` 循环请求同一站点，既省连接又容易控制频率；
- 需要"隔离"不同站点（不同 Cookie/头）时，才建多个 Session。

### 29. requests.utils 常用工具函数

```python
import requests
from requests.utils import (
    dict_from_cookiejar, cookiejar_from_dict,
    requote_uri, get_encoding_from_headers, parse_header_links,
)

# requote_uri：把 URL 中非法字符重新编码（拼接 URL 出现中文/空格时用）
bad_url = "https://example.com/北京 天气"
print(requests.utils.requote_uri(bad_url))
# https://example.com/%E5%8C%97%E4%BA%AC%20%E5%A4%A9%E6%B0%94

# get_encoding_from_headers：从响应头推断编码
enc = requests.utils.get_encoding_from_headers(resp.headers)
print(enc)   # 如 'utf-8'
```

> 手动拼 URL 时带中文/空格容易报错，用 `requote_uri` 一次性修正，比手动 `quote` 省事。

## 九、小结

- `requests` 是最常用的请求库：`get/post + headers/data/params/proxies`；
- 文本用 `resp.text`，二进制资源用 `resp.content`；
- 乱码优先用 `resp.content.decode()` 或 `resp.encoding = resp.apparent_encoding`；
- 反爬应对：设置浏览器 UA、使用代理 IP、使用 Session 维持登录态、控制频率；
- 异常处理：捕获 `Timeout / ConnectionError / HTTPError / RequestException`，用 `raise_for_status()` 快速失败；
- 高级技巧：`urllib3.Retry` 条件重试、`timeout=(连接, 读取)`、`dict_from_cookiejar` 转 cookie、`resp.history` 看重定向、`stream=True` 流式读取、`hooks` 钩子、PreparedRequest 底层调试、`session.close()` 释放连接、urllib3 DEBUG 日志排查；
- 补充：`resp.elapsed` 测速、带认证代理 `user:pass@ip:port`、`resp.links` Link 头分页、Session 全局代理/证书设置、`trust_env=False` 绕过本机代理软件；
- 上传：`data` 与 `files` 可混用（multipart/form-data 附带普通字段）；大文件用 `stream=True` + `iter_content` 分块写并显示进度；
- 调试：`resp.request.url/headers/body` 查看"实际发送"的请求，与浏览器抓包对比定位差异；`requote_uri` 修正拼接 URL 的中文/空格；
- 性能：同一 `Session` 复用连接（keep-alive），循环请求同一站点用同一个 Session 更快。
