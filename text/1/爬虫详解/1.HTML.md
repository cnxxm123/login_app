# HTML（超文本标记语言）详解

## 一、什么是 HTML？

HTML 全称 **HyperText Markup Language（超文本标记语言）**，它是构成网页的基础语言。

### 1. 三个核心概念

| 概念 | 说明 |
| ---- | ---- |
| 标签（Tag） | 也叫"标记"，是 HTML 中最基本的单元，用尖括号 `<>` 包裹 |
| 属性（Attribute） | 附加在标签上，用来描述标签的额外信息，格式为 `属性名="值"` |
| 内容（Content） | 标签中间包裹的文字、图片、超链接等 |

一个完整的"标签+内容+属性"可以形象地理解为：

```
<人 肤色="黄色" 眼镜="很大"></人>
 │   └──属性──┘      └──空内容──┘
 └──标签名──┘
```

### 2. 普通文本 vs 超文本

- **普通文本**：只有文字内容。
- **超文本**：不仅能包含文字，还能包含图片、音频、视频、超链接等多媒体内容。

### 3. HTML 与协议的关系

网页通过 **HTTP（超文本传输协议）** 在网络中传输。HTTP 传输的本质上就是 HTML 文档（还有 CSS、JS、图片等资源）。

### 4. 为什么爬虫要学 HTML？

爬虫的目标是"从网页中提取数据"。网页源代码本质是 HTML 字符串，只有理解了 HTML 的结构（标签、属性、层级关系），才能用解析库（BeautifulSoup、lxml）准确定位到我们想要的数据。

## 二、HTML 的主体结构

一个标准的 HTML5 文档结构如下：

```html
<!DOCTYPE html>              <!-- 声明文档类型为 html5 -->
<html>                       <!-- 根标签，整个文档的唯一根 -->
<head>                       <!-- 头部分：网页的"配置信息"，不显示在页面上 -->
    <meta charset="UTF-8">   <!-- 声明字符集，防止乱码 -->
    <title>页面标题</title>   <!-- 浏览器标签页上显示的标题 -->
    <link rel="stylesheet" href="style.css">  <!-- 引入外部 CSS -->
    <style> /* 内嵌 CSS */ </style>
    <script src="app.js"></script>            <!-- 引入外部 JS -->
</head>
<body>                       <!-- 身体部分：网页实际显示的内容 -->
    <h1>我是标题</h1>
    <p>我是段落</p>
</body>
</html>
```

### 各部分的职责

| 标签 | 作用 |
| ---- | ---- |
| `<!DOCTYPE html>` | 声明文档类型为 HTML5。旧版曾用 `<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML...">`，现已废弃 |
| `<html>` | 根标签，一个 HTML 文档只能有一个 |
| `<head>` | 存放网页的元信息，不会显示在浏览器页面中 |
| `<title>` | 网页标题，显示在浏览器标签页 |
| `<meta>` | 元信息。常用：`charset`（字符集）、`name="description"`（描述）、`name="keywords"`（关键词）、`name="author"`（作者） |
| `<link>` | 引入外部资源（最常用的是 CSS 文件） |
| `<style>` | 在页面内部写 CSS 样式 |
| `<script>` | 写入或引入 JavaScript |
| `<body>` | 网页真正显示的内容区域 |

> **爬虫视角**：抓包时看到的 `resp.text` 就是整个 `<html>...</html>` 的字符串。

## 三、HTML 的标签分类

### 1. 按标签形式分类

**单标签（自闭合标签）**：没有结束标签，如：

```html
<br/>   <!-- 换行 -->
<img/>  <!-- 图片 -->
<hr/>   <!-- 水平分割线 -->
<input/> <!-- 输入框 -->
```

**双标签（成对标签）**：有开始和结束标签，如：

```html
<p>我是段落</p>
<div>我是块级容器</div>
```

### 2. 常用文本标签

```html
<div>块级标签，用来布局，设置字/画/表格的摆放位置</div>
<p>段落标签，自成一段，上下自动留出间距</p>
<h1>一级标题</h1>
<h2>二级标题</h2>
<h3>三级标题</h3>
<h4>四级标题</h4>
<h5>五级标题</h5>
<h6>六级标题</h6>
<span>行内标签，不换行</span>
```

> `h1~h6` 标题字体加粗、各自占一行。搜索引擎也依靠标题标签判断页面内容的重要程度。

#### 2.1 文本格式化标签（强调/加粗/斜体/删除线等）

| 标签 | 效果 | 语义说明 |
| ---- | ---- | -------- |
| `<b>` | **加粗** | 纯视觉效果（bold） |
| `<strong>` | **加粗** | 表示"重要"，语义更强（爬虫提取时两者等价） |
| `<i>` | *斜体* | 纯视觉效果（italic） |
| `<em>` | *斜体* | 表示"强调" |
| `<u>` | <u>下划线</u> | 下划线 |
| `<del>` | ~~删除线~~ | 已删除的内容（如原价） |
| `<ins>` | <ins>插入线</ins> | 新增内容 |
| `<mark>` | 高亮 | 标记文本 |
| `<small>` | 小号字 | 版权、注释 |
| `<sub>` | 下标 | H₂O |
| `<sup>` | 上标 | x² |
| `<code>` | `代码` | 行内代码 |
| `<pre>` | 保留格式 | 保留空格和换行的代码块 |
| `<blockquote>` | 引用块 | 长引用 |
| `<q>` | "短引用" | 行内引用 |
| `<hr>` | 水平分割线 | 块级 |
| `<br>` | 换行 | 行内 |

```html
<p>原价 <del>￥6999</del>，现价 <strong>￥5999</strong>（<mark>限时</mark>）</p>
<pre>
def hello():
    print("保留缩进与换行")
</pre>
<p>化学式 H<sub>2</sub>O，数学 x<sup>2</sup></p>
<blockquote>这是一段长引用的内容。</blockquote>
```

> **爬虫视角**：
> - 电商抓"原价/现价"时，原价往往包在 `<del>` 里，现价包在 `<strong>`/`<span>` 里，先看标签语义再写 XPath，比单纯按 class 更稳；
> - `<pre>` 里的内容会保留换行缩进，抓代码/JSON 文本时要用 `normalize-space` 处理。

#### 2.2 块级元素 vs 行内元素（重要概念）

| 对比 | 块级元素 | 行内元素 |
| ---- | -------- | -------- |
| 典型标签 | `div` `p` `h1~h6` `ul` `ol` `li` `table` `form` | `span` `a` `img` `input` `em` `strong` `b` `i` |
| 是否换行 | 独占一行，默认宽度占满 | 不换行，宽度随内容 |
| 能否设宽高 | 可以 | 一般无效（`img` 除外） |
| 嵌套规则 | 可嵌套块级 + 行内 | **不能嵌套块级**（浏览器会自动闭合） |

> **爬虫视角**：理解块级/行内能帮你预判解析结果。比如 `<p>` 里不能放 `<div>`，浏览器会自动把 `<p>` 拆开，导致 `//p/div` 这类 XPath 找不到节点。

#### 2.3 details / summary（可折叠内容，了解即可）

```html
<details>
    <summary>点击展开详情</summary>
    <p>这里是被折叠的内容，默认不显示。</p>
</details>
```

> 常见于"展开更多""FAQ 问答"。抓取时若 `resp.text` 里内容存在但页面不显示，通常不是这里的问题，而是 JS 或 `display:none` 控制。

### 3. 图片标签

```html
<img src="图片地址" alt="加载失败提示" title="鼠标悬停提示" width="宽" height="高" />
```

| 属性 | 是否必填 | 作用 |
| ---- | -------- | ---- |
| `src` | 必填 | 图片路径或 URL |
| `alt` | 可选 | 图片加载失败时显示的文字 |
| `title` | 可选 | 鼠标悬停时的提示文字 |
| `width` / `height` | 可选 | 宽高；只给一个时等比缩放，都给则按指定尺寸显示 |

> **爬虫视角**：抓取图片时，就是通过 `src` 属性拿到图片的真实下载地址，再用 `requests` 以二进制方式下载。

### 4. 路径

**相对路径**（以当前文件为基准）：

```
./       当前目录
../      上一级目录
../../   上两级目录
```

**绝对路径**：

- URL 形式：`https://www.example.com/images/a.png`
- 磁盘形式：`D:/images/a.png`

#### `<base>` 标签（影响所有相对路径的基准）

`<base>` 写在 `<head>` 里，会**改变整个页面所有相对路径的解析基准**：

```html
<head>
    <base href="https://example.com/static/">
</head>
<body>
    <img src="logo.png">   <!-- 实际解析为 https://example.com/static/logo.png -->
</body>
```

> **爬虫视角**：如果你用 `urljoin` 拼接相对链接时发现地址错乱，先检查页面里有没有 `<base>`。它会让 `./`、`../`、甚至裸文件名都基于 `base` 的 href 来解析。

### 5. 超链接标签

```html
<a href="链接地址" title="提示信息" target="_blank">点击显示的文本</a>
```

| 属性 | 说明 |
| ---- | ---- |
| `href` | 必填，跳转地址 |
| `target="_blank"` | 在新窗口打开 |
| `target="_self"` | 在当前窗口打开（默认） |
| `title` | 悬停提示 |
| `rel` | 与目标页面的关系，如 `nofollow`/`noopener`/`noreferrer` |

> **爬虫视角**：列表页的每一条数据通常都是一个 `<a>` 链接，提取 `href` 后拼接成完整的详情页 URL，再继续抓取——这就是"翻页/翻详情"爬虫的基本套路。

#### 5.1 rel 属性（对 SEO/反爬有意义）

```html
<a href="/detail/1.html" rel="nofollow">被禁止收录的链接</a>
<a href="https://外部站.com" target="_blank" rel="noopener noreferrer">外链</a>
```

| rel 值 | 含义 | 爬虫关注点 |
| ------ | ---- | ---------- |
| `nofollow` | 告诉搜索引擎"不要传递权重/不要收录该链接" | 常见于评论区、登录、广告等链接，不代表不能爬 |
| `noopener` | 新窗口打开时隔离 `window.opener`，防钓鱼 | 安全相关，与抓取无关 |
| `noreferrer` | 跳转时**不携带 Referer** 头 | **反爬相关**：外链跳转不带来源，模拟时要注意 Referer 缺失 |

> 抓详情页时若发现目标站校验 Referer，可先看 `resp.text` 里 `<a rel="noreferrer">` 是否存在，作为"该站是否依赖 Referer"的参考线索。

#### 特殊 href 值（爬虫常见坑）

```html
<a href="#">点击无跳转</a>                       <!-- 跳到页面顶部 -->
<a href="javascript:void(0)">点击无跳转</a>      <!-- 真正意义上的"什么都不做" -->
<a href="javascript:void(0)" onclick="loadData()">加载</a> <!-- 靠 JS 触发，点击后走 onclick -->
```

- 看到 `href="javascript:void(0)"` 说明跳转不靠 href，靠 `onclick` 里的 JS 函数 → 需要找 JS 里的接口；
- 很多前端"分页/筛选"按钮都是这种写法，`resp.text` 里没有下一页地址，要逆向 JS。

### 7. HTML 注释

```html
<!-- 多行注释，浏览器不会渲染其中的内容 -->
```

注释的作用：

1. 代码调试（注释掉一部分代码看效果）；
2. 解释说明。

> **爬虫视角**：部分网站会在注释里藏关键提示甚至数据，抓取时留意 `<!-- -->` 之间的内容。

### 8. HTML5 语义化标签

HTML5 新增了一组"有含义"的标签，让页面结构更清晰：

```html
<header>网页头部 / 区块头部</header>
<nav>导航栏</nav>
<main>页面主体内容（一个页面只有一个 main）</main>
<article>独立的一篇文章 / 一条新闻</article>
<section>页面中的一块区域</section>
<aside>侧边栏</aside>
<footer>网页底部 / 版权信息</footer>
```

> 语义化标签本质上和 `<div>` 一样都是块级容器，但"名字更有意义"。**爬虫解析时**它们和 div 一样参与层级定位，无需特殊处理。

### 9. 全局属性与 data-* 自定义属性

所有 HTML 标签都可以使用以下全局属性：

| 属性 | 作用 |
| ---- | ---- |
| `id` | 唯一标识，一个页面只能出现一次 |
| `class` | 样式类名，可多个（空格隔开） |
| `style` | 内联样式 |
| `title` | 鼠标悬停提示 |
| `data-*` | 自定义数据属性，常用来存 JSON 数据 |

`data-*` 属性在爬虫中非常重要——很多网站把数据直接塞进标签里：

```html
<div class="goods" data-id="10086" data-price="5999" data-name="苹果手机">苹果手机</div>
```

```python
from lxml import etree

html = '<div class="goods" data-id="10086" data-price="5999">苹果手机</div>'
tree = etree.HTML(html)
# 用 @data-* 直接取自定义属性
print(tree.xpath("//div[@class='goods']/@data-id"))       # ['10086']
print(tree.xpath("//div[@class='goods']/@data-price"))    # ['5999']
```

> 常见于列表页的"伪详情"：把详情数据存在 `data-*` 里，点开详情只是本地展示，无需再发请求。解析时直接取即可。

### 9.2 事件属性（逆向时定位 JS 用）

`on*` 开头的属性叫**事件属性**，当对应事件发生时执行里面的 JS：

| 属性 | 触发时机 |
| ---- | -------- |
| `onclick` | 鼠标点击 |
| `onchange` | 值改变（如 select 下拉切换） |
| `onmouseover` / `onmouseout` | 鼠标移入 / 移出 |
| `onsubmit` | 表单提交前 |
| `onload` | 页面/资源加载完 |
| `onkeyup` / `onkeydown` | 键盘按键 |

```html
<button onclick="login()">登录</button>                     <!-- 逆向入口：login() 函数 -->
<select onchange="cityChanged(this.value)">...</select>     <!-- 换城市触发 -->
<input type="text" id="pwd" onblur="encryptPwd()">          <!-- 失焦时加密 -->
```

> **逆向视角**：很多网站的加密参数是在 `onclick`、`onchange`、`onblur` 里调用的 JS 函数完成的。看到这些属性，就能顺着函数名去 JS 源码里断点定位加密逻辑，这是扣 JS/补环境的第一步。

### 10. HTML 实体（Entity）

网页源码中偶尔会出现 `&nbsp;`、`&amp;` 之类的字符，这叫 **HTML 实体**——用来表示那些在 HTML 中有特殊含义或无法直接输入的字符。

| 实体写法 | 实际字符 | 说明 |
| -------- | -------- | ---- |
| `&nbsp;` | 空格 | 不换行空格（爬虫提取文本时会遇到，记得 strip） |
| `&amp;` | & | 与号 |
| `&lt;` | < | 小于号 |
| `&gt;` | > | 大于号 |
| `&quot;` | " | 双引号 |
| `&#39;` | ' | 单引号 |

```python
import html

s = "苹果&nbsp;&amp;&nbsp;华为"
print(html.unescape(s))   # 苹果 & 华为（还原成真实字符）
```

> 用 bs4 提取文本时通常已被自动还原，但用 re 提取时需要手动 `html.unescape()` 处理。

### 11. 图片懒加载（爬虫常见坑）

现代网站为了省流量，图片常使用**懒加载**：真实地址先存在 `data-src` 里，等滚动到可视区域才替换到 `src`。

```html
<img class="lazy" data-src="https://example.com/real.png" src="https://example.com/placeholder.gif" />
```

- 直接取 `@src` 得到的是**占位图**；
- 必须取 `@data-src`（或 `@data-original`、`@data-url` 等，因网站而异）才是真实图片地址。

```python
from lxml import etree

html = '<img class="lazy" data-src="https://example.com/real.png" src="https://example.com/placeholder.gif"/>'
tree = etree.HTML(html)
# 先取 data-src，取不到再退回到 src
real = tree.xpath("//img[@class='lazy']/@data-src")
print(real)   # ['https://example.com/real.png']
```

## 四、iframe（内联框架）

### 1. 定义

`<iframe>` 元素会在当前页面中嵌入另一个独立的 HTML 文档（即"页面套页面"）。

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>iframe 示例</title>
</head>
<body>
    <!-- src 指向被嵌入的页面或资源 -->
    <iframe src="https://www.example.com/player" width="600" height="400"></iframe>
</body>
</html>
```

### 1.5 iframe 常用属性

| 属性 | 说明 |
| ---- | ---- |
| `src` | 被嵌入页面的地址 |
| `width` / `height` | 宽高 |
| `sandbox` | 安全隔离：限制内部脚本/表单/弹窗等能力 |
| `allow` | 权限控制（摄像头、麦克风等） |
| `referrerpolicy` | 控制跳转时携带的 Referer（反爬常看） |
| `loading="lazy"` | 懒加载 iframe，滚动到才加载 |

```html
<iframe src="https://example.com/login" sandbox="allow-scripts allow-forms"></iframe>
```

> **逆向视角**：登录页常被嵌入 iframe，且用 `sandbox` 做隔离。若网页功能异常，可尝试去掉 sandbox 或直接抓 iframe 的 `src` 单独请求。

### 2. 爬虫中的 iframe 陷阱

很多网站（尤其是视频网站、第三方登录、广告位）会把内容放在 iframe 中。此时：

- 直接在 `resp.text` 里**找不到** iframe 内部的内容；
- 需要先从主页面拿到 iframe 的 `src`，再对 `src` 单独发一次请求抓取。

```python
import requests
from lxml import etree

resp = requests.get("https://example.com/index")
tree = etree.HTML(resp.text)
iframe_src = tree.xpath("//iframe/@src")[0]   # 拿到 iframe 地址
print("iframe 地址:", iframe_src)

# 再单独请求 iframe 内的页面
iframe_html = requests.get(iframe_src).text
```

## 五、TABLE 表格

### 1. 基本结构

表格由"行（tr）"和"单元格（td/th）"构成：

```html
<table border="1" width="500">
    <tr>
        <th>表头1</th>
        <th>表头2</th>
        <th>表头3</th>
    </tr>
    <tr>
        <td>单元格1</td>
        <td>单元格2</td>
        <td>单元格3</td>
    </tr>
</table>
```

### 2. 标签与属性

| 标签 | 含义 |
| ---- | ---- |
| `<table>` | 表格容器 |
| `<tr>` | 行（table row） |
| `<th>` | 表头单元格（加粗居中） |
| `<td>` | 普通单元格 |

常用属性：`width`（宽）、`height`（高）、`border`（边框）、`colspan`（跨列）、`rowspan`（跨行）。

### 3. 语义化分组：thead / tbody / tfoot

大表格常用这三个标签把"表头 / 表体 / 表尾"分开，浏览器/解析库也更容易定位：

```html
<table border="1">
    <thead>
        <tr><th>名称</th><th>价格</th></tr>
    </thead>
    <tbody>
        <tr><td>苹果</td><td>5</td></tr>
        <tr><td>香蕉</td><td>3</td></tr>
    </tbody>
    <tfoot>
        <tr><td>合计</td><td>8</td></tr>
    </tfoot>
</table>
```

> **爬虫视角**：很多网页数据区在 `<tbody>` 里，但注意部分框架（如某些前端渲染）tbody 下没有 `<tr>`，而是直接用 div 伪表格；也有网站的行是 JS 动态拼出来的（`resp.text` 里没有），需另做处理。

### 4. 单元格合并：colspan / rowspan

```html
<tr>
    <td colspan="2">占两列</td>   <!-- 横向合并 2 个单元格 -->
</tr>
<tr>
    <td rowspan="2">占两行</td>   <!-- 纵向合并 2 个单元格 -->
    <td>正常单元格</td>
</tr>
```

> **爬虫视角**：股票行情、票房排行、历史数据等结构化数据常常放在 `<table>` 里。用 xpath 的 `//table/tbody/tr` 一次取出所有行，再逐行取单元格即可。

## 六、FORM 表单

### 1. form 基本结构

```html
<form action="提交地址" method="post">
    <!-- 表单项 -->
</form>
```

| 属性 | 说明 |
| ---- | ---- |
| `action` | 数据提交到的服务器地址 |
| `method` | 提交方式：`get` 或 `post` |

### 2. GET 与 POST 的区别

| 对比项 | GET | POST |
| ------ | --- | ---- |
| 参数位置 | URL 地址栏可见（`?name=alex`） | 放在请求体（body）中，地址栏不可见 |
| 长度限制 | 有（IE 约 2K，火狐约 8K） | 默认不受限制 |
| 安全性 | 相对不安全 | 相对安全 |
| 典型场景 | 查询、翻页、搜索 | 登录、注册、提交数据 |

```html
<!-- GET 提交：参数出现在 URL 中 -->
<form action="/search" method="get">
    <input type="text" name="wd" />
    <input type="submit" value="搜索" />
</form>
```

### 3. input 表单项

```html
<input type="text" name="username" />      <!-- 单行文本框 -->
<input type="password" name="pwd" />       <!-- 密码框 -->
<input type="radio" name="gender" value="men" />  <!-- 单选 -->
<input type="checkbox" name="hobby" />     <!-- 多选 -->
<input type="submit" value="提交" />        <!-- 提交按钮 -->
<input type="reset" value="重置" />         <!-- 重置按钮 -->
<input type="hidden" name="token" value="abc123" /> <!-- 隐藏域，常存加密参数 -->
```

#### 常用 type 类型（爬虫抓包时会遇到）

| type | 说明 |
| ---- | ---- |
| `text` | 单行文本 |
| `password` | 密码（输入显示为黑点） |
| `email` | 邮箱（自动校验格式） |
| `number` | 数字 |
| `date` / `time` | 日期 / 时间 |
| `file` | 文件上传（`enctype` 需为 `multipart/form-data`） |
| `range` | 滑块 |
| `hidden` | 隐藏域（重要！常存 token/加密参数） |

#### input 常用属性（模拟提交时经常用到）

| 属性 | 说明 |
| ---- | ---- |
| `name` | **提交时的参数名**，模拟请求时就是请求体/URL 里的 key |
| `value` | 默认值 / 提交时的值 |
| `placeholder` | 输入框内的灰色提示文字 |
| `required` | 必填项，为空时浏览器拦截提交 |
| `maxlength` | 最大输入长度 |
| `readonly` | 只读（可提交） |
| `disabled` | 禁用（**不会随表单提交**，抓包时看到 disabled 字段要小心） |

```html
<input type="text" name="username" placeholder="请输入用户名" required maxlength="20" />
<input type="hidden" name="token" value="abc123" readonly />
```

> **爬虫视角**：抓包模拟表单时，`name` 决定参数名、`value` 决定参数值；`disabled` 的字段浏览器不会发送，但如果你手动加上也不会报错——有的网站恰好用它做"假参数"反爬。

### 3.2 textarea（多行文本）

```html
<textarea name="content" rows="5" cols="30">默认内容</textarea>
```

### 3.3 label（标签，关联表单控件）

```html
<label for="username">用户名:</label>
<input type="text" name="username" id="username">
```

- `label` 的 `for` 指向控件的 `id`，点击 label 文字即可聚焦对应输入框。

### 3.4 fieldset / legend（表单分组）

```html
<fieldset>
    <legend>基本信息</legend>
    <input type="text" name="name" placeholder="姓名">
</fieldset>
```

### 3.5 datalist（输入建议列表）

```html
<input list="cities" name="city">
<datalist id="cities">
    <option value="北京"></option>
    <option value="上海"></option>
</datalist>
```

### 4. select 下拉列表

```html
<select name="city">
    <option value="bj">北京</option>
    <option value="sh">上海</option>
    <option value="gz">广州</option>
</select>
```

- `select` 的 `name` 属性：提交时作为参数名；
- `option` 的 `value` 属性：被选中项提交时的值。

> **爬虫视角**：登录、搜索、翻页请求往往就是模拟表单提交。抓包后把表单字段（`name` 与 `value`）整理成字典，用 `requests.post(url, data=表单字典)` 即可模拟。隐藏域 `type="hidden"` 里的 `token` 常是反爬校验参数，不能漏掉。

### 5. form 的 enctype（提交编码格式）

`enctype` 决定表单数据以什么**编码方式**放进请求体，直接决定你模拟请求时用 `data` 还是 `files`：

| enctype 值 | 请求体格式 | 说明 |
| ---------- | ---------- | ---- |
| `application/x-www-form-urlencoded`（默认） | `username=alex&pwd=123` | 普通表单，`requests` 用 `data=` 提交 |
| `multipart/form-data` | 二进制分块 | **文件上传**必须用它，`requests` 用 `files=` 提交 |
| `text/plain` | 纯文本 | 少见，直接提交原始文本 |

```html
<!-- 普通表单 -->
<form action="/login" method="post">
    <input type="text" name="username">
    <input type="submit">
</form>

<!-- 文件上传表单（enctype 必须为 multipart/form-data） -->
<form action="/upload" method="post" enctype="multipart/form-data">
    <input type="file" name="file">
    <input type="submit">
</form>
```

> **爬虫视角**：登录接口抓包时若看到请求头 `Content-Type: multipart/form-data; boundary=----...`，说明是分块上传（通常带文件），模拟时用 `files=`；否则一般用 `data=`。

### 6. 表单校验属性（HTML5）

不依赖 JS 就能做的输入校验，模拟提交时**浏览器不会替你做**，所以校验必须服务器端再做一次：

```html
<input type="email" name="email" required />      <!-- 必填 + 邮箱格式 -->
<input type="text" name="age" pattern="[0-9]+" /> <!-- 正则校验：只能是数字 -->
<input type="text" name="code" minlength="6" maxlength="6" /> <!-- 长度 6 -->
```

| 属性 | 作用 |
| ---- | ---- |
| `required` | 必填 |
| `pattern` | 正则校验 |
| `min` / `max` | 数值范围（配合 number） |
| `minlength` / `maxlength` | 长度范围 |
| `autocomplete="off"` | 关闭自动补全（部分网站用来防爬） |

## 六·五、媒体标签与 meta 信息

### 1. 视频 / 音频

```html
<video src="movie.mp4" controls width="400"></video>   <!-- controls 显示播放控件 -->
<audio src="song.mp3" controls></audio>
```

> 爬虫下载视频时，`src` 往往不是真实地址（可能是 M3U8 分片），需要另学 M3U8 下载。

### 2. picture（响应式图片）

```html
<picture>
    <source media="(min-width: 800px)" srcset="big.jpg">
    <source media="(min-width: 400px)" srcset="mid.jpg">
    <img src="small.jpg" alt="兜底图">
</picture>
```

### 3. canvas（画布，爬虫很少涉及）

```html
<canvas id="c" width="300" height="150"></canvas>
```

> 注意：**canvas 生成的内容（比如验证码/图表）不是 HTML 文本**，`resp.text` 里抓不到，只能截图识别。

### 4. 重要 meta 标签

| meta 写法 | 作用 |
| --------- | ---- |
| `<meta charset="UTF-8">` | 字符集（**爬虫第一个看它，决定怎么解码**） |
| `<meta name="viewport" content="width=device-width, initial-scale=1">` | 移动端适配 |
| `<meta name="description" content="描述">` | 页面描述 |
| `<meta name="keywords" content="关键词">` | 页面关键词 |
| `<meta name="robots" content="noindex,nofollow">` | 控制搜索引擎索引（noindex 不收录、nofollow 不跟随链接） |
| `<meta http-equiv="refresh" content="3;url=/new.html">` | 3 秒后跳转（一种反爬/跳转手段） |
| `<meta http-equiv="Content-Type" content="text/html;charset=gbk">` | 声明编码为 gbk |

> **爬虫视角**：`<meta name="robots" content="noindex">` 只是"告知搜索引擎"，**不构成技术拦截**，普通爬虫（requests）照常可访问，无需理会；但某些站会用 robots.txt + meta 组合做反爬心理战。

#### 4.1 link 的资源预加载（优化爬取效率的知识）

`<link>` 除了引入 CSS，还能预加载/预连接资源。逆向分析时留意这些，可提前发现真实数据接口：

```html
<!-- preconnect：提前建立与域名的 TCP/TLS 连接，加速后续请求 -->
<link rel="preconnect" href="https://api.example.com">

<!-- preload：提前加载关键资源（字体/图片/脚本） -->
<link rel="preload" href="https://cdn.example.com/main.js" as="script">

<!-- prefetch：提前下载下一页/即将用到的资源 -->
<link rel="prefetch" href="/list-2.html">
```

| rel 值 | 含义 | 逆向价值 |
| ------ | ---- | -------- |
| `preconnect` | 提前握手连接目标域 | **强烈提示**该域名是后续真正要请求的接口域 |
| `dns-prefetch` | 提前 DNS 解析 | 同上，辅助发现域名 |
| `preload` | 预加载当前页关键资源 | 可能藏着加密 JS / 字体（字体反爬） |
| `prefetch` | 预取下一资源 | 常指向下一页/详情数据 |

> 逆向找数据接口时，先扫一遍 `<head>` 里的 `preconnect`/`dns-prefetch` 域名，往往比在 JS 里大海捞针更快定位真实 API 服务器。

### 5. Open Graph（og）标签

社交平台（微信/微博/QQ）分享链接时，抓取 `og:` 开头的 meta 生成卡片。爬虫提取"文章标题/配图/摘要"时也常用：

```html
<meta property="og:title" content="这篇文章的标题" />
<meta property="og:image" content="https://example.com/cover.jpg" />
<meta property="og:description" content="摘要内容" />
<meta property="og:url" content="https://example.com/article/1" />
```

> 若正文里找不到标题/封面，很多网站会在这里暴露一份"简化版"，是很好的备用数据源。

> **爬虫解码顺序建议**：优先看 `<meta charset>` 或 `Content-Type` 头里声明的编码；再不行用 `resp.apparent_encoding` 自动识别。

#### 字符编码原理（乱码是怎么来的）

| 编码 | 特点 | 常见场景 |
| ---- | ---- | -------- |
| ASCII | 只有 128 个字符（英文字母、数字、符号），1 字节 | 英文 |
| GBK / GB2312 | 中文双字节，兼容 ASCII | 国内老网站、部分政府站 |
| UTF-8 | 全球统一编码，中文 3 字节，1~4 字节变长 | 现代网站主流 |
| UTF-16 / Unicode | 字符的"编号表"本身 | 内部表示，网页少见 |

```python
# 编码不一致就会乱码：字节序列用错误的编码去解
s = "中文"
gbk_bytes = s.encode("gbk")          # b'\xd6\xd0\xce\xc4'
print(gbk_bytes.decode("utf-8", errors="replace"))   # 乱码：�� ��

# requests 里用对编码
resp = requests.get(url)
resp.encoding = "gbk"     # 按服务器声明/实际编码手动指定
print(resp.text)          # 正确显示
```

> **爬虫视角**：`resp.text` 乱码时，先改 `resp.encoding`（gbk/utf-8/gb2312）逐个试；判断编码可用 `resp.apparent_encoding`（基于字节统计推断）或看 `Content-Type` 响应头。

### 6. script 的加载方式（决定数据是否在 HTML 里）

| 写法 | 说明 |
| ---- | ---- |
| `<script src="a.js"></script>` | 默认：**阻塞**后续渲染，按顺序执行 |
| `<script src="a.js" defer></script>` | 异步下载、**HTML 解析完后再执行**（保序） |
| `<script src="a.js" async></script>` | 异步下载、**下载完立即执行**（不保序） |
| `<script>代码</script>` | 内联脚本，数据可能直接写在 HTML 里 |

```html
<script src="data.js"></script>           <!-- 数据可能在 data.js 里 -->
<script>window.__INIT_DATA__ = {...}</script> <!-- 数据直接内联在 HTML 里 -->
```

> **爬虫视角**：`resp.text` 里能看到数据 → 直接解析；看不到但页面有 → 找 `src` 指向的 js 文件里有没有数据，或内联脚本里的 `window.xxx = {...}`（常配合 `re.search(r"window\.__INIT_DATA__ = (.*?)</script>")` 提取 JSON）。都没有才考虑用 selenium/playwright 渲染。

### 7. noscript / template（特殊但有用的标签）

```html
<!-- noscript：禁用 JS 时才显示的内容 -->
<noscript><a href="/mobile/">请启用 JavaScript 或访问手机版</a></noscript>

<!-- template：定义"模板"，默认不渲染，JS 克隆后再填充 -->
<template id="item-tpl">
    <li class="item"><span class="title"></span></li>
</template>
<script>
    // 复制模板并插入真实数据
    const tpl = document.getElementById("item-tpl");
    const li = tpl.content.cloneNode(true);
    li.querySelector(".title").textContent = "商品名";
    document.body.appendChild(li);
</script>
```

> **爬虫视角**：
> - `<noscript>` 出现在 JS 反爬严重的站点，说明内容依赖 JS；
> - `<template>` 是前端模板，`resp.text` 里只能看到骨架（如空的 `.title`），**真实数据不在 HTML 里**，需要找 JS 请求的接口。

### 8. 结构化数据：JSON-LD（爬虫提取数据的"捷径"）

很多网站会额外声明一份**结构化数据**给搜索引擎（百度/谷歌）用于展示富摘要，它藏在 `<script type="application/ld+json">` 里，本身就是合法 JSON，**爬虫直接解析即可，比写 XPath 还方便**：

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "苹果手机 15 Pro",
  "image": "https://example.com/img/1.jpg",
  "description": "这是一台旗舰手机",
  "offers": {
    "@type": "Offer",
    "price": "5999",
    "priceCurrency": "CNY"
  }
}
</script>
```

```python
import re
import json
import requests

resp = requests.get("https://example.com/detail/1")
# 取出所有 ld+json 块
m = re.findall(r'<script type="application/ld\+json">(.*?)</script>', resp.text, re.S)
for block in m:
    data = json.loads(block)          # 直接转成字典
    print(data.get("name"))           # 苹果手机 15 Pro
    print(data["offers"]["price"])    # 5999
```

> 常见 `@type`：`Product`（商品）、`Article`/`NewsArticle`（文章）、`Recipe`（菜谱）、`Movie`（电影）、`JobPosting`（招聘）。抓取新闻/电商/点评类站点时，先搜 `ld+json`，往往一两行代码就拿到全部字段，省去繁琐的 XPath。

### 9. 结构化数据：Microdata（微数据，了解即可）

通过 `itemscope` / `itemprop` 属性把普通标签标记为结构化数据：

```html
<div itemscope itemtype="https://schema.org/Product">
    <span itemprop="name">苹果手机</span>
    <span itemprop="price">5999</span>
</div>
```

```python
from lxml import etree
html = '<div itemscope itemtype="https://schema.org/Product"><span itemprop="name">苹果手机</span><span itemprop="price">5999</span></div>'
tree = etree.HTML(html)
# 通过 itemprop 定位
print(tree.xpath("//*[@itemprop='name']/text()"))    # ['苹果手机']
print(tree.xpath("//*[@itemprop='price']/text()"))   # ['5999']
```

> 现在主流站点更常用 JSON-LD，Microdata 较少见，但遇到老站仍可能用到。

## 六·六、HTML 的 DOM 结构（树形结构）

浏览器会把 HTML 解析成一颗 **DOM 树**，方便 JS 操作和解析库定位：

```
document
 └─ html
     ├─ head
     │   ├─ meta
     │   └─ title
     └─ body
         ├─ div#header
         │   └─ nav
         ├─ main
         │   └─ article > h1, p
         └─ footer
```

- **父节点 / 子节点 / 兄弟节点**：与文件夹树类似；
- 爬虫的 xpath / bs4 / CSS 选择器，本质都是在**这颗树上按路径/条件找节点**；
- 理解"层级"很重要：`//div/span` 和 `//div//span` 结果不同（前者只找直接子级）。

### 标签嵌套规则（浏览器自动容错）

浏览器解析 HTML 时会**自动修正**一些不合法嵌套，理解它有助于看懂"被浏览器改写后的 DOM"：

- **块级元素**（div/p/h1~h6/ul/li/table/form）默认占满一行，可嵌套块级与行内；
- **行内元素**（span/a/img/input/em/strong）不换行，**不能**嵌套块级元素（浏览器会强行闭合）；
- `<p>` 内部**不能**直接放块级元素（如 div、ul），否则浏览器会把 p 截断；
- `<li>` 必须放在 `<ul>` 或 `<ol>` 内；`<tr>` 必须放在 `<table>` 内。

```python
# 浏览器容错的典型例子：p 里嵌 div 会被自动拆开
from lxml import etree
bad = "<p>开头<div>内容</div>结尾</p>"
tree = etree.HTML(bad)
# lxml 会补全/修正成 <p>开头</p><div>内容</div><p>结尾</p> 之类结构
print(etree.tostring(tree, encoding="unicode", pretty_print=True))
```

> **爬虫视角**：同一个网页，浏览器开发者工具里的 DOM 和抓回来的 `resp.text` **可能不完全一样**（因为 JS 动态改动 + 浏览器容错）。以实际 `resp.text` 为准写 XPath，必要时用 `etree.tostring` 查看解析后的真实树。

### 浏览器渲染流程（为什么有的数据抓不到）

一个网页从 URL 到显示，大致经过：

```
输入URL → DNS解析域名 → TCP三次握手 → 发送HTTP请求 → 服务器返回HTML
       → 解析HTML构建DOM树 → 解析CSS构建CSSOM → 合并成渲染树
       → 执行JS（可能再次修改DOM、发起新请求） → 布局 → 绘制
```

- **第一次 HTTP 响应**返回的是原始 HTML；之后 JS 发起的请求是**后续响应**（XHR/fetch）；
- 数据若由 JS 动态渲染（如 SPA、点击加载更多），原始 HTML 里就没有 → 需要找接口或浏览器渲染；
- 因此判断"数据在不在 HTML 里"，本质是判断它是在**首次响应**还是**JS 后续请求**里。

## 七、爬虫中 HTML 的综合应用示例

下面用 xpath 从一个商品列表页提取所有商品名称和价格：

```html
<!-- 假设页面结构如下 -->
<div class="goods-list">
    <div class="goods-item">
        <a href="/detail/1.html" class="goods-name">苹果手机</a>
        <span class="price">5999</span>
    </div>
    <div class="goods-item">
        <a href="/detail/2.html" class="goods-name">华为平板</a>
        <span class="price">2999</span>
    </div>
</div>
```

```python
from lxml import etree
import requests

html = requests.get("https://example.com/list").text
tree = etree.HTML(html)

items = tree.xpath("//div[@class='goods-item']")
for item in items:
    name = item.xpath("./a[@class='goods-name']/text()")[0]
    price = item.xpath("./span[@class='price']/text()")[0]
    href = item.xpath("./a/@href")[0]
    print(f"商品: {name}, 价格: {price}, 链接: {href}")
```

## 八、小结

- HTML 是网页的骨架，由**标签 + 属性 + 内容**组成；
- 掌握 `<a>`（链接）、`<img>`（图片）、`<table>`（表格）、`<form>`（表单）四大类标签，就能应对绝大多数爬虫场景；
- 文本标签：`div/p/h1~h6/span` 打底，`strong/em/del/mark/sub/sup/code/pre` 等格式化标签按语义取数（原价抓 `<del>`、现价抓 `<strong>`）；
- 块级 vs 行内：块级独占一行可设宽高，行内不换行不能嵌块级，浏览器会自动闭合非法嵌套；
- 表单进阶：`textarea`、`label`、`fieldset`、`datalist`、各种 `input type`（email/number/file/hidden）、`name`/`value`/`disabled` 属性、`enctype` 三种编码格式、HTML5 校验属性；
- 表格进阶：`thead/tbody/tfoot` 语义分组、`colspan/rowspan` 单元格合并；
- 高频爬虫知识点：`data-*` 自定义属性存数据、`data-src` 懒加载、`&nbsp;` 等 HTML 实体、iframe 嵌套页面、`meta charset` 决定解码、canvas 内容抓不到、`og:` 分享卡片可作备用数据源；
- 进阶知识点：`<base>` 影响相对路径基准、`href="javascript:void(0)"` 靠 JS 触发、`on*` 事件属性是逆向定位 JS 的入口、`<noscript>`/`<template>` 说明数据不在 HTML 里、字符编码（UTF-8/GBK）与乱码原理；
- `rel` 属性：`nofollow` 不收录、`noreferrer` 不传 Referer（反爬线索）；`meta robots` 只是"告知"搜索引擎，不构成技术拦截；
- `<link>` 预加载：`preconnect`/`dns-prefetch`/`preload`/`prefetch` 可提前暴露真实接口域名；
- **结构化数据**：`<script type="application/ld+json">`（JSON-LD）和 `itemprop`（Microdata）里藏着现成的 JSON，是提取数据的捷径；
- iframe 进阶：`sandbox` 隔离、`referrerpolicy` 控制 Referer、懒加载；
- **标签嵌套规则**：浏览器会自动容错修正不合法嵌套，`resp.text` 与开发者工具里的 DOM 可能不同；
- **浏览器渲染流程**：首次响应（HTML）与 JS 后续请求（XHR/fetch）之分，决定了数据能否在 `resp.text` 中直接找到；
- `<script>` 的 defer/async/内联区别决定了数据是否直接出现在 `resp.text` 里（否则需 JS 渲染）；
- HTML 会被解析成 **DOM 树**，理解父子/兄弟层级，xpath / bs4 / CSS 才能精确定位数据。
