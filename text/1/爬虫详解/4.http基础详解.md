# HTTP 协议 详解

## 一、什么是 HTTP？

**HTTP（HyperText Transfer Protocol，超文本传输协议）** 是互联网上应用最广泛的网络协议。所有的 WWW 文件都必须遵守这个标准。

**协议（Protocol）**：通信双方约定好的传输格式。HTTP 就是"浏览器/爬虫"与"服务器"之间约定好的请求与响应的格式规范。

### HTTP 是无状态的

**HTTP 本身是无状态协议**——服务器默认**不记得**上一次请求是谁发的、做了什么。每一次请求都是"全新的"。

因此要想让服务器"记住"用户（登录态、购物车），只能靠额外的机制：

- **Cookie**：服务器下发、浏览器保存、每次请求自动带上；
- **Session**：服务器端保存的用户状态，通过 Cookie 里的 sessionid 关联。

> 这也是为什么爬虫登录后要"带上 Cookie"——不带的话服务器每次都会把你当陌生人。

### 常见端口号

| 协议 | 默认端口 |
| ---- | -------- |
| HTTP | 80 |
| HTTPS | 443 |
| SSH（远程登录） | 22 |
| MySQL（数据库） | 3306 |
| Redis（缓存） | 6379 |
| MongoDB（数据库） | 27017 |

## 二、HTTPS 与 HTTP 的区别

| 对比项 | HTTP | HTTPS |
| ------ | ---- | ----- |
| 全称 | 超文本传输协议 | 安全套接层超文本传输协议 |
| 加密 | 明文传输 | 通过 SSL/TLS 加密传输 |
| 证书 | 无需证书 | 需要申请 SSL 证书（部分免费，企业级多收费） |
| 端口 | 80 | 443 |
| 连接 | 简单，无状态 | 加密传输 + 身份认证 |
| 安全性 | 低 | 高 |

> 简单理解：HTTPS = HTTP + SSL/TLS。它保证了传输内容不被窃听、不被篡改、并验证服务器身份。现在的网站几乎全部使用 HTTPS。

## 三、反爬虫的一般手段（为什么爬虫要懂 HTTP）

网站为了阻止爬虫，会使用以下手段。理解它们，才能针对性破解：

| 手段 | 说明 | 应对方案 |
| ---- | ---- | -------- |
| User-Agent 检测 | 检查请求头中的 UA，非浏览器则拒绝 | 设置浏览器 UA 头 |
| 代理 IP | 封禁高频访问的 IP | 使用代理 IP 池 |
| 验证码 | 人机验证 | 打码平台 / 图形识别（ddddocr） |
| 动态加载网页 | 数据通过 AJAX 异步加载，源码里没有 | 抓包分析接口，直接请求接口 |
| 数据加密 | 参数/响应加密（AES/RSA 等） | JS 逆向、还原加密逻辑 |
| 频率限制 | 同一 IP/账号访问过频被限 | 控制访问频率、加延时 |

## 四、HTTP 请求

### 0. URL 的结构（先搞清楚"请求发给谁"）

一个典型 URL 长这样：

```
https://www.example.com:8080/path/page?name=alex&page=2#section
└─┬─┘ └───────┬───────┘ └┬┘ └────┬────┘ └──────┬─────┘ └───┬───┘
协议       域名/主机     端口      路径         查询参数(Query)  锚点
```

| 部分 | 说明 | 爬虫注意点 |
| ---- | ---- | ---------- |
| 协议 | `http` / `https` | 决定是否加密 |
| 域名 | `www.example.com` | 服务器地址，有的还要带上 `Host` 头 |
| 端口 | `:8080` | 不写则默认 80/443 |
| 路径 | `/path/page` | 定位资源 |
| 查询参数 | `?name=alex&page=2` | GET 参数都在这，用 `&` 分隔，**注意 URL 编码** |
| 锚点 | `#section` | **不会发送给服务器**，仅浏览器内部定位，抓包 URL 里常要去掉 |

> GET 翻页、搜索的本质就是**改查询参数**：`?page=1` → `?page=2`。requests 中推荐用 `params` 字典，自动帮你做 URL 编码。

#### URL 编码（百分号编码，爬虫高频坑）

URL 里只允许一部分字符（字母、数字、`-_.~`），汉字、空格、`&`、`=`、`+` 等在 URL 中都必须转义成 `%xx`：

| 原始字符 | 编码后 | 说明 |
| -------- | ------ | ---- |
| 空格 | `%20`（有时是 `+`） | 空格最常见 |
| 中 | `%E4%B8%AD` | 汉字 UTF-8 编码 |
| 文 | `%E6%96%87` | 汉字 UTF-8 编码 |
| & | `%26` | 若在值里要转义，否则被当成参数分隔符 |

```python
from urllib.parse import quote, unquote, urlencode

# 手动编码单个值
print(quote("北京"))        # %E5%8C%97%E4%BA%AC

# 解码（抓包看到的 %xx 还原成中文）
print(unquote("%E5%8C%97%E4%BA%AC"))   # 北京

# 用 urlencode 构造查询串（最常用，自动处理所有特殊字符）
params = {"wd": "北京 天气", "page": 2}
print(urlencode(params))    # wd=%E5%8C%97%E4%BA%AC+%E5%A4%A9%E6%B0%94&page=2

# requests 里直接用 params 字典，自动编码
resp = requests.get("https://example.com/search", params=params)
print(resp.request.url)     # 可以看到编码后的完整 URL
```

> 抓包时 URL 里的 `%xx` 就是编码后的参数；用 requests 时**永远传原始中文给 params/data，不要自己先编码**，否则会双重编码导致搜索不到结果。

### 1. 请求消息格式

一个 HTTP 请求由三部分组成：

```
请求行
请求头

请求体
```

### 2. 请求行

```
GET /index.html HTTP/1.1
```

- 方法（GET）
- 请求路径（/index.html）
- 协议版本（HTTP/1.1）

### 3. 常见请求方法

| 方法 | 含义 |
| ---- | ---- |
| GET | 获取资源（查询） |
| POST | 提交数据（新增/登录） |
| PUT | 更新资源（整体替换） |
| PATCH | 部分更新资源 |
| DELETE | 删除资源 |
| HEAD | 只获取响应头（不返回响应体，用于探测） |
| OPTIONS | 查询服务器支持的方法（CORS 预检） |
| TRACE | 回显请求（调试用） |

> 爬虫中最常用 **GET**（查数据）和 **POST**（登录/提交）。**HEAD** 常用来"探测链接是否有效"而不下载内容，能省流量。

### 4. 常见请求头

| 请求头 | 含义 | 爬虫注意点 |
| ------ | ---- | ---------- |
| `Accept` | 浏览器支持的返回数据类型 | |
| `Accept-Charset` | 支持的字符集 | |
| `Accept-Encoding` | 支持的压缩格式（gzip 等） | |
| `Accept-Language` | 语言环境 | |
| `Host` | 想访问哪台主机 | 有些服务器校验 |
| `If-Modified-Since` | 缓存数据的时间 | |
| `Referer` | 从哪个页面跳转过来的 | **防盗链**，图片等资源常校验 |
| `Connection` | 请求后保持连接还是断开 | |
| `User-Agent` | 浏览器标识 | **最常被校验** |
| `Cookie` | 用户身份凭证 | 登录态靠它 |
| `X-Requested-With` | 值为 `XMLHttpRequest` 时代表 AJAX 请求 | 用于区分接口请求 |

### 5. 请求头中的 Content-Type（POST 必带）

POST 请求体的编码方式由 `Content-Type` 决定，**带错会导致服务器收不到参数**：

| 请求头 Content-Type | 请求体格式 | requests 用法 |
| ------------------- | ---------- | ------------- |
| `application/x-www-form-urlencoded` | `name=alex&pwd=123` | `data={...}` |
| `application/json` | `{"name":"alex"}` | `json={...}`（requests 自动设置该头） |
| `multipart/form-data` | 二进制分块（含文件） | `files={...}` |

```python
import requests

# 表单格式（登录、搜索最常见）
resp = requests.post(
    "https://example.com/login",
    data={"username": "alex", "password": "123"},
)

# JSON 格式（接口常用）
resp = requests.post(
    "https://api.example.com/submit",
    json={"name": "alex", "age": 18},
)
print(resp.request.headers.get("Content-Type"))  # application/json
```

> 抓包时先看请求头 `Content-Type`，再决定用 `data=` 还是 `json=`。**很多爬虫失败是因为"该用 json 却用了 data"或反过来。**

### 5.5 认证方式（Authorization 头，逆向高频）

很多接口需要身份凭证，通常放在 `Authorization` 请求头里，常见三种：

| 方式 | 格式 | 说明 |
| ---- | ---- | ---- |
| Basic Auth | `Authorization: Basic base64(用户名:密码)` | 最简单，把用户名密码 Base64 编码 |
| Bearer Token | `Authorization: Bearer <token>` | 登录后服务器发的令牌，最常见 |
| 自定义 Header | `X-Token: xxx` | 网站自定义的鉴权头，字段名因站而异 |

```python
import requests
import base64

# 方式一：Basic Auth（requests 会自动编码）
resp = requests.get("https://httpbin.org/basic-auth/alex/123",
                    auth=("alex", "123"))
print(resp.status_code)   # 200 表示认证成功

# 手动拼 Base64
token = base64.b64encode(b"alex:123").decode()
resp2 = requests.get("https://example.com/api",
                     headers={"Authorization": f"Basic {token}"})

# 方式二：Bearer Token（最常用）
resp3 = requests.get("https://api.example.com/user",
                     headers={"Authorization": "Bearer eyJhbGciOi..."})
```

> **逆向视角**：登录接口成功后返回的 `token` / `access_token`，后续请求都要带在 `Authorization` 头里；若 token 是 JWT（`eyJ...` 三段式），可在 [jwt.io](https://jwt.io) 解码查看里面的 payload。

### 5.6 Range 请求与断点续传（206）

下载大文件时，客户端可用 `Range` 头要求服务器**只返回某一段字节**，服务器返回 **206**（部分内容）：

```python
import requests

url = "https://example.com/big.zip"
# 请求第 1000 字节开始的内容
headers = {"Range": "bytes=1000-"}
resp = requests.get(url, headers=headers, stream=True)
print(resp.status_code)             # 206
print(resp.headers.get("Content-Range"))  # bytes 1000-999999/1000000

# 配合 stream=True 分块写入，避免大文件撑爆内存
resp2 = requests.get(url, stream=True)
with open("big.zip", "wb") as f:
    for chunk in resp2.iter_content(chunk_size=8192):
        f.write(chunk)
```

| Range 写法 | 含义 |
| ---------- | ---- |
| `bytes=0-99` | 前 100 字节 |
| `bytes=100-` | 从第 100 字节到最后 |
| `bytes=-500` | 最后 500 字节 |
| `bytes=0-99,200-299` | 多段（服务器可选择是否支持） |

> 服务器**不支持** Range 时会忽略该头、直接返回 **200** 全量内容。断点续传思路：先拿文件总大小（`Content-Length`），已下载部分续传剩余字节，最后拼接。

### 6. 压缩传输（Accept-Encoding / Content-Encoding）

服务器为了省流量，会按请求头 `Accept-Encoding: gzip` 把响应体压缩后传输，响应头用 `Content-Encoding` 标明压缩方式：

| 压缩方式 | 说明 |
| -------- | ---- |
| `gzip` | 最常见 |
| `deflate` | zlib 压缩 |
| `br` | Brotli 压缩（Chrome 默认会带） |
| 无 | 未压缩 |

```python
import requests
import gzip
from io import BytesIO

resp = requests.get("https://example.com", headers={"Accept-Encoding": "gzip"})
enc = resp.headers.get("Content-Encoding")

if enc == "gzip":
    data = gzip.decompress(resp.content).decode("utf-8")
else:
    data = resp.text
```

> `requests` 默认会自动解压 gzip/deflate，只有遇到**不自动解压的 br 压缩**或自建底层请求（urllib 未带 Accept-Encoding）时才需要手动处理。判断方法：响应头出现 `Content-Encoding` 且 `resp.text` 是乱码/二进制时就要手动解压。

## 五、HTTP 响应

### 1. 响应消息格式

```
状态行
响应头

响应体
```

### 2. 状态行

```
HTTP/1.1 200 OK
```

包含：协议版本、状态码、状态描述。

### 3. 常见响应头

| 响应头 | 含义 |
| ------ | ---- |
| `Location` | 告诉浏览器跳转到哪里（重定向） |
| `Server` | 服务器型号 |
| `Content-Encoding` | 响应数据的压缩格式 |
| `Content-Length` | 回送数据的长度 |
| `Content-Language` | 语言环境 |
| `Content-Type` | 回送数据的类型（如 text/html、application/json） |
| `Refresh` | 定时刷新 |
| `Content-Disposition` | 以下载方式打开数据 |
| `Transfer-Encoding` | 数据以分块方式回送 |
| `Expires: -1` | 控制浏览器不要缓存 |
| `Set-Cookie` | **服务器下发 Cookie**（记住，登录态靠它） |

### 3. MIME 类型（Content-Type 的值）

`Content-Type` 告诉客户端"返回的数据是什么类型"。爬虫中常遇到：

| Content-Type | 含义 |
| ------------ | ---- |
| `text/html` | HTML 网页（大部分爬虫目标） |
| `application/json` | JSON 数据（接口） |
| `application/x-www-form-urlencoded` | 表单提交格式 |
| `multipart/form-data` | 文件上传格式 |
| `text/plain` | 纯文本 |
| `application/xml` / `text/xml` | XML 数据 |
| `image/jpeg` / `image/png` | 图片 |
| `application/octet-stream` | 二进制流（文件下载） |
| `application/pdf` | PDF 文档 |

> 判断"是网页还是接口"就看 `Content-Type`；JSON 接口用 `resp.json()`，网页用 `resp.text`。

### 4. 内容协商（Content Negotiation）

服务器根据请求头决定返回什么：

| 请求头 | 作用 |
| ------ | ---- |
| `Accept` | 客户端能接受的数据类型 |
| `Accept-Language` | 客户端语言偏好（`zh-CN,zh;q=0.9`） |
| `Accept-Encoding` | 支持的压缩方式（`gzip, deflate`） |

```python
import requests

headers = {
    "Accept": "application/json",            # 期望服务器返回 JSON
    "Accept-Language": "zh-CN,zh;q=0.9",
    "Accept-Encoding": "gzip, deflate",
}
resp = requests.get("https://httpbin.org/headers", headers=headers)
print(resp.headers.get("Content-Encoding"))   # 若被 gzip 压缩会显示
```

### 5. 超时与重试（爬虫必会）

**超时**：请求发出后，若服务器迟迟不响应，设置超时可以避免程序"卡死"。

```python
import requests

# timeout 只设"连接"超时
resp = requests.get("https://example.com", timeout=5)

# timeout=(连接超时, 读取超时)  推荐写法
resp = requests.get("https://example.com", timeout=(3, 10))
# 3 秒连不上就放弃；连上后 10 秒读不到数据就放弃

# 只给读取超时：timeout=(None, 10)
resp = requests.get("https://example.com", timeout=(None, 10))
```

| timeout 写法 | 含义 |
| ------------ | ---- |
| `timeout=5` | 连接 + 读取都是 5 秒 |
| `timeout=(3, 10)` | 连接 3 秒、读取 10 秒 |
| `timeout=(None, 10)` | 不限制连接、读取 10 秒 |

**重试**：网络抖动或临时 5xx 时，自动重试几次更稳定：

```python
import requests
from requests.adapters import HTTPAdapter

s = requests.Session()

# 给 http/https 挂上重试适配器
adapter = HTTPAdapter(max_retries=3)   # 最多重试 3 次
s.mount("http://", adapter)
s.mount("https://", adapter)

resp = s.get("https://example.com")
```

> **爬虫视角**：批量爬取时强烈建议"超时 + 重试 + 延时"三件套。单请求超时设 `(3, 10)`；重试用 `HTTPAdapter` 或 `tenacity`/`retry` 库；再配合 `time.sleep(随机)` 控制频率，能显著降低被封概率。

### 5.1 手动实现简单重试（循环版）

不想引第三方库，可以自己写循环重试：

```python
import time
import requests

def get_with_retry(url, max_retries=3, **kwargs):
    for i in range(max_retries):
        try:
            resp = requests.get(url, timeout=(3, 10), **kwargs)
            if resp.status_code == 200:
                return resp
        except requests.exceptions.RequestException as e:
            print(f"第{i+1}次失败: {e}")
            time.sleep(1)   # 失败后等 1 秒再试
    return None

resp = get_with_retry("https://example.com")
if resp:
    print(resp.status_code)
else:
    print("重试多次仍失败")
```

> 更健壮的做法：只对"可重试的异常"（连接错误、超时、5xx）重试，4xx（如 403/404）重试也没意义，直接跳过。

### 6. GET 与 POST 的完整对比（高频面试/实战点）

| 对比项 | GET | POST |
| ------ | --- | ---- |
| 语义 | 获取资源 | 提交数据（创建/登录） |
| 参数位置 | URL 查询参数 | 请求体（body） |
| 是否幂等 | 是（重复执行结果相同） | 否（重复可能创建多条） |
| 是否缓存 | 可被缓存/收藏 | 一般不被缓存 |
| 长度限制 | 受 URL 长度限制 | 理论上无限制 |
| 可见性 | 参数明文在 URL/日志中 | 参数在 body，但抓包也能看到 |
| 典型场景 | 查询、翻页、搜索 | 登录、注册、上传、下单 |

> 很多网站**登录用 POST、翻页查询用 GET**。逆向时先在 Network 里看清方法，用错方法会返回 405 或参数收不到。注意：**POST 不代表安全**，抓包一样能看明文，真正的安全要靠 HTTPS + 参数加密。

### 7. CORS 跨域与 OPTIONS 预检（逆向接口会遇到）

浏览器出于安全，默认禁止跨域请求。前后端分离的网站常通过 **CORS（跨域资源共享）** 放行：

```http
# 响应头（服务器端返回，浏览器看到才放行）
Access-Control-Allow-Origin: https://www.example.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
```

- **简单请求**：GET/POST + 表单格式 → 浏览器直接发；
- **预检请求（Preflight）**：带自定义头 / `application/json` / 其他方法时，浏览器会**先发一个 OPTIONS 请求**询问服务器是否允许，得到许可后才发真实请求。

```python
# 抓包时看到"OPTIONS 方法"就是 CORS 预检
import requests
resp = requests.options("https://api.example.com/submit")
print(resp.headers.get("Access-Control-Allow-Origin"))  # 看放行来源
```

> **爬虫视角**：requests 模拟请求**不受 CORS 限制**（CORS 是浏览器行为），所以正常 `requests.get/post` 都能直接请求跨域接口；看到 OPTIONS 预检是浏览器发的，爬虫通常不需要管它。但如果用 jsdom/puppeteer 在"浏览器环境"里模拟，就会遇到 CORS。

### 8. Cookie 请求头的格式（登录态核心）

```http
Cookie: sessionid=abc123; uid=10086; token=xyz
```

- 多个 Cookie 用 `;` 分号 + 空格分隔；
- 每个 Cookie 是 `键=值` 对；
- 服务器通过 `Set-Cookie` 下发，浏览器自动存储并在下次请求带上。

```python
import requests
# 手动带 Cookie（抓包复制的字符串）
cookie_str = "sessionid=abc123; uid=10086"
resp = requests.get("https://example.com", headers={"Cookie": cookie_str})

# 或用 session 管理（推荐，会自动处理 Set-Cookie）
s = requests.Session()
s.get("https://example.com/login")          # 服务器 Set-Cookie 被自动保存
resp = s.get("https://example.com/profile") # 自动带上 Cookie
```

> 详见后面的《cookie 和 session 详解》文件，这里只强调：**Cookie 是维持登录态的核心，模拟请求时要么手动带 Cookie 头，要么用 Session 自动管理。**

### 9. HTTP 缓存机制（304 与 ETag）

服务器会用缓存头让浏览器"别重复下载"：

| 头 | 方向 | 作用 |
| ---- | ---- | ---- |
| `Cache-Control: max-age=3600` | 响应 | 资源可缓存 1 小时 |
| `Expires` | 响应 | 过期时间（老写法） |
| `ETag: "abc123"` | 响应 | 资源内容的"指纹/版本号" |
| `If-None-Match: "abc123"` | 请求 | 问服务器：内容还是 abc123 吗？ |
| `If-Modified-Since` | 请求 | 问服务器：内容从某时间起变过吗？ |

协商缓存的流程：

1. 第一次请求 → 响应带 `ETag` 和 `Cache-Control`；
2. 客户端再次请求时带上 `If-None-Match: <ETag>`；
3. 服务器对比：内容没变 → 返回 **304**（无响应体，省流量）；内容变了 → 返回 **200** 和新内容。

```python
import requests

# 第一次请求
resp = requests.get("https://httpbin.org/etag/abc")
etag = resp.headers.get("ETag")
print(resp.status_code, etag)

# 第二次带上 If-None-Match 询问是否变化
resp2 = requests.get("https://httpbin.org/etag/abc",
                     headers={"If-None-Match": etag})
print(resp2.status_code)   # 304，没有响应体
```

> **爬虫视角**：如果频繁抓同一个接口却被"限流/封 IP"，可以先利用缓存（304）减少不必要的重复下载；反过来，如果发现请求总是返回 304，说明服务器认为你的本地"缓存"没过期，需要清掉 `If-None-Match` / `If-Modified-Since` 或加随机参数（时间戳）强制刷新。

## 六、HTTP 状态码

### 1. 分类总览

| 状态码范围 | 含义 |
| ---------- | ---- |
| 100-199 | 信息类，用于指定客户端应相应的某些动作 |
| 200-299 | 请求成功 |
| 300-399 | 重定向（资源已移动，通常带 Location 头指向新地址） |
| 400-499 | 客户端错误 |
| 500-599 | 服务器错误 |

### 2. 常见状态码

| 状态码 | 含义 |
| ------ | ---- |
| 200 | 请求成功，最常见 |
| 201 | 创建成功（POST 后常见） |
| 204 | 无内容（成功但没有返回体） |
| 206 | 部分内容（断点续传/流式下载） |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 304 | 未修改（走缓存） |
| 307 / 308 | 临时/永久重定向（保留请求方法，与 301/302 略有差异） |
| 400 | 请求语法错误 |
| 401 | 未认证（需要登录/Token） |
| 403 | 禁止访问（无权限 / 被反爬拦截） |
| 404 | 请求的资源不存在 |
| 405 | 请求方法不被允许（如用 GET 调只支持 POST 的接口） |
| 408 | 请求超时 |
| 429 | 请求过于频繁（被限流） |
| 451 | 因法律原因不可用 |
| 500 | 服务器内部错误 |
| 502 | 网关错误（上游服务器无响应） |
| 503 | 服务不可用（服务器过载/维护） |
| 504 | 网关超时 |

> **爬虫提示**：遇到 401 检查有没有带登录态；遇到 403/429 通常是被反爬拦截，需要补 UA/Cookie/代理；遇到 404 可能是 URL 拼错；遇到 405 检查请求方法（GET/POST）是否正确。

### 3. 状态码在 requests 中的使用

```python
import requests

resp = requests.get("https://httpbin.org/status/404")

# 判断成功/失败
print(resp.ok)          # False（4xx/5xx 时为 False）

# 主动抛异常（配合 try/except）
try:
    resp.raise_for_status()
except requests.exceptions.HTTPError as e:
    print("HTTP 错误:", e.response.status_code)

# 手动分支处理
if resp.status_code == 200:
    print("成功")
elif resp.status_code == 403:
    print("被反爬拦截，需要补 UA/代理")
```

### 4. 重定向的处理（301/302）

服务器返回 301/302 时，响应头 `Location` 会指向新地址。浏览器会自动跟着跳，`requests` 默认也会（`allow_redirects=True`）：

```python
import requests

# 默认自动跟随重定向（最多 30 次）
resp = requests.get("https://httpbin.org/redirect/2")
print(resp.status_code)           # 200（最终结果）
print(resp.url)                   # 跳转后的最终 URL
print(resp.history)               # 重定向历史：每个中间 Response

# 关闭自动跟随，手动看跳去哪
resp2 = requests.get("https://httpbin.org/redirect/2", allow_redirects=False)
print(resp2.status_code)          # 302
print(resp2.headers.get("Location"))  # 要跳去的新地址
```

> **爬虫视角**：
> - 登录后跳转、短链（`t.cn/xxx`）、`http→https` 都会产生重定向；
> - 有些网站用 302 做"反爬中转"（先跳到一个验证页再回来），此时要 `allow_redirects=False` 单独跟踪 Location；
> - 注意：POST 遇到 302 时，`requests` 会**把方法改成 GET** 再跟随（除非 307/308 保留方法），某些接口依赖 POST 302 时会踩坑。

## 七、HTTP 的版本演进

| 版本 | 发布时间 | 特点 |
| ---- | -------- | ---- |
| HTTP/1.0 | 1996 | 每次请求都要新建 TCP 连接，用完即断，效率低 |
| HTTP/1.1 | 1997 | **持久连接**（keep-alive），一个连接可发多个请求；支持 chunked 分块传输、缓存控制 |
| HTTP/2 | 2015 | 多路复用（一个连接并行多个请求）、头部压缩、二进制分帧 |
| HTTP/3 | 2022 | 基于 UDP 的 QUIC 协议，减少握手延迟 |

> 爬虫基本无需关心版本，但要注意：**HTTP/1.1 的持久连接**意味着同一个 `requests.Session` 会复用 TCP 连接，请求更快；抓包时如果看到 `Connection: keep-alive` 就是持久连接。

### HTTPS 的加密流程（理解即可）

HTTPS = HTTP + TLS。建立连接时大致经历：

1. **握手**：客户端发起"ClientHello"，服务器返回"ServerHello" + **证书**（含公钥）；
2. **验证**：客户端验证证书是否可信（是否由受信任的 CA 签发、是否过期）；
3. **协商密钥**：客户端用公钥加密一个"预主密钥"发给服务器，双方各自算出**对称密钥**；
4. **加密通信**：之后所有数据都用这个对称密钥加密传输。

> 简单记忆：**握手阶段用"非对称加密"（RSA 等）安全地传递密钥，后续传输用"对称加密"（AES 等）**——这样既安全又高效。爬虫使用 `requests` 时这些过程全部自动完成，无需手动处理。

## 八、用 Python 完整查看一次 HTTP 交互

```python
import requests

resp = requests.get("https://httpbin.org/get", headers={
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"
})

# 状态码
```

### 用 curl 快速调试 HTTP

抓包后如果想快速验证，可以用命令行 `curl`（Windows 自带 curl.exe）：

```bash
# GET 请求，显示响应头
curl -i https://httpbin.org/get

# 只显示响应头（HEAD 效果）
curl -I https://httpbin.org/get

# POST 表单提交
curl -X POST -d "username=alex&password=123" https://httpbin.org/post

# POST JSON
curl -X POST -H "Content-Type: application/json" -d '{"name":"alex"}' https://httpbin.org/post

# 带 UA / Cookie
curl -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64)" -b "sessionid=abc" https://example.com

# 跟随重定向
curl -L https://example.com

# 下载文件
curl -o baidu.png https://www.baidu.com/img/bd_logo1.png
```

> F12 里复制请求 → 在 Network 面板的请求上右键 → "Copy as cURL"，可以直接生成 curl 命令，用来快速排查请求头/参数问题。

### 抓包实战思路

用 Chrome 开发者工具（F12）→ Network 面板抓包时：

1. 找请求：确认是 GET 还是 POST，URL 是什么；
2. 看请求头：哪些头是必须的（UA、Referer、Cookie）；
3. 看请求体：POST 的表单字段或 JSON 结构；
4. 看响应：数据是直接返回还是需要解密。

把这些信息"搬运"到 requests 里，就完成了一个接口的模拟请求。

## 九、小结

- HTTP 请求 = 请求行 + 请求头 + 请求体；响应 = 状态行 + 响应头 + 响应体；
- URL 结构：协议 + 域名 + 端口 + 路径 + 查询参数 + 锚点；GET 翻页/搜索就是改查询参数；
- URL 编码：汉字/空格/特殊字符要转义成 `%xx`，requests 传 `params`/`data` 会自动编码，不要手动双重编码；
- HTTP **无状态**，登录态靠 Cookie/Session 维持；
- 方法：GET/POST 最常用，HEAD 探测、PUT/PATCH 更新、DELETE 删除、OPTIONS 预检；
- 掌握常见请求头（UA、Referer、Cookie、Host、X-Requested-With）和响应头（Set-Cookie、Content-Type、Location）；
- 认证方式：Basic Auth（Base64）、Bearer Token（最常见）、自定义 Header；登录后的 token 要带在 `Authorization` 头里；
- Range 请求：`bytes=0-99` 指定字节段，服务器返回 206，用于断点续传/分片下载；
- POST 必带正确的 `Content-Type`：表单用 `data=`、JSON 用 `json=`、上传用 `files=`；
- 超时与重试：`timeout=(3,10)` 双超时、`HTTPAdapter(max_retries=3)` 自动重试、循环版手动重试；"超时+重试+延时"三件套降低被封概率；
- GET vs POST：参数位置、幂等性、缓存、长度限制的完整对比，登录多用 POST、翻页查询多用 GET；
- CORS 跨域：`Access-Control-Allow-Origin` 等响应头放行浏览器跨域；OPTIONS 预检是浏览器行为，requests 不受 CORS 限制；
- Cookie 请求头格式：`key=value; key2=value2`，靠 `Set-Cookie` 下发、Session 自动管理；
- 压缩传输：`Accept-Encoding` 请求、`Content-Encoding` 响应，requests 自动解压 gzip/deflate，br 可能要手动解；
- 缓存机制：`ETag` / `If-None-Match` / `304` 协商缓存，减少重复下载、突破"总返回旧数据"问题；
- MIME 类型：`text/html` 是网页、`application/json` 是接口，用 `Content-Type` 判断；
- 掌握状态码含义（200 成功、401 未认证、403 被拦截、404 不存在、405 方法错、429 限流、5xx 服务器错）；
- 重定向：301/302 带 `Location`，requests 默认跟随，`allow_redirects=False` 可手动跟踪（注意 POST 302 会变 GET）；
- HTTPS = HTTP + TLS：握手用非对称加密传密钥，传输用对称加密；
- 调试手段：Python `requests` + 浏览器 F12 抓包 + 命令行 `curl` 三者配合；
- 爬虫的本质就是：模拟浏览器构造 HTTP 请求，再从响应中提取数据。
