# 游戏配置详解（简单版）

> 这是《游戏配置指南》的加强版，多讲"为什么"，少讲"黑话"。
> 看完你能明白：配置到底存哪、为什么存那、以及常见格式都是啥。

---

## 先打个比方

- **配置** = 游戏的"遥控器"。音量、画质、键位这些，都是你随手能调的东西。
- 游戏里还分两种配置，千万别混：
  - **开发商定的**（平衡数值、关卡数据）→ 跟着游戏走，玩家一般不碰。
  - **你自己调的**（音量、画质、键位）→ 存到你电脑的用户目录里。

记住一句话：**谁要改，就放谁的地盘。** 玩家要改的，一定在用户目录，不在游戏安装目录。

---

## 一、Windows 游戏：为什么配置"不放进安装目录"？

老游戏、绿色版喜欢把配置放游戏根目录（比如生化危机4重制版的 `local_config.ini`）。
但现代游戏几乎都放**用户目录**，原因是四个硬道理：

1. **Program Files 不让普通用户写**：Windows 的 UAC 安全机制，往系统目录写文件会被拦或弹窗。
2. **多用户不打架**：你调的键位，不该影响同一个电脑上别人的。
3. **更新不丢设置**：游戏更新会重写安装目录，配置放里面一更新就没了。
4. **Windows 官方就推荐这么做**：微软专门给"用户数据"建了目录，软件照着来才规范。

### AppData 里三个文件夹到底啥区别？

`C:\Users\你的用户名\AppData` 是隐藏目录，底下三个文件夹分工不同，**找配置/存档基本就在这三个里**：

| 文件夹 | 一句话解释 | 游戏常用来 |
|--------|-----------|-----------|
| **Roaming** | 会跟着你的微软账户/域"漫游"到别的电脑 | 存配置（小） |
| **Local** | 只属于这台电脑，不漫游 | 存缓存、大文件 |
| **LocalLow** | 给"低权限"程序用的（沙盒、低完整性进程） | **Unity 游戏默认写这** |

> 就记：**Roaming 会同步、Local 只在本地、LocalLow 是低权限的角落。**

还有两个常见位置：`Documents\My Games\游戏名\`（老牌惯例）和 `Saved Games\`（微软给存档专用）。

## 二、各引擎的配置机制（重点）

每个引擎给开发者一套"存配置的 API"，背后都对应一个真实位置。**看懂这层，你就能反过来找配置。**

### Unity

Unity 让开发者统一用 `Application.persistentDataPath`（持久化数据目录），它在不同平台长这样：

| 平台 | 实际位置 |
|------|---------|
| **Windows 电脑** | `C:\Users\<用户名>\AppData\LocalLow\<公司名>\<游戏名>\` |
| macOS | `~/Library/Application Support/<公司名>/<游戏名>/` |

两个关键点：
- **为什么路径里有"公司名/游戏名"？** 因为 Unity 用它俩生成一个 **GUID 身份证**。只要公司名、产品名不变，更新多少次都读同一个文件夹，**你的设置/存档才不会丢**。
- **"LocalLow"只是默认**：开发者完全能改成别的地方。所以找不到就撒网搜（搜游戏英文名）。

> 记住：Unity 游戏 → 默认去 `LocalLow\公司名\游戏名\` 找。

### Unreal（虚幻引擎）

Unreal 用一整套 **INI 配置文件**（后缀 `.ini`，记事本能打开），结构是"`[分区]` + `键=值`"。

重点是它有**"层层覆盖"**机制：多个配置文件叠在一起，后面的盖前面的。玩家在设置里改的东西，最终写进"最高优先级"的那个文件里。

```
引擎基础配置  →  平台配置  →  项目默认配置  →  你这台电脑的实际设置（最优先）
  Base.ini    [平台]      Default*.ini    Saved\Config\[平台]\.ini
```

常见文件名：`DefaultGame.ini`（游戏规则）、`DefaultEngine.ini`（渲染物理）、`DefaultInput.ini`（键位）。

### Godot

- 项目的"身份证 + 配置"都叫 **`project.godot`**（一个文本文件）。
- Godot 有两条虚拟路径，是最容易踩坑的地方：
  - `res://` → 项目目录。**导出游戏后就变成只读**（被打包进 pck 了）。
  - `user://` → 用户目录。**保证能写**，配置/存档都应该放这。

`user://` 在 Windows 的真实位置：`%APPDATA%\Godot\app_userdata\<项目名>\`

> 常见坑：开发者在电脑上存 `res://` 能存能读，导出后全丢，因为 res:// 变只读了。**找 Godot 的配置存档，去 app_userdata，别翻游戏目录。**

### Capcom RE 引擎

RE 引擎 = 卡普空自研，生化危机系列、鬼泣5 都用它。
- 配置：正版在用户目录；**绿色版/破解版在游戏根目录的 `local_config.ini`**（生化危机4重制版就是）。

## 三、配置文件格式（看懂后缀）

一句话原理：程序脑子里是"对象"，硬盘上是"文字"。**配置文件格式 = 两者之间的翻译规则**。下面几种各有长短：

| 格式 | 像什么 | 优点 | 缺点 | 什么时候用 |
|------|--------|------|------|-----------|
| **`.json`** | 现代最流行 | 什么语言都能读、天然能套层级 | 不支持写注释、语法严格 | **默认首选** |
| `.ini` | 最古老 | 极简单、记事本就能写 | 不能多层嵌套、类型全靠猜 | 老游戏、简单开关、Unreal |
| `.yaml` | 人最舒服 | 能写注释、可读性最好 | 缩进错一格就崩 | 复杂配置、K8s/Docker |
| `.toml` | ini 的升级版 | 又简单又结构化、类型明确 | 生态不如 JSON 广 | Rust 系、现代工具 |
| `.xml` | 老牌严格 | 规范强、能校验 | 太啰嗦 | 老游戏、企业系统 |
| `.csv` | 表格 | 适合导入导出 | 只存表格，不存树 | 报表，游戏基本不用 |

**口诀**：和别的东西对接用 JSON；人要经常手写的复杂配置用 YAML/TOML；就几个开关用 INI。

## 四、命名规律：配置文件都叫什么名字？

### 通用命名

- 通用名：`config.json` / `settings.json` / `options.json`
- 按用途：`audio.json`（声音）、`video.json`（画质）、`input.json`（键位）、`balance.json`（平衡数值）
- 经验：**名字要让人一眼看出"这是什么设置"**，所以 `settings` / `config` / `options` 是出现率最高的三个词。

### 各引擎的配置命名习惯（重点）

不同引擎对"配置文件名"各有固定习惯，认出来就能直接猜到文件名：

| 引擎 | 配置文件名（常见） | 说明 |
|------|-------------------|------|
| **Unity** | 无固定名 | 引擎不规定，开发者随便起：`settings.json`、`config.dat` 都可能；玩家设置多数走 PlayerPrefs（注册表，键名是哈希，看不到文件） |
| **Unreal** | `DefaultGame.ini`、`DefaultEngine.ini`、`DefaultInput.ini`、`GameUserSettings.ini` | `Default*` 开头 = 引擎/项目默认；`GameUserSettings.ini` = 玩家在菜单里改的设置，优先级最高 |
| **Godot** | `project.godot` | 项目的"身份证 + 基础配置"；玩家设置写在 `user://`（即 app_userdata 目录）里，文件名开发者随意 |
| **Capcom RE 引擎** | `local_config.ini`（部分作品叫 `xxxconfig.ini`，如鬼泣5 是 `dmc5config.ini`） | 生化危机、鬼泣5 等；绿色版在游戏根目录，正版在 `userdata\<ID>\<AppID>\remote\win64_save\` |
| **Valve Source** | `config.cfg`、`autoexec.cfg`、`config_default.cfg` | 都在 `cfg\` 文件夹；`config.cfg` 是游戏自己写键位的，`autoexec.cfg` 是玩家自定义、每次启动自动执行 |
| **id Tech（Doom/Quake）** | `config.cfg`、`autoexec.cfg` | 都在 `base` 目录（`baseq2`、`baseq3`…）；菜单里改的写进 `config.cfg`，玩家自定义用 `autoexec.cfg` |
| **Bethesda（上古卷轴/辐射）** | `Skyrim.ini`、`SkyrimPrefs.ini`、`Fallout4.ini`、`Fallout4Prefs.ini` | 在 `Documents\My Games\<游戏名>\`；带 `Prefs` 的是画质/界面设置 |
| **RPG Maker** | 无固定配置名 | 开发者配置在游戏资源里；玩家设置存系统或游戏目录 |
| **Ren'Py** | `options.rpy` 等 | 配置写进游戏脚本（`.rpy`），玩家偏好存在存档目录 |

> 铁律：**引擎命名是"惯例"，不是"规定"**。看到 `DefaultGame.ini` 基本可断定 Unreal；但 Unity 游戏叫什么都行，别因为名字不像就排除掉。

## 五、核心总结（记住这 5 条）

1. **配置 = 遥控器**。开发商定的跟游戏走，玩家调的一定在用户目录。
2. 现代桌面游戏玩家设置存 **AppData**（Roaming/Local/LocalLow）。
3. **Unity → LocalLow、Godot → app_userdata、Unreal → 一套 ini**；全都是"默认"，开发者能改。
4. 后缀选型：**对接用 JSON、人写的复杂配置用 YAML/TOML、简单开关用 INI**。
5. 找不到就别死磕：**用系统搜索撒网找游戏英文名**，比猜路径靠谱。
