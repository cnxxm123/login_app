# 游戏存档领域知识库（详解版）

> 本文件是 `game-save-knowledge.md` 的完整扩展版。
> 适用场景：排查"云主机游戏"存档不加载、分辨率不对、换破解组存档、存档丢失等问题。
> 结构：原理 → 破解组规则 → 引擎位置 → 缓存 → 文件特征 → 优先级 → 陷阱 → 实战流程。

---

## 第一章 存档是怎么生成的（原理）

游戏运行时进度在**内存**里（血量、背包、位置…）。把内存"翻译"成硬盘文件的过程叫**序列化**。

- **文本存档**（JSON/XML）→ 记事本可打开可改 → 常见于独立游戏。
- **二进制存档**（.sav / .bin / .dat）→ 改不了 → **商业大作基本都是**（生化危机4重制版 `.bin` 即此）。

商业大作给存档上三道"保险"：

| 保险 | 作用 | 失败后果 |
|:---|:---|:---|
| 校验和 | 文件尾部存校验密码，读取时核对 | 对不上 → 提示"存档损坏" |
| 加密/混淆 | 防止十六进制改金钱/属性 | 直接改 → 校验失败 |
| 原子写入 | 先写临时文件再改名 | 写一半断电 → 旧档仍在，不会变半截坏档 |

> 结论：**存档不能随便改、有时会莫名坏**，原因就是这三道保险。

## 第二章 破解组存档规则详解

### 2.1 原理：为什么破解组要把存档转到"公共文档"？

正版存档在 `Steam安装目录\userdata\<SteamID>\<AppID>\remote\` 下。
未加密补丁（破解组）**不能保证所有用户机器上都装了 Steam**，所以会把存档重定向到 `C:\Users\Public\Documents\<未加密组名>\`（公共文档）或用户目录下。

### 2.2 各破解组速查表

| 破解组 | 特征文件 | 默认存档位置 |
|:---|:---|:---|
| CODEX / RUNE | codex.ini, steam_emu.ini（含 CODEX/RUNE） | `%PUBLIC%\Documents\Steam\CODEX\{AppID}` |
| RUNE（个别游戏） | 同 RUNE，但部分走 MicrosoftStore 目录 | `%PUBLIC%\Documents\MicrosoftStore\RUNE`（如《极限竞速：地平线6》） |
| FLT | flt.ini | `%APPDATA%\FLT\Steam\{AppID}` |
| Goldberg | steam_interfaces.txt, steam_settings/ | `%APPDATA%\Goldberg SteamEmu Saves\{AppID}` |
| Goldberg(local_save_path) | + configs.user.ini 含 local_save_path | **相对于 steam_api64.dll 所在目录**（不是游戏根目录！） |
| GSE（Goldberg 分支） | config.user.ini 含 account_steamid | `%APPDATA%\GSE Saves\{AppID}` |
| EMPRESS | empress.ini | `%LOCALAPPDATA%\EMPRESS\{AppID}`（部分走 `%PUBLIC%\Documents\EMPRESS\{AppID}`） |
| TENOKE | tenoke.ini | `%GAME_DIR%\Tenoke`（根目录） |
| Ali213 / 3DM | ali213.ini / 3dm.ini | `%GAME_DIR%\Profile`（根目录） |
| GOG | goggame-*.info | `%USERPROFILE%\Documents\My Games\{GameName}` |
| SKIDROW | SKIDROW.ini | `%LOCALAPPDATA%\SKIDROW\{AppID}` |
| PLAZA / DARKSiDERS | 同 CODEX | 同 CODEX |
| SSE（SmartSteamEmu） | SmartSteamEmu.ini | `%APPDATA%\SmartSteamEmu\{AppID}` |

### 2.3 各破解组的"账户 ID"与存档加密

**关键认知**：很多游戏的存档按"Steam 账户 ID"加密，不同破解组用自己的 ID，所以**不同破解组的存档互不通用**。想通用，要么改破解组的 ini 里的 ID，要么用工具转换。

| 破解组 | 账户信息文件 | ID 写法 | 典型默认 ID |
|:---|:---|:---|:---|
| RUNE | 游戏目录 `steam_emu.ini` | `AccountId=<好友ID>`（注意去掉 `#` 注释） | 好友ID `6144`（对应 17 位 `76561197960271872`） |
| EMPRESS | `...\EMPRESS\{AppID}\remote\settings\user_steam_id.txt` | 17 位完整 SteamID | 随发布者不同 |
| GSE | 游戏目录 `steam_settings\config.user.ini` | `account_steamid=<17位ID>` | 随发布者不同 |
| TENOKE | 游戏目录 `tenoke.ini` | `account = 0x<十六进制ID>` | 十六进制格式 |

### 2.4 Steam ID 转换（17 位 ↔ 好友 ID）

17 位 SteamID 与"好友 ID"（AccountId）可以互相换算：

```
好友ID = 17位SteamID - 76561197960265728
例如：76561197960271872 - 76561197960265728 = 6144（RUNE 默认 ID）
```

- 在线换算：https://steamid.io
- 批量转换存档：用"存档 UID 转换工具"（见 2.5）

### 2.5 破解组之间存档互转（实战 3 例）

以《生化危机4重制版》（AppID 2050650）为例，三种常见互转：

**例 1：EMPRESS 存档 → 用 RUNE 破解读取**
1. 打开 `C:\Users\Public\Documents\EMPRESS\2050650\remote\settings\user_steam_id.txt`，拿到 17 位 ID。
2. 到 https://steamid.io 把 17 位 ID 转成好友 ID（如 142577166）。
3. 编辑游戏目录 `steam_emu.ini`：把 `#AccountId=0` 改为 `AccountId=142577166`（**去掉 `#`**）。
4. 复制 EMPRESS 存档 `...\EMPRESS\2050650\remote\2050650\remote\win64_save\` 到 `...\Steam\RUNE\2050650\remote\win64_save\`。

**例 2：EMPRESS 存档 → 用 GSE 破解读取**
1. 从 `user_steam_id.txt` 拿到 17 位 ID。
2. 编辑 `steam_settings\config.user.ini`：把 `account_steamid=` 后面改成该 17 位 ID。
3. 复制存档到 `%APPDATA%\GSE Saves\2050650\remote\win64_save\`。

**例 3：正版存档 → 转成 RUNE 存档**
1. 用"存档 UID 转换工具"打开正版存档 `Steam\userdata\<你的好友ID>\2050650\remote\win64_save\`。
2. 左边读出正版好友 ID，右边输入 RUNE 默认 ID `6144`，点转换。
3. 把工具 `_OUTPUT\` 下生成的存档复制到 `...\Steam\RUNE\2050650\remote\win64_save\`。

> ⚠️ 光改 ini 里的 SteamID 不一定能直接读正版档，因为存档本体还按旧 ID 加密，必须用工具重写加密。**只有"原 ID 没变"时改 ini 才有效**（如例 1、例 2 是"不改变原加密账号"）。

## 第三章 引擎识别与存档/配置位置

### 3.1 引擎指纹速查

| 引擎 | 识别特征 | 存档位置（默认） |
|:---|:---|:---|
| Unreal Engine 4/5 | Engine 目录、Binaries\Win64、.uproject、.uasset | `%LOCALAPPDATA%\{ProjectName}\Saved\SaveGames` |
| Unity | UnityPlayer.dll、*_Data 目录 | `%LOCALAPPDATA%Low\{Company}\{Product}` |
| CryEngine | CrySystem.dll | 因游戏而异 |
| Godot | project.godot、.pck（魔数 GDPC） | `%APPDATA%\Godot\app_userdata\{ProjectName}` |
| RPG Maker | www 目录、nw.dll、Game.rgssad | 游戏目录内 save 或 www/save |
| Capcom RE 引擎 | re_chunk_*.pak、local_config.ini | 正版 `userdata\...\remote\win64_save\`；绿色版根目录 `win64_save\` |
| Bethesda | Skyrim.ini / Fallout4Prefs.ini | `Documents\My Games\{GameName}\`；存档 `.ess`/`.fos` |
| Valve Source | cfg\、*.vpk | 存档 `.sav` 在 `SAVE\` 文件夹 |
| id Tech | base\ 下的 config.cfg / autoexec.cfg | 因游戏而异 |
| Ren'Py | .rpa、renpy\、.save | `%APPDATA%\RenPy\` |

> **UE 引擎重要**：ProjectName 通常是 **exe 名去掉扩展名**（如 `ch5_pro.exe` → `ch5_pro`），**不是游戏显示名**。

### 3.2 UE 引擎配置文件详细位置（重点）

UE 的配置遵循"层层覆盖"机制：**引擎基础 → 平台 → 项目默认 → 实际设置（最高优先级）**。

玩家在菜单里改的设置最终写入 `GameUserSettings.ini`（画质/分辨率/帧率）。

| 阶段 | 位置 |
|:---|:---|
| 编辑器内 | `<项目目录>\Saved\Config\WindowsEditor\Game.ini` |
| 打包开发版 | `<打包目录>\<项目名>\Saved\Config\Windows\Game.ini` |
| **打包正式版（玩家）** | `%LOCALAPPDATA%\<项目名>\Saved\Config\Windows\GameUserSettings.ini` |
| 引擎编辑器偏好（开发者） | `%LOCALAPPDATA%\UnrealEngine\{版本}\Saved\Config\Windows\EditorSettings.ini` |

常见配置文件：
- `GameUserSettings.ini` — **玩家可调设置**（画质/分辨率/帧率），优先级最高
- `Game.ini` / `DefaultGame.ini` — 游戏规则
- `Engine.ini` / `DefaultEngine.ini` — 渲染/物理
- `Input.ini` / `DefaultInput.ini` — 键位
- `Scalability.ini` — 图形质量等级

> 排查"客户调分辨率没变化"时：确认存档/配置目录是 `%LOCALAPPDATA%\<exe名>\Saved\Config\Windows\`，用"预设存档把分辨率写死"可解决（见《解决问题.md》20260820 案例）。

### 3.3 各引擎存档命名规律（辅助验证）

| 引擎 | 存档后缀 | 命名规律 | 例子 |
|:---|:---|:---|:---|
| Unreal | .sav | 槽位名（SlotName） | `savegame.sav`、`Slot1.sav` |
| Unity | 无固定 | 开发者随意；PlayerPrefs 在注册表（键名哈希） | `save.dat`、`progress.json` |
| Godot | 无固定 | 常叫 save | `user://save_data.dat` |
| Capcom RE | 不固定 | 目录固定 `win64_save\`；文件名含 data/slot | `data00-1.bin` |
| Bethesda | .ess/.fos | 多段下划线命名；同目录 .skse/.bak | `Save3_599DDA48_1_..._.ess` |
| Valve Source | .sav | 按地图/章节 | `d1_town_01.sav` |
| RPG Maker | 各版本不同 | `SaveXX.后缀` / `fileXX.后缀` | `Save01.lsd`、`file1.rpgsave` |
| Ren'Py | .save | 页码-槽位；auto-/quick- 前缀 | `1-1LT1.save`、`auto-1.save` |

RPG Maker 后缀速记：`.lsd`(2000/2003) → `.rxdata`(XP) → `.rvdata`(VX) → `.rvdata2`(VX Ace) → `.rpgsave`(MV/MZ)。

> 命名是**辅助验证**，不是铁律。最稳仍是先认指纹（UnityPlayer.dll、.uproject 等）。

## 第七章 常见陷阱

1. **同一游戏可能有多个存档位置**（引擎存档 + 破解组存档，都要找）。
2. **Goldberg 的 local_save_path 相对路径基准是 DLL 目录**，不是游戏根目录。
3. **UE 的 ProjectName 是 exe 名**，不是游戏显示名。
4. **游戏未运行过时，所有存档目录都不存在**（路径对但文件夹还没生成）。
5. **注册表路径可能因 32/64 位系统不同**（注意 WOW6432Node）。
6. **部分游戏用 Windows VirtualStore 机制重定向写入**。
7. **不同破解组存档按各自 Steam ID 加密互不通用**，需改 ini 或用工具转换。
8. **破解版一般没有 Steam 云**，存档只在本地；正版/破解版存档一般不能直接互拷。
9. **新手教程记录可能存注册表**（每个存档对应不同注册表路径，见《解决问题.md》20260225 网吧&超市模拟器案例）。
10. **云同步失败常见急救**：删对应游戏的 `remotecache.vdf` 让 Steam 重新从云端拉取。

## 第八章 实战：备份与迁移黄金流程

1. **定期手动备份**（U 盘/网盘）是唯一可靠方案。
2. 换电脑/重装：**先关云同步 → 备份本地存档 → 拷到新电脑同路径 → 启动验证 → 再开云同步**。
3. 恢复后弹冲突 → 选"上传至 Steam"把本地这份覆盖云端。
4. 备份前**先退出游戏**，避免拷到写一半的坏档。
5. **备份只拷 `remote\` 里的存档文件**，不用管 `remotecache.vdf`（会自动重建）。
6. ⚠️ **千万别复制别人的 `steam_autocloud.vdf`**（云"身份证"，复制 = 云存档认错主、同步错乱）。

## 第九章 速查汇总

### Steam 云存档相关文件

| 文件 | 位置 | 作用 |
|:---|:---|:---|
| 云存档本地镜像 | `Steam\userdata\<SteamID>\<AppID>\remote\` | 云同步文件的本地真副本 |
| remotecache.vdf | 每个游戏 `userdata\<ID>\<AppID>\` 内 | 同步"账本"，不是存档本体，删了能重建 |
| steam_autocloud.vdf | Steam 安装目录 `config\`（全局） | 云"身份证"，绑定账户，**别复制别人的** |
| cloud_log.txt | `Steam\logs\` | 每次同步的日志，排查用 |

### UE 打包正式版关键位置

| 内容 | 位置 |
|:---|:---|
| 玩家配置（分辨率/画质/帧率） | `%LOCALAPPDATA%\<exe名>\Saved\Config\Windows\GameUserSettings.ini` |
| 存档 | `%LOCALAPPDATA%\<exe名>\Saved\SaveGames\` |
| 着色器缓存 | `%LOCALAPPDATA%\<exe名>\Saved\*.upipelinecache` |
