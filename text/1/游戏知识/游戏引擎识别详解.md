# 游戏引擎识别详解（简单版）

> 这是《游戏引擎识别指南》的加强版，多讲"为什么"，少讲"黑话"。
> 看完你能明白：每个引擎会留下什么"指纹"、怎么看穿它、看完怎么接着找配置/存档。

---

## 先打个比方

- **识别引擎** = 看游戏"穿的校服"。每个引擎打包游戏的方式都固定，留下独一无二的"指纹"。
- 为什么值得认？因为**每个引擎都有自己的"默认存档/配置位置"**。认出引擎 = 直接去它家抽屉拿东西，比满屋子乱翻快得多。

**但记住一条铁律：引擎给的只是"默认位置"，开发商可以改。** 所以认出引擎只是让你有方向，找不到还是要撒网搜。

---

## 一、先认四大引擎的"指纹"（重点）

### Unity —— 看两个东西就实锤

Unity 打包出的 Windows 游戏，结构一定是这样：

```
游戏名.exe              ← 只是个小壳子
UnityPlayer.dll         ← 引擎真正的心脏在这（带 Unity 签名）
游戏名_Data\            ← 所有游戏数据都在这
    ├── Managed\        ← 脚本代码
    └── StreamingAssets\← 原始资源
```

**原理**：Unity 把引擎本体塞进一个叫 `UnityPlayer.dll` 的文件，数据全堆在一个叫"`游戏名_Data`"的文件夹里。**这俩是 Unity 独有的招牌，看见基本实锤。**

其他特征：
- 启动时有 Unity 经典 logo；日志文件在 `LocalLow\<公司>\<游戏>\Player.log`。

### Unreal（虚幻引擎）—— 工程气息重

结构看起来像"一个正经项目"：

```
游戏名.uproject        ← 项目文件（用记事本打开是 JSON，写着绑定的引擎版本）
Engine\                ← 引擎本体
Content\               ← 游戏资源（.uasset / .umap）
Config\                ← 配置（Default*.ini）
Saved\                 ← 缓存/日志（存档在 Saved\SaveGames）
```

**原理**：`.uproject` 是 Unreal 独有的"项目身份证"；`.uasset` 资源格式也是独有后缀。看到这些大写目录 + 这些后缀 = Unreal。

### Godot —— 一个文本文件 + 一个包

```
游戏名.exe              ← 本身就是"完整引擎 + 启动器"
游戏名.pck              ← 所有资源打包（有时直接嵌进 exe，看不到 pck）
```

**原理**：
- 只要文件夹里有 **`project.godot`**（文本文件）就是 Godot 项目。
- **`.pck`** 是资源包，文件开头有固定暗号 `GDPC`（用十六进制工具能看见）。
- 配置/存档在 `%APPDATA%\Godot\app_userdata\`。

### Capcom RE 引擎（生化危机、鬼泣5）

- 资源包是 `re_chunk_*.pak`（带 `re_` 前缀）。
- 配置 `local_config.ini`、存档 `win64_save\`（绿色版都在根目录）。
- 记住"re_"开头 = RE 引擎，很好认。

### 其他引擎（看一眼留个印象）

| 看到 | 引擎 |
|------|------|
| 一堆 `.vpk` 资源包 + `cfg\` | Valve Source（CS、求生之路） |
| `Game.rgssad` / `www\` 文件夹 | RPG Maker |
| `flashplayer_32_sa.exe` + `.swf` | Flash 老游戏 |
| 一堆 `.rpa` + `renpy\` | Ren'Py 视觉小说 |

## 二、四种识别方法（从快到慢）

### 方法 1：看安装目录（最快最准）

装好后打开游戏目录，找上面的"指纹"：
- `UnityPlayer.dll` 或 `游戏名_Data\` → **Unity**
- `.uproject` / `Engine\` / `.uasset` → **Unreal**
- `project.godot` / `.pck` → **Godot**
- `re_chunk_*.pak` / `local_config.ini` → **RE 引擎**

### 方法 2：看运行中的进程（不用装任何东西）

游戏运行时打开 **任务管理器 → 详细信息**：
- `UnityCrashHandler64.exe` → Unity
- `UnrealCEFSubProcess.exe` / `CrashReportClient.exe` → Unreal
- `godot*.exe` → Godot

**原理**：引擎会自带"崩溃上报器"等辅助进程，名字是引擎起的、改不了。

### 方法 3：右键 exe 看"详细信息"（最省事）

找到主程序 `.exe` → **右键 → 属性 → 详细信息**，看"产品名称 / 公司名称 / 文件说明"：

- "Unity Player" / "Unity Technologies" → Unity
- "Unreal Engine" / "Epic Games" → Unreal

**原理**：Windows 程序自带"版本信息标签"，很多引擎把自己的名字写进去了。10 秒搞定，不用翻文件。

### 方法 4：看表现特征（兜底）

- 启动出现 Unity logo / 写着 "Made with Unity" / "Unreal Engine" → 最直接。
- 画面光照、粒子特别夸张、文件巨大 → 多半 Unreal（只能参考）。

## 三、认出引擎后 → 去哪找配置/存档

| 引擎 | 配置（默认） | 存档（默认） |
|------|-------------|-------------|
| **Unity** | `LocalLow\<公司>\<游戏>\` | 同左 |
| **Unreal** | 项目 `Config\Default*.ini` | `%LOCALAPPDATA%\<游戏>\Saved\SaveGames\` |
| **Godot** | 项目 `project.godot` | `%APPDATA%\Godot\app_userdata\<项目名>\` |
| **RE 引擎** | 根目录 `local_config.ini`（绿色版） | 正版 `Steam\userdata\...\win64_save\`；绿色版根目录 `win64_save\` |

### 再加一招：用"命名规律"反推引擎

不翻目录也能猜——每种引擎的**配置/存档文件名**有固定习惯，看到就能反推：

| 看到这个文件名/后缀 | 大概率是 |
|---------------------|---------|
| `DefaultGame.ini`、`GameUserSettings.ini` | Unreal |
| 存档是 `.sav`（`Saved\SaveGames\` 里） | Unreal |
| `project.godot` | Godot |
| `local_config.ini` + `win64_save\` | Capcom RE 引擎 |
| `Skyrim.ini` / `Fallout4Prefs.ini`、存档 `.ess` / `.fos` | Bethesda（上古卷轴/辐射） |
| `cfg\` 里的 `config.cfg` / `autoexec.cfg` | Valve Source |
| `base\` 里的 `config.cfg` / `autoexec.cfg` | id Tech（Doom/Quake） |
| `Save01.lsd`、`file1.rpgsave` 这类"槽位号"存档 | RPG Maker |
| `.save` 后缀、`%APPDATA%\RenPy\` 目录 | Ren'Py 视觉小说 |
| `.bin`、`.dat` 且位置五花八门 | 自定义引擎 / Unity（无固定） |

> 记住：**命名是"惯例"不是"规定"**，用来做交叉验证很管用，但不能当唯一依据。最稳的仍是先认指纹（UnityPlayer.dll、.uproject 等），再用命名规律复核。

> 再提醒一次：**全是"默认"，开发商能改**。认完引擎只是有方向，找不到就回归撒网搜。

## 四、最短路径（决策树）

```
打开游戏安装目录
│
├─ 有 游戏名_Data 或 UnityPlayer.dll ──────→ Unity → 去 LocalLow\公司\游戏 找
│
├─ 有 .uproject / Engine\ / .uasset ───────→ Unreal → 去 %LOCALAPPDATA%\<游戏>\Saved 找
│
├─ 有 project.godot / .pck ────────────────→ Godot → 去 app_userdata 找
│
├─ 有 re_chunk_*.pak / local_config.ini ───→ RE 引擎 → 根目录 win64_save 或 Steam userdata
│
└─ 都没有 ──→ 通用撒网：AppData 三个 + Documents\My Games + Saved Games 搜游戏英文名
```

**两个最便宜的判定动作**（不确定时先用）：
1. 右键主 exe → 详细信息看产品名（10 秒）。
2. 游戏运行时看任务管理器进程名（10 秒）。

---

## 五、核心总结（记住这 7 条）

1. **识别引擎 = 找配置/存档的捷径**，不是必需；找不到就撒网搜。
2. Unity 指纹：`UnityPlayer.dll` + `游戏名_Data` 文件夹。
3. Unreal 指纹：`.uproject` + `Content`/`Saved` 大目录 + `.uasset`。
4. Godot 指纹：`project.godot` 文本文件 + `.pck`（暗号 GDPC）。
5. RE 引擎指纹：`re_chunk_*.pak` / `local_config.ini` / `win64_save\`。
6. 免安装三法：看目录 / 看进程 / 右键 exe 看版本信息。认出引擎后用上表定位，找不到就搜。
7. **命名可反推引擎**（`DefaultGame.ini`、`.sav`、`.ess`/`.fos`、`SaveXX.lsd`、`.save`…），但只是惯例，用来复核最稳。
