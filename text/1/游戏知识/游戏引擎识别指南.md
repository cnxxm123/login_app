# 游戏引擎识别指南

> 一句话：判断引擎 = 找配置/存档的"捷径"，**不是必经之路**。想快速判断就看本指南；想直接找文件，先撒网搜（见《游戏存档指南》）。

---

## 一、4 种判断方法

### 方法 1：看游戏目录特征（最快最准）

装好后打开游戏安装目录，看有没有标志性文件：

| 看到这些 | 引擎 |
|----------|------|
| `UnityPlayer.dll`、`UnityCrashHandler.exe`、`*_Data\` 文件夹（如 `Game_Data`） | **Unity** |
| `Engine\`、`Binaries\`、`.uproject`、`.uasset` | **Unreal** |
| `project.godot` | **Godot** |
| `.exe` 同级有 `www\` 文件夹、`Game.rgssad` | **RPG Maker** |
| `flashplayer_32_sa.exe`、`.swf` | **Flash 老游戏** |
| 一大堆 `.bin` + `SND/` `BGM/` | **Ren'Py / 独立小游戏** |

> **Unity 最典型特征**：游戏目录里一定有 `<游戏名>_Data` 文件夹（含 `Managed\`、`StreamingAssets\`），启动时有 Unity 风格画面。

### 方法 2：看运行中的进程（不用装任何东西）

游戏运行时打开 **任务管理器 → 详细信息**，看进程名：

```
UnityCrashHandler64.exe     → Unity
UnrealCEFSubProcess.exe     → Unreal
CrashReportClient.exe       → Unreal
godot*.exe                  → Godot
```

### 方法 3：检查 .exe 的文件描述（最简单）

找到主程序 `.exe`，**右键 → 属性 → 详细信息**，看"产品名称"或"文件说明"：

- **"Unity Player" / "Unity Technologies"** → Unity
- **"Unreal Engine" / "Epic Games"** → Unreal
- 很多引擎会把名字写进版本信息里

### 方法 4：看游戏表现特征（兜底参考）

- 有典型 **Unity 启动 logo**、`Player.log` 在 `%appdata%\..\LocalLow` → Unity
- 高细节光照、瀑布般粒子、文件巨大 → 大概率 Unreal
- 启动画面直接写 **"Made with Unity" / "Unreal Engine"** → 最直接

---

## 二、判断出来后 → 配置/存档去哪找

| 引擎 | 配置位置 | 存档位置 |
|------|---------|---------|
| **Unity** | 默认 `LocalLow\公司名\游戏名\` | 同左（开发者可改，找不到就撒网搜） |
| **Unreal** | 项目 `Config\Default*.ini` | `Local\游戏名\Saved\SaveGames\` |
| **Godot** | 项目 `project.godot` | `Roaming\Godot\app_userdata\项目名\` |
| **Capcom RE 引擎** | `local_config.ini`（如生化危机4重制版） | 正版在 `Roaming\Capcom\游戏名\`；绿色版在根目录 `win64_save\` |

---

## 三、实操最短路径

1. 看安装目录有没有 `*_Data` 或 `UnityPlayer.dll` → **Unity**，两分钟定位
2. 没有，再看有没有 `.uproject` / `Engine` / `Binaries` → **Unreal**
3. 都没有，就用"撒网搜 + 看安装目录有没有 save/config"的通用找法（见《游戏存档指南》）

---

## 核心总结（3 条）

1. **最快判断**：看安装目录标志文件——`*_Data`/`UnityPlayer.dll` → Unity，`.uproject`/`Engine` → Unreal。
2. **判断引擎是捷径不是必需**，找不到也可以直接撒网搜存档/配置。
3. 判断出来后，用上面"引擎 → 位置"表定位；**引擎给的是默认路径，开发者可能改**，找不到就回归通用找法。
