# 游戏存档详解（简单版）

## 一、存档是怎么存出来的？（一句话原理）

游戏玩的时候，你的进度在"内存"里（血量、背包、位置…）。要把进度**变成硬盘上的一份文件**，程序要干一件事叫**序列化**——把内存里的东西"翻译"成文件里的一串数据。

- 有的游戏用**文字**存（JSON/XML）→ 记事本能打开、能改 → 常见于独立游戏（方便玩家改）。
- 有的游戏用**乱码般的二进制**存（.sav/.bin/.dat）→ 改不了 → **商业大作基本都是这种**（生化危机4重制版的 `.bin` 就是）。

商业大作还会给存档上三道"保险"：
1. **校验和**：文件尾部存一个"对不上就是坏了"的密码。读取时一算对不上，就提示"存档损坏"。
2. **加密/混淆**：防止你拿十六进制工具把金钱改成 99999。
3. **原子写入**：不直接覆盖旧档，先写临时文件再改名。**写一半断电，旧档还在**，不会变成半截坏档。

> 记住：**存档不能随便改、有时会莫名坏**，原因就是这三道保险。

## 二、存档去哪找？（通用四板斧）

90% 的 PC 游戏存档在这四个地方，挨个搜游戏英文名（`Win+E` 搜索框，范围选"此电脑"）：

```
C:\Users\你的用户名\
├── AppData\Roaming\游戏名\      （%APPDATA%）
├── AppData\Local\游戏名\        （%LOCALAPPDATA%）
├── AppData\LocalLow\游戏名\     （Unity 最爱）
└── Documents\My Games\游戏名\   （老牌惯例）
     Saved Games\游戏名\         （微软给存档专用）
```

> 提示：AppData 是隐藏目录，直接往地址栏粘完整路径也能进。

## 三、各引擎的存档去哪？（默认位置）

### Unity

Unity 没有官方存档 API，开发者就两种做法：

| 做法 | 原理 | 位置 |
|------|------|------|
| `PlayerPrefs` | 引擎内置的"小仓库" | Windows 存**注册表**（`HKEY_CURRENT_USER\Software\<公司>\<产品>`，键名是哈希） |
| 自己写文件 | 写进 `Application.persistentDataPath` | Windows 默认 `LocalLow\公司\游戏\` |

> Unity 存档**没有固定后缀**：开发者用 JSON 就能记事本改，用 `.dat`/`.sav` 就是二进制。先看 `LocalLow\公司名\游戏名\` 里有什么；没有文件就去注册表翻 PlayerPrefs。开发者能改路径，找不到就撒网搜。

### Unreal（虚幻引擎）

Unreal 有官方存档系统，按"槽位"存（像游戏的存档位）。

- 编辑器里：项目目录 `Saved\SaveGames\`
- **打包后**：大多重定向到 `%LOCALAPPDATA%\<游戏名>\Saved\SaveGames\`

> 别在安装目录傻找 Unreal 存档——打包后它通常跑用户目录去了。

### Godot

Godot 明确：存档写 `user://`，导出后保证能写。Windows 位置：

```
%APPDATA%\Godot\app_userdata\<项目名>\
```

> 开发者可改位置（项目设置里），找不到就搜 `app_userdata`。

### Capcom RE 引擎（重点实例）

生化危机系列、鬼泣5 用的是 RE 引擎，它的存档位置**跟"正版/破解版"走**：

| 版本 | 存档位置 |
|------|---------|
| **正版（Steam）** | `C:\Program Files (x86)\Steam\userdata\<你的ID>\<AppID>\remote\win64_save\`（文件是 .bin/.sav） |
| **绿色版/破解版** | 游戏**根目录** `win64_save\` 或 `save\` |
| **Xbox Game Pass 版** | 微软加密目录 `%LOCALAPPDATA%\Packages\CAPCOM.xxx\SystemAppData\wgs\`（无法移植到 Steam 版） |

> 关键领悟：**存档跟着"平台给的持久化位置"走**，不一定固定在某处——正版跟 Steam、绿色版跟根目录。

### 各引擎的存档命名规律（重点速查）

认出引擎后，不光知道"存哪"，还能猜到"文件名长什么样"：

| 引擎 | 存档后缀 | 命名规律 | 例子 |
|------|---------|---------|------|
| **Unreal** | `.sav` | 文件名 = 开发者设置的"槽位名（SlotName）" | `savegame.sav`、`Slot1.sav` |
| **Unity** | 无固定 | 开发者随意；PlayerPrefs 在注册表（键名是哈希） | `save.dat`、`progress.json` |
| **Godot** | 无固定 | 开发者随意，常叫 save / 存档相关 | `user://save_data.dat`、`savegame.json` |
| **Capcom RE 引擎** | 不固定（RE4 重制版是 `.bin`，生化2 重制版/鬼泣5 是 `.sav`） | 后缀随作品变，但目录**固定叫 `win64_save\`**；文件名常含 `data`/`slot` 字样 | RE4 重制版 `data00-1.bin` |
| **Bethesda（上古卷轴/辐射）** | `.ess`（上古卷轴）/ `.fos`（辐射4） | 下划线分隔的多段命名，**各版本不同**（上古卷轴5特别版是"槽位_种族ID_是否MOD_角色名_地点_时间_等级"）；同目录有 `.skse`（SKSE 插件存档）和 `.bak`（备份） | `Save3_599DDA48_1_56616E20426C65616B_DarkwaterWorld_000612_20220409152435_8_1.ess` |
| **Valve Source** | `.sav`（在 `SAVE\` 文件夹） | 按地图/章节命名 | `d1_town_01.sav` |
| **RPG Maker** | 按版本不同 | 一律 `SaveXX.后缀` / `fileXX.后缀`（XX = 槽位号） | `Save01.lsd`、`file1.rpgsave` |
| **Ren'Py** | `.save` | `页码-槽位号`（可能带截图后缀）；自动/快速存档以 `auto-`、`quick-` 开头 | `1-1LT1.save`、`auto-1.save` |

各版本 RPG Maker 存档后缀速记：`.lsd`（2000/2003）→ `.rxdata`（XP）→ `.rvdata`（VX）→ `.rvdata2`（VX Ace）→ `.rpgsave`（MV/MZ）。

> 命名规律是**辅助验证**：看到 `.ess`/`.fos` 就知道是 Bethesda，看到 `Save01.lsd` 就是 RPG Maker 2000/2003。但名字仍由开发者定——**规律是参考，不是铁律**。

## 四、Steam 云存档深挖（重点）

### 4.1 云存档是"另一份进度"吗？

**不是！** Steam 云存档 = **本地一份真存档 + 云端一份复印件**。Steam 只是个"文件同步工具"，它不管文件内容，只管"哪些文件、多大、何时改过"。

```
游戏玩 → 写本地存档（真身）
            ↓ 退出游戏后，Steam 自动上传
         → 云端（复印件/备份）
            ↓ 换电脑 / 重装
         → 启动游戏前下载回本地
```

三个必须知道的事：
- 云是**备份不是保险箱**：Steam 官方自己都说，云出问题导致的数据丢失**可能找不回**，历史快照也会被新档慢慢覆盖。
- **关掉云 = 只有本地一份**，删了真没了。
- 备份永远靠自己：**定期把存档文件夹复制到 U 盘/网盘**，最稳。

### 4.2 云端文件本地缓存：userdata 目录

```
C:\Program Files (x86)\Steam\userdata\<你的SteamID>\<AppID>\remote\
```

- `<你的SteamID>`：17 位数字账号（多账号就有多文件夹）。
- `<AppID>`：游戏 ID（商店页网址里的数字，如 Dota2 是 570）。
- `remote\`：**云同步文件的本地真副本**，备份就拷这里。

### 4.3 remotecache.vdf —— 云同步的"记账本"

位置：每个游戏的 `userdata\<ID>\<AppID>\` 里面。

- **作用**：记录每个云文件"多大、何时改、有没有同步"。Steam 靠它判断本地和云端谁新。
- **不是存档本体**：删了它**不会删存档**，只是让 Steam 失去同步记录。
- 实用价值：云存档同步失败时，**删掉这个 vdf** 让 Steam 重新从云端拉取，是常见急救法。

### 4.4 steam_autocloud.vdf —— 云存档的"身份证"

位置：`Steam 安装目录\config\steam_autocloud.vdf`（全局一个，不属于某个游戏）。

- **作用**：记录"这台机器的云存档属于哪个账户"。
- **⚠️ 千万别复制别人的**：把别人的身份证拷给自己 = 云存档认错主、同步错乱。

### 4.5 为什么云存档位置五花八门？（Root 路径原理）

有的游戏云存档在"我的文档"，有的在 AppData——因为**开发商配置存档路径时用的是"路径代号"**（比如"我的文档"、"Saved Games"），Steam 把代号转成数字 ID，记录在 `remotecache.vdf` 里。常见代号：

| 数字 ID | 对应位置 |
|---------|---------|
| 0 | Steam 云目录 `remote\` |
| 1 | 游戏安装目录 |
| 2 | 我的文档 |
| 4 | `AppData\Local` |
| 9 | Saved Games 文件夹 |
| 12 | `AppData\LocalLow` |

> 所以不用死记某游戏在哪——**知道"它在 Steam 云里，云可能映射到任意位置"就够了。**

### 4.6 云同步的其他细节

- **何时同步**：游戏**退出后**自动上传；另一台设备**启动游戏前**下载。
- **冲突**：同一份文件本地和云端都改过、没同步 → 启动时弹窗让你选。一般**按修改时间选新的**。
- **离线模式**：离线不同步，回线才补，容易引发冲突。
- **同步失败**常见原因：网络差（可加速器）、缓存坏（删 remotecache.vdf）、磁盘满、网盘/杀软锁了文件夹。
- **找回旧档**：Steam 网页端 → 账户详情 → 云服务 → 该游戏 → 显示文件 → 选旧时间戳 → 还原。**还原前先关自动云同步**，否则坏档又上传把旧档覆盖。
- **日志**：`Steam\logs\cloud_log.txt` 记录每次同步，排查用。

### 4.7 备份时拷什么？

**只拷 `remote\` 里的存档文件即可**，不用管 `remotecache.vdf`（会自动重建）。拷到新电脑后**先关云同步再放档**，验证没问题再开，避免被云端旧档覆盖。

## 五、破解版/学习版存档

- 破解版一般**没有 Steam 云**，存档只在本地（游戏根目录或用户目录）。
- 生化危机4绿色版：配置 `local_config.ini` + 存档 `win64_save\` 都在**游戏根目录**。
- 破解版存档往往**跟破解组/版本绑定**，换版本可能不通用；**正版和破解版存档一般不能互拷**。

---

## 六、备份与迁移黄金流程

1. **定期手动备份**（U 盘/网盘）是唯一可靠方案。
2. 换电脑：**先关云同步 → 备份本地存档 → 拷到新电脑同路径 → 启动验证 → 再开云同步**。
3. 恢复后若弹冲突，选"上传至 Steam"把本地这份覆盖云端。
4. 备份前**先退出游戏**，否则可能拷到写一半的坏档。

## 七、核心总结（记住这 9 条）

1. 存档 = **进度日记**，靠"序列化"把内存变文件；大作都是二进制 + 加密，改不了。
2. 通用找法：`AppData`（Roaming/Local/LocalLow）+ `Documents\My Games` + `Saved Games` 挨个搜游戏英文名。
3. **Unity → LocalLow、Unreal → %LOCALAPPDATA%\Saved\SaveGames、Godot → app_userdata**（都是默认）。
4. RE 引擎：正版在 `Steam\userdata\<ID>\<AppID>\remote\win64_save\`，绿色版在根目录。
5. **Steam 云 = 本地一份 + 云端复印件**，不是第二份进度。
6. `remotecache.vdf` = 同步**记账本**（删了能重建）；`steam_autocloud.vdf` = 云**身份证**（别复制别人的）。
7. 云存档位置五花八门，是因为开发商用"路径代号 → 数字 ID"映射到不同地方。
8. 备份只拷 `remote\` 里的文件；一切以**手动备份**为准，云端只是便利不是保险。
9. **命名能反推引擎**：`.sav` 多属 Unreal、`.ess`/`.fos` 是 Bethesda、`SaveXX.lsd`/`.rpgsave` 是 RPG Maker、`.save` 是 Ren'Py——但都是惯例，不是铁律。
