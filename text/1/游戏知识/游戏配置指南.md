# 游戏配置完全指南

## 一、配置文件一般放哪

### Windows 桌面游戏（先判断类型）

| 类型 | 判断方法 | 配置位置 |
|------|---------|---------|
| **老式单机 / 绿色版** | 安装目录里有 `config.ini` / `settings` / `save` | **游戏根目录**（如 RE4 的 `local_config.ini`） |
| **现代游戏**（Steam 等） | 安装目录里没有这些 | **`%appdata%` 系列**（下图） |

```
C:\Users\你的用户名\
├── AppData\Roaming\游戏名\      # 常用配置
├── AppData\Local\游戏名\        # 本地配置+缓存
├── AppData\LocalLow\游戏名\     # Unity 最爱
└── Documents\My Games\游戏名\   # 也很常见
```

> 为什么现代游戏不写安装目录：`Program Files` 没写权限、触发 UAC 弹窗、多用户互相覆盖、卸游戏丢配置。

### 三大引擎

| 引擎 | 配置位置 |
|------|---------|
| **Unity** | 默认 `AppData\LocalLow\公司名\游戏名\`（**是默认不是一定**，开发者可改路径，找不到就撒网搜） |
| **Unreal** | 项目根目录 `Config\`：`DefaultGame.ini`、`DefaultEngine.ini`、`DefaultInput.ini` |
| **Godot** | 项目根目录 `project.godot`；玩家配置在 `user://` → `Roaming\Godot\app_userdata\项目名\` |

## 二、后缀怎么选

| 后缀 | 特点 | 用在哪 |
|------|------|--------|
| **`.json`** ⭐ | 最流行、现代首选 | 几乎所有现代游戏 |
| `.yaml` / `.yml` | 可读性好、支持注释 | 云游戏、工具配置 |
| `.ini` | 最简单 `键=值` | 老游戏、简单开关、Unreal |
| `.cfg` / `.conf` | 同 ini 变体 | Source 引擎、Godot |
| `.toml` | 比 ini 更规范 | Rust 系、现代工具 |
| `.xml` | 老牌但啰嗦 | 老游戏 |
| `.asset` / `.tres` | 引擎专属 | Unity / Godot |

**口诀：默认选 `.json`，要写注释用 YAML/TOML，就几个简单开关用 `.ini`。**

---

## 三、怎么命名

- **通用名**：`config.json` / `settings.json` / `options.json` / `game.json`
- **按用途**：`audio.json`（音效）、`video.json`（画质）、`input.json`（键位）、`language.json`（语言）、`balance.json`（平衡数值）、`levels.json`（关卡）
- **引擎惯用**：`DefaultGame.ini`（Unreal）、`project.godot`（Godot）、`local_config.ini`（Capcom RE 引擎，生化危机4重制版）

---

## 四、推荐目录结构

```
my-game/
├── config/                  # 开发者配置（随游戏发布）
│   ├── game.json            # 核心数值：速度、重力、金币
│   ├── balance.json         # 平衡数值
│   └── levels.json          # 关卡数据
├── assets/                  # 美术、音频
└── js/                      # 游戏逻辑
```

玩家个人设置（音量、画质、键位）→ 单独走 **AppData 下 settings.json**（桌面）。

---

## 核心总结（4 条）

1. **后缀优先 `.json`**，命名 `config` / `settings` + 用途前缀（`audio.json`、`balance.json`）。
2. **数值和逻辑分离**：所有可调数值集中一个配置文件，改平衡不动代码。
3. **开发者配置**随游戏走；**玩家配置**存用户目录。
4. **别往安装目录写**：权限、UAC、多用户覆盖、重装丢失。
