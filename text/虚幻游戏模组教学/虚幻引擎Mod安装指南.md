# 虚幻引擎游戏 Mod 安装教程（Pak / UE4SS 篇）

> 本教程基于 UE4SS 官方文档（docs.ue4ss.com）和 RE-UE4SS 官方仓库整理，适合零基础玩家。
>
> **重要**：虚幻引擎（UE）的 Mod 玩法和 Unity 完全不同——**没有统一的“框架 + DLL”安装法**。Pak 资源、UE4SS 脚本、官方 Mod 平台、游戏专用加载器等可能并存；安装前必须先看**该游戏和该 Mod 下载页**的说明。
>
> **通用性边界（必读）**：`~mods`、`LogicMods`、Pak 文件名 `_P`、代理 DLL 名称、UE4SS 的目录布局都可能是游戏或发布包专用约定，不是所有 UE 游戏都适用。目录、配套 `.sig` / `.utoc` / `.ucas` 文件、加载器版本与顺序，一律以 Mod 作者和游戏社区说明优先。
>
> 如果你的游戏是 Unity 引擎，请看同目录下的《Unity 游戏 Mod 安装教程》（MelonLoader 篇 / BepInEx 篇）。

---

## 一、前置知识

### 1.1 UE Mod 的三条路

Unity 游戏常见的 Mod 是“加载框架 + DLL”，但也可能有官方 Mod 支持或游戏专用加载器；UE 游戏同样不能只凭文件扩展名判断路线。下面是常见分类，**不是所有游戏的固定规则**：

| 路线 | 常见原理 | 常见适用 Mod | 是否需要额外加载器 |
|------|----------|-------------|------------------|
| **Pak / IoStore 资源 Mod** | 由游戏或专用加载器挂载资源包 | 换皮肤、改贴图、模型、数据资源 | 取决于该游戏；可能还需要配套文件或加载器 |
| **UE4SS 框架** | 注入脚本系统，在运行时用 Lua/C++ 扩展游戏逻辑 | 加菜单、改玩法、调概率、新功能 | 需要按游戏要求安装 UE4SS |
| **官方 Mod 支持** | 游戏自带创意工坊、mod.io、官方 SDK 等 | 以官方支持范围为准 | 通常不需要额外注入框架 |

> **怎么判断路线？** 以 Mod 下载页、压缩包 README 和该游戏社区置顶说明为准：如果作者写“放进 `Paks/~mods`”“放进 `LogicMods`”或“Requires UE4SS”，那是该 Mod 的安装要求，不能推广到其他 UE 游戏。

**不同路线可能共存**，但是否可共存、加载顺序和联机兼容性仍由具体游戏决定。

### 1.2 怎么判断游戏是不是虚幻引擎

打开游戏根目录，下面特征可以帮助判断它**可能**使用 UE，但不是绝对证明；最可靠的是游戏官方资料、PCGamingWiki 或该游戏 Mod 社区的引擎说明：

| 特征 | 说明 |
|------|------|
| 有 `Engine/` 文件夹 | 引擎资源目录 |
| 有 `游戏名/Binaries/Win64/` 目录 | 里面有 `游戏名-Win64-Shipping.exe`（Shipping 后缀是 UE 打包标志） |
| 有 `游戏名/Content/Paks/` 目录 | 里面有大量 `.pak` 文件（UE 的资源打包格式） |

> 不确定就去 PCGamingWiki 查该游戏的引擎信息，或直接看 Mod 页面写没写 "Requires UE4SS"。

### 1.3 和 Unity Mod 的关键差异

| 对比项 | Unity（常见加载器生态） | UE（常见资源包 / UE4SS 生态） |
|--------|--------------------------|--------------------------------|
| Mod 形态 | 常见为托管 DLL、资源包或游戏专用格式 | 常见为资源包、Lua/C++ Mod、官方 Mod 或游戏专用格式 |
| 加载方式 | 常由 MelonLoader、BepInEx、官方支持或专用加载器决定 | 常由游戏 Pak/IoStore 挂载规则、UE4SS、官方支持或专用加载器决定 |
| 代理/注入 | 仅部分加载器与游戏使用代理 DLL，名称按发布包和游戏要求而定 | UE4SS 等加载器可能使用代理 DLL，名称同样因游戏/发布包而异 |
| 联机与反作弊 | 任何注入式 Mod 都可能触发限制 | 任何注入式 Mod 都可能触发限制；不要按引擎类别推断“安全” |

## 二、路线一：Pak 资源 Mod（最简单）

### 2.1 原理

UE 游戏可能把资源打包为 `.pak`，也可能使用 IoStore 文件（常见为 `.utoc` / `.ucas`）。资源包是否自动挂载、挂载路径、覆盖顺序、签名要求和是否需要专用加载器，都由**具体游戏**决定；不能仅根据扩展名判断“放进去一定生效”。

### 2.2 安装步骤（仅在 Mod 页面明确要求 `Paks/~mods/` 时适用）

以下是部分游戏/Mod 使用的目录约定，以 Palworld 类说明为例；它**不是所有 UE 游戏的标准路径**：

1. 先完整阅读 Mod 下载页和压缩包 README，确认它要求 `~mods`、其他目录、专用加载器，还是官方 Mod 平台。
2. 如果作者明确要求 `游戏名/Content/Paks/~mods/`，再定位该游戏实际的 `Paks` 目录并创建 `~mods`。
3. 按原样复制作者提供的文件；若压缩包带有同名 `.sig`、`.utoc`、`.ucas` 或其他配套文件，不要只抽取 `.pak`。
4. 只在作者说明允许的离线/单人环境验证；不生效时先查看 Mod 作者的排错说明，而不是自行猜测加载顺序。

```text
Pal/Content/Paks/
├── Pak-Windows.pak          ← 游戏原版（不要修改）
└── ~mods/                   ← 仅当该 Mod 明确要求时创建
    ├── BetterSkin_P.pak     ← 示例：保持作者提供的文件名与配套文件
    └── ...
```

### 2.3 重要边界

| 情况 | 正确做法 |
|------|----------|
| `~mods` 文件夹 | 这是部分游戏/加载器的约定；不能把“波浪号一定最后加载”或“更新一定不会清理”当作通用规则。 |
| 文件名带 `_P` | 不要擅自重命名，但也不要把它当作所有游戏的优先级保证；完整保留作者提供的命名与配套文件。 |
| `LogicMods` | 仅当所用 UE4SS 蓝图 Mod/游戏说明明确要求时使用；不要把所有蓝图 pak 都默认放进去。 |
| 不确定放哪里 | Mod 作者说明、README、该游戏社区置顶说明优先；不要自行分析 pak 或套用其他游戏目录。 |
| 游戏更新后 | 更新可能改变资源、签名、挂载或 Mod 兼容性；备份自己的 Mod 清单后逐个排查，不承诺任一目录不会被更新影响。 |

## 三、路线二：UE4SS 框架

### 3.1 UE4SS 是什么

UE4SS（Unreal Engine 4/5 Scripting System）是 UE 游戏中**常见**的 Mod 框架之一，功能可类比 Unity 生态中的 MelonLoader/BepInEx：

- **Lua 脚本系统**：用 Lua 读写游戏对象、调用函数
- **C++ Mod API**：高性能深度修改
- **蓝图 Mod 加载器**：可为**符合该加载器与游戏要求**的蓝图 Mod 提供加载能力
- **调试工具**：游戏内控制台、属性查看器、热重载

> 当前社区维护项目为 **RE-UE4SS**（GitHub: UE4SS-RE/RE-UE4SS）。它面向 UE4/UE5 游戏，但“能否运行”取决于具体游戏、引擎改动、UE4SS 版本、Custom Game Config 与 Mod 要求；不要把固定的 UE 小版本范围当作兼容性承诺。

### 3.2 下载与版本选择

1. 打开发布页：`github.com/UE4SS-RE/RE-UE4SS/releases`
2. 下载标准版 `UE4SS_vX.X.X.zip`（**不要**下 `zDEV` 开发版，普通玩家用不到）
3. **版本不是越新越好**：Mod 页面指定了版本就按指定的装（比如 Palworld 社区长期用 v3.0.1）

### 3.3 基础安装：以当前下载包的实际布局为准

1. **确保游戏已关闭**。
2. 找到真正运行的游戏可执行文件所在目录。许多 UE 游戏位于：
   ```text
   游戏根目录/游戏名/Binaries/Win64/
   ```
   但不要只凭目录猜测；确认其中的 `*-Win64-Shipping.exe` 或游戏社区指定的实际 EXE。
3. 下载与 Mod/游戏要求匹配的标准包 `UE4SS_vX.X.X.zip`，把**包内要求的全部文件**解压到真实游戏 EXE 所在目录。
4. 不要根据“3.x”“新版”“平铺版”等版本号猜目录。打开当前解压结果，找到以下实际文件的位置：
   - `UE4SS.dll`
   - `UE4SS-settings.ini`
   - `Mods/` 与其中的 `mods.txt`
   - 代理 DLL（常见为 `dwmapi.dll`，但实际名称以发布包和游戏要求为准）

**后续所有 Lua/C++ Mod 都应放到这个实际 `Mods/` 目录下；`mods.txt` 也必须修改同一目录中的文件。** UE4SS 官方基础安装的核心要求是：让 UE4SS DLL 被目标游戏加载，并让配置与 `Mods` 目录处于 UE4SS 能找到的位置。

> 不要把 `ue4ss/` 子目录是否存在当作版本特征；某些发布包、管理器或集中安装方案的工作目录会不同。最可靠的是当前下载包、Mod 作者说明和实际生成的 `UE4SS.log`。

### 3.4 UE4SS Mod 的常见形态与位置

| Mod 类型 | 常见特征 | 安装原则 |
|----------|----------|----------|
| **Lua 脚本 Mod** | Mod 文件夹内常有 `scripts/main.lua` | 将整个 Mod 文件夹放进当前 UE4SS 的实际 `Mods/` 目录，并按要求在 `mods.txt` 启用。 |
| **C++ Mod** | Mod 文件夹内常有 `dlls/main.dll` | 保留作者提供的目录结构，放进当前 UE4SS 的实际 `Mods/` 目录，并按要求在 `mods.txt` 启用。 |
| **蓝图 / 资源 Mod** | `.pak` 或带配套文件的资源包 | 不存在统一目录；仅按该 Mod/该游戏明确指定的 `LogicMods`、`~mods`、官方目录或专用加载器规则安装。 |

**Lua/C++ Mod 示例**（以作者提供 `FastHatch/` 为例）：

```text
<当前 UE4SS 工作目录>/Mods/
└── FastHatch/
    └── scripts/main.lua
```

然后打开同一 `Mods/` 目录里的 `mods.txt`，按作者要求加入或确认：

```text
FastHatch : 1
```

### 3.5 `mods.txt`：开关与加载顺序

`Mods/mods.txt` 控制 Lua/C++ Mod 的启用状态和加载顺序。典型格式：

```text
; 格式：文件夹名 : 1(启用) 或 0(禁用)，分号开头是注释
FastHatch : 1
SomeCheat : 0
BPModLoaderMod : 1     ← 仅当所用蓝图 Mod/游戏说明要求时保持启用
Keybinds : 1           ← 内置按键系统，保持在最后
```

| 规则 | 说明 |
|------|------|
| Mod 名称 | 写法应与 `Mods/` 下实际文件夹名一致；不要依赖跨系统的大小写行为。 |
| 加载顺序 | 有依赖关系时按 Mod 作者说明排序。 |
| `Keybinds` | 若当前发布包包含该内置 Mod，按 UE4SS 文档建议保持在末尾。 |

### 3.6 首次启动验证

1. 正常启动游戏。
2. **基础安装不一定显示额外控制台或 GUI 窗口**；不要以“有没有弹窗”作为唯一成功条件。
3. 查找与 `UE4SS.dll` 同目录或当前工作目录中的 `UE4SS.log`，确认时间戳更新且没有明显错误。
4. 可按当前版本的默认热键验证，或在 `UE4SS-settings.ini` 中按需开启 GUI；再按 Mod 说明测试功能。

> 若使用蓝图 Mod，是否需要 `BPModLoaderMod`、`LogicMods` 或其他加载步骤，以该 Mod 的安装说明为准。

## 四、管理与配置

### 4.1 `UE4SS-settings.ini`：按现象排错，不要先改默认值

设置文件位于**当前 UE4SS 工作目录**，不要预设为 `ue4ss/UE4SS-settings.ini`。修改前先备份，并只改与当前问题相关的项：

| 设置项 | 何时才考虑修改 | 注意 |
|--------|----------------|------|
| `GraphicsAPI = dx11` | 当前 UE4SS 版本的 GUI 窗口出现全白/花屏等问题时 | 这是特定版本已知问题的排错尝试，不是所有游戏的默认最优设置。 |
| `bUseUObjectArrayCache = false` | 当前版本在游戏启动阶段崩溃且社区/日志建议此项时 | 先备份原配置；游戏与 UE4SS 版本不同，效果也可能不同。 |
| `GuiConsoleEnabled` / `ConsoleEnabled` | 需要显示或隐藏调试界面时 | 基础安装不依赖 GUI 才能正常工作。 |
| `EnableHotReloadSystem` | Mod 作者或当前版本说明明确支持热重载时 | 热重载不等于所有 Mod 都能安全无重启刷新。 |

### 4.2 卸载

| 需求 | 操作 |
|------|------|
| 禁用某个 UE4SS Mod | `mods.txt` 里改成 `: 0`（文件保留） |
| 彻底删除某个 Mod | 删 `Mods/` 里的对应文件夹 + `mods.txt` 里对应行 |
| 卸载 pak / 蓝图资源 Mod | 按该 Mod 的实际安装说明删除对应文件及其配套文件，不要默认只删某个固定目录。 |
| 完全卸载 UE4SS | 依据当前安装包实际文件清单删除 UE4SS DLL、代理 DLL、设置/日志与工作目录；先备份自己的 Mod 和配置。 |

### 4.3 备份与迁移自己的 Mod 配置

建议只备份**自己拥有游戏中的 Mod 文件、Mod 配置、存档和日志**：

| 内容 | 建议 |
|------|------|
| UE4SS 框架与 Mod | 记录当前 UE4SS 版本，备份实际工作目录中的 `Mods/`、`mods.txt` 和设置文件。 |
| 资源 Mod | 备份作者提供的完整 Mod 文件组及来源链接；不要只保留单个 `.pak`。 |
| 存档 | 按具体游戏的官方/社区说明备份，常见位置不等于所有游戏一致。 |
| 日志 | 保存出现问题时的 `UE4SS.log`，便于重装后排错。 |

> 不要打包、传播或指导绕过平台验证的游戏本体。平台游戏的移动、修复、授权与更新应通过对应客户端完成；本教程只讨论玩家自己拥有的 Mod、配置和存档备份。

## 五、常见问题排查

### Q1：启动报错缺少 VCRUNTIME140.dll / MSVCP140.dll

缺 Visual C++ 运行库。微软官网下载安装 **Visual C++ Redistributable 2015-2022 x64**，装完重启。

### Q2：游戏完全没反应，`UE4SS.log` 都没生成

1. 确认 UE4SS 文件位于**真实游戏 EXE**所在目录，而不是启动器或最外层目录。
2. 对照当前下载包与游戏社区说明，确认代理 DLL 名称；它不一定永远是 `dwmapi.dll`。
3. 检查杀毒软件/Windows 防护是否隔离了新 DLL；只在确认下载来源可信后再处理白名单。
4. 核对 UE4SS、游戏版本、Custom Game Config 和 Mod 要求；先移除第三方 Mod，仅验证加载器本身。

### Q3：启动就崩溃，弹虚幻引擎报错窗口

先还原/备份所有 Mod，只保留 UE4SS 基础安装并查看 `UE4SS.log`。如果当前 UE4SS 版本或该游戏社区明确建议，可尝试将 `bUseUObjectArrayCache = false`；这不是所有游戏都必须使用的默认设置。

### Q4：UE4SS 控制台 GUI 全白/花屏

确认你确实启用了 GUI，再按当前 UE4SS 版本的发布说明尝试 `GraphicsAPI = dx11`。基础安装不依赖 GUI；GUI 不可用时仍可通过日志和 Mod 功能验证加载状态。

### Q5：Mod 装了没效果

- Lua/C++ Mod：确认它位于当前实际 `Mods/` 目录，且 `mods.txt` 中名称与文件夹名一致并已启用。
- 蓝图/资源 Mod：不要默认认定 `LogicMods` 或 `~mods`；按 Mod 作者提供的目录、加载器和配套文件要求复核。
- 检查 Mod 是否支持当前游戏、UE4SS 与其他前置 Mod 的版本。
- 打开 `UE4SS.log` 搜 `Error`、Mod 名称和加载顺序信息。

### Q6：联机游戏能装吗？

**不要把注入、脚本或资源 Mod 用于带反作弊、公共服务器、竞技或未明确允许的联机环境。** 即使游戏有单人模式，也应先核对游戏条款、官方规则和 Mod 社区兼容说明；不确定时不要安装。

### Q7：游戏更新后 Mod 失效/崩溃

游戏更新可能改变资源、签名、内部对象或加载方式：
1. 先通过移走/禁用 Mod 的方式确认原版是否可运行。
2. 查看游戏与 Mod 作者的更新说明，等待明确适配。
3. 恢复时从加载器、前置 Mod 到功能 Mod 逐个加回；不要假设任何 Mod 目录不会受更新影响。

## 六、流程总结

```
① 先确认游戏可能使用 UE，并找到该游戏/该 Mod 的官方或社区安装说明
       ↓
② 按 Mod 页面判断实际路线：官方平台 / 资源包 / UE4SS / 游戏专用加载器
       ↓
③ 资源包路线：完整保留作者提供的文件组，放到作者明确指定的目录
③ UE4SS 路线：把当前发布包放到真实游戏 EXE 目录，找到实际 Mods/ 与 mods.txt
       ↓
   Lua/C++ Mod 保留目录结构放入实际 Mods/
   蓝图/资源 Mod 只按作者说明使用 LogicMods、~mods 或其他目录
       ↓
   按要求在 mods.txt 启用，查看 UE4SS.log 验证
       ↓
④ 出问题：先移走 Mod 验证原版，再查看日志、版本要求与游戏专用配置
```

> 核心口诀：**游戏和 Mod 页面说明优先；先确认加载器与目录，再添加 Mod；日志优先于猜路径。**
