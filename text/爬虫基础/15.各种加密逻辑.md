# 各种加密逻辑

在我们进行js逆向的时候. 总会遇见一些我们人类无法直接能理解的东西出现. 此时你看到的大多数是被加密过的密文. 

## MD5

**MD5是一个非常常见的摘要(hash)算法,其特点就是小巧. 速 度快. 极难被破解. 所以, 所以md5会被拿来计算签名**。**MD5 标准十六进制结果的字符范围仅包含** **`0-9`** **和** **`a-f`（小写），固定 32 位长度。**

### md5的python实现流程

```python
from hashlib import md5
s = 'alex'
salt = "我是盐.把我加进去就没人能破解了"

obj = md5(salt.encode("utf-8"))  # 创建加密器对象，可以加盐也可以不加，加盐之后就很难撞库了
obj.update(s.encode("utf-8"))  # 传入明文开始加密

bs = obj.hexdigest()   # 字符串
print(bs)
```

### 扩展; sha256

```python
from hashlib import sha1, sha256
sha = sha256(b'salt')
sha.update(b'alex')
print(sha.hexdigest())
```

不论是**sha1, sha256, md5**都属于摘要算法. 都是在计算hash值. 只是散列的程度不同而已. 这种算法有一个特性. 他们是散列. 不是加密. 而且, 由于**hash算法是不可逆的, 所以不存在解密的逻辑.**

### js实现md5

```js
var crypto = require("crypto"); //nodejs自带的库，不需要安装

function my_md5(s){
    return crypto.createHash("md5").update(s).digest("hex");
}
```

## Base64

通常被加密后的内容是字节. 而我们的密文是用来传输的(不传输谁加密啊) 。还有在传输图片，音频等二进制数据，可能会因为包含不可打印字符（如控制字符）导致传输错误或被截断。

但是, 在http协议里想要传输字节是很麻烦的一个事儿. 相对应的. 如果传递的是字符串就好控制的多. 此时base64就应运而生了。

26个大写字母+26个小写字母+10个数字+2个特殊符号(+和/)组成了一组类似64进制的计算逻辑. 这就是base64了。

**base64是一种字符串的格式。**

### python实现Base64

流程:

1. 与md5一样，要先转化为字节
2. 再进行加密
3. 加密后得到的是字节
4. 对得到的字节进行decode()得到加密字符串

```python
import base64

bs = "我要吃饭".encode("utf-8")
bm = base64.b64encode(bs)  # 只计算一次Base64字节串
s = bm.decode()  # 直接复用bm，转成字符串

print(s)  # 结果还是 "5oiR6KaB5ZCD6aWt"

# 解码部分不变
s = "5oiR6KaB5ZCD6aWt"
print(base64.b64decode(s).decode("utf-8"))  # 我要吃饭
```

### Base64的长度问题

**注意, b64处理后的字符串长度. 一定是4的倍数. 如果在网页上看到有些密文的b64长度不是4的倍数. 会报错**。

例如, 

```python
import base64

s = "ztKwrsTj0b0"
bb = base64.b64decode(s)
print(bb)

此时运行出现以下问题
Traceback (most recent call last):
  File "D:/PycharmProjects/rrrr.py", line 33, in <module>
    bb = base64.b64decode(s)
  File "D:\Python38\lib\base64.py", line 87, in b64decode
    return binascii.a2b_base64(s)
binascii.Error: Incorrect padding

```

**解决思路. base64长度要求. 字符串长度必须是4的倍数. 填充一下即可**

```python
import base64

s = "ztKwrsTj0b0"
s += ("=" * (4 - len(s) % 4))  # 使用 = 填充
bb = base64.b64decode(s).decode("gbk")
print(bb)
```

### **Base64注意事项**

由于标准的Base64编码后可能出现字符+和/，但是这两个字符在URL中就不能当做参数传递，所以就出现了Base64URL。



下面是它们的区别：

```markdown
1.Base64编码后出现的+和/在Base64URL会分别替换为-和_

2.Base64编码中末尾出现的=符号用于补位，这个字符和queryString中的key=value键值对会发生冲突，所以在Base64URL中=符号会被省略，去掉=后怎么解码呢？因为Base64是把3个字节变为4个字节，所以，Base64编码的长度永远是4的倍数，因此，需要加上=把Base64字符串的长度变为4的倍数，就可以正常解码了。
```

我们的应对方案:

```markdown
在处理base64的时候.如果遇到了没有+和/的情况. 可以采用下面的方案来替换掉+和/。
b64 = base64.b64decode(mi, b"-_")
```



## URLEncode

***作用是把url中的中文，&，=，替换成 %xx 的形式，因为用户可能会在参数中填入&，=，会与原本的&，=产生歧义。***

***但是是只把用户填入的中文，&，=进行替换，url原本的&，=是不变的。***

在我们访问一个url的时候总能看到这样的一种url

```url
https://www.sogou.com/web?query=%E5%90%83%E9%A5%AD%E7%9D%A1%E8%A7%89%E6%89%93%E8%B1%86%E8%B1%86&_asf=www.sogou.com&_ast=&w=01019900&p=40040100&ie=utf8&from=index-nologin&s_from=index&sut=3119&sst0=1630994614300&lkt=0%2C0%2C0&sugsuv=1606978591882752&sugtime=1630994614300
```

此时会发现, 在浏览器上明明是能看到中文的. 但是一旦复制出来. 或者在抓包工具里看到的. 都是这种%. 那么这个%是什么鬼? 也是加密么?

非也, 其实**我们在访问一个url的时候. 浏览器会自动的进行urlencode操作**. 会对我们请求的url进行编码. 这种编码规则被称为百分号编码. 是专门为url(统一资源定位符)准备的一套编码规则.

一个url的完整组成: 

```python
scheme://host:port/dir/file?p1=v1&p2=v2#anchor

http  ://www.baidu.com/tieba/index.html?name=alex&age=18
    参数: key=value
    服务器可以通过key拿value

```

此时. 如果参数中出现一些特殊符号. **比如'=' 我想给服务器传递a=b=c这样的参数. 必然会让整个URL产生歧义.** 

所以, **把url中的参数部分转化成字节. 每字节的再转化成2个16进制的数字. 前面补%.** 

### python实现URLEncode

**普通字符串**

```python


# 单独编码字符串
wq = "米饭怎么吃"
print(quote(wq))  # %E7%B1%B3%E9%A5%AD%E6%80%8E%E4%B9%88%E5%90%83  # 得到的是字符串不是字节
print(quote(wq, encoding="gbk")) # %C3%D7%B7%B9%D4%F5%C3%B4%B3%D4    encoding默认是utf-8

```

**字典**

```python
from urllib.parse import urlencode, unquote, quote
# 多个数据统一进行编码
dic = {
    "wq": "米饭怎么吃",
    "new_wq": "想怎么吃就怎么吃"
}

print(urlencode(dic))  # wq=%E7%B1%B3%E9%A5%AD%E6%80%8E%E4%B9%88%E5%90%83&new_wq=%E6%83%B3%E6%80%8E%E4%B9%88%E5%90%83%E5%B0%B1%E6%80%8E%E4%B9%88%E5%90%83
print(urlencode(dic, encoding="utf-8"))  # 也可以指定字符集

```

**一个完整的url编码过程**

```python
base_url = "http://www.baidu.com/s?"
params = {
    "wd": "大王"
}

url = base_url + urlencode(params)
print(url)  # http://www.baidu.com/s?wd=%E5%A4%A7%E7%8E%8B
```

**解码**

```python
s = "http://www.baidu.com/s?wd=%E5%A4%A7%E7%8E%8B"
print(unquote(s))  # http://www.baidu.com/s?wd=大王
```

## 非对称加密

非对称加密. 加密和解密的秘钥不是同一个秘钥.

这里需要两把钥匙. 一个公钥, 一个私钥.  公钥发送给客户端. 

常见的非对称加密算法: RSA, DSA等等, 我们就介绍一个. RSA加密, 也是最常见的一种加密方案

RSA加密每次都是不一样的

### 4.1 python实现RSA加密解密

#### 4.1.1 创建公钥和私钥

```python
from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_v1_5
from Crypto import Random
import base64

# 随机
gen_random = Random.new


# 生成秘钥
rsakey = RSA.generate(1024)  # 1024  2048 3042  推荐2048
with open("rsa.public.pem", mode="wb") as f:
    f.write(rsakey.publickey().exportKey())

with open("rsa.private.pem", mode="wb") as f:
    f.write(rsakey.exportKey())
```

#### 4.1.2 加密

```python
# 加密
data = "我要吃饭了"
with open("rsa.public.pem", mode="r") as f:
    pk = f.read()
    rsa_pk = RSA.importKey(pk)
    rsa = PKCS1_v1_5.new(rsa_pk)

    result = rsa.encrypt(data.encode("utf-8"))
    # 处理成b64方便传输
    b64_result = base64.b64encode(result).decode("utf-8")
    print(b64_result)
```



#### 4.1.3 解密
