## 二、基础知识

### 1. 类变量与实例变量

- **核心概念**：类变量定义在类体内、方法外，属于"类"，所有实例共享；实例变量在 `__init__` 里用 `self.xxx = ...` 绑定，属于"单个实例"，互不影响。
- **关键原理**：
  - Python 的类和对象本质都是"字典"（命名空间）。类变量在 `类.__dict__`，实例变量在 `实例.__dict__`。
  - **属性查找顺序**：实例 `__dict__` → 类 `__dict__` → 父类 `__dict__`（依次向上）。实例变量可以"遮蔽"同名类变量。
  - 通过 `实例.属性 = 值` 只能创建/修改实例变量，改不到类变量；只有 `类.属性 = 值` 才能改类变量。
  - `getattr / setattr / delattr` 用于"属性名是运行时动态字符串"的场景，比写死的 `对象.属性` 灵活。
- **【易错点】**：
  - 给实例赋同名属性只是"遮蔽"类变量，并不会修改类变量本身。
  - 修改类变量后，所有实例看到的该变量都会同步变化（因为它们共享）。
  - 忘了属性是否存在时用 `getattr(obj, 'name', 默认值)` 避免抛 `AttributeError`。

```python
class Student:
    cou = 1          # 类变量：所有实例共享
    def __init__(self):
        self.a = 1   # 实例变量：只属于该对象

s = Student()
print(s.cou)         # 1（实例.__dict__ 没有 cou → 找到类变量）
print(Student.__dict__)   # 类的命名空间（含 cou、方法）
print(s.__dict__)         # 实例的命名空间（只有 a）
s.age = 18           # 给实例动态加属性
Student.age = 18     # 给类动态加类变量（s 也能访问到）
```

### 2. 私有属性与私有方法

- **核心概念**：Python 没有真正的"私有"，靠**命名约定 + 名称改写（name mangling）**模拟：`_xxx` 是"约定私有"（君子协定），`__xxx` 触发名称改写成为"伪私有"。
- **关键原理**：类体内部的 `self.__age` 在**编译期**被改写成 `self._ClassName__age`。因此外部写 `obj.__age` 会报 `AttributeError`，但 `obj._Student__age` 依然能访问——"防君子不防小人"。
- **【易错点】**：
  - 单下划线 `_` 只是约定，外部随便访问、不报错。
  - 名称改写只对**类体内部**生效，类外面写的 `__xxx` 不会被改写。
  - 不要定义以双下划线开头**且以双下划线结尾**的名字（如 `__init__`），那是魔法方法。
  - 名称改写同时作用于子类（子类 `__x` 改写为 `_子类名__x`），天然避免父子类内部属性冲突。

```python
class Student:
    def __init__(self, name, age):
        self._name = name    # 约定私有，外部可访问 st1._name
        self.__age = age     # 实际存为 self._Student__age

s = Student('张三', 18)
print(s._name)               # 张三（单下划线不拦截）
# print(s.__age)             # AttributeError！
print(s._Student__age)       # 18（改写后的名字可访问）
print(s.__dict__)            # {'_name': '张三', '_Student__age': 18}
```

### 3. 类方法与静态方法

- **核心概念**：实例方法第一个参数是 `self`；`@classmethod` 的第一个参数是 `cls`（类本身），能访问/修改类变量；`@staticmethod` 是放在类里的普通函数，不自动传 `self` 或 `cls`。
- **关键原理**：
  - 类方法通过 `类名.方法()` 或 `实例.方法()` 调用时，Python 自动把**当前类**传给 `cls`。
  - 类方法里创建实例要用 `cls(...)` 而不是写死类名，继承时才能正确创建子类实例。
  - 类方法常用作"备选构造函数"（如 `Date.from_string('2024-01-05')`）；静态方法用作与类/实例无关的工具函数。
- **【易错点】**：
  - 类方法里没有实例对象，不能访问 `self.xxx` 实例变量。
  - 静态方法若误加 `self` 参数，调用时会因缺参报错。
  - 在类方法里改类变量，会影响所有实例共享的值。

```python
class Cat:
    count = 0
    def __init__(self, name):
        self.name = name
        Cat.count += 1

    @classmethod
    def get_count(cls):          # cls 就是 Cat
        return cls.count

    @staticmethod
    def is_valid(n):             # 无 self/cls，纯工具函数
        return n > 0

a = Cat('小白'); b = Cat('小黑')
print(Cat.get_count())           # 2
print(Cat.is_valid(5))           # True
```

### 4. 常用的特殊方法（魔法方法）

- **核心概念**：魔法方法是名字以双下划线开头和结尾的方法，**不能手动调用**，由解释器在特定时机自动触发，从而让对象拥有与内置类型一致的语法行为。
- **关键原理**：
  - `print(obj)` 优先调用 `__str__`，没定义则 fallback 到 `__repr__`；交互式环境/`repr(obj)` 用 `__repr__`。
  - **`__eq__` 与 `__hash__` 联动（最大坑）**：定义了 `__eq__` 而未定义 `__hash__`，Python 会把 `__hash__` 置为 `None`，对象**不可哈希**，放进 set / 作 dict 的键会报 `TypeError`。可哈希约束：`a == b` 时 `hash(a) == hash(b)`。
  - `__bool__` 在 `bool(obj)`、`if obj`、`while obj`、`obj and x`、`obj or x`、`not obj` 处都会调用；没定义则退而用 `__len__`（为 0 则 False）。
  - `__del__` 在垃圾回收前调用，时机不确定，别放重要逻辑。
  - `__len__` 必须返回非负整数；`__add__` 让对象支持 `+`。
- **【易错点】**：`__str__` 必须返回字符串；`__bool__` 必须返回布尔值；只定义 `__eq__` 忘记 `__hash__` 是最经典的坑。

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):          # == 比较
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)

    def __hash__(self):               # 必须同时定义，否则不可哈希
        return hash((self.x, self.y))

    def __bool__(self):               # 真值判断
        return self.x != 0 or self.y != 0

p1, p2 = Point(1, 2), Point(1, 2)
print(p1 == p2)          # True
print(hash(p1))          # 可哈希
print(bool(Point(0, 0))) # False
```

### 5. @property 装饰器（属性访问控制）

- **核心概念**：`@property` 把方法变成属性来访问；配合 `@xxx.setter` 把赋值也变成方法调用，在"读/写"中间插入校验逻辑，对外保持普通属性的简洁写法。
- **关键原理**：`obj.age = 10` → 自动调用 setter 做校验 → 校验通过后把数据存到**内部隐藏变量** `self.__age`；`obj.age` → 自动调用 getter 返回 `self.__age`。校验失败用 `raise ValueError('...')`。
- **【易错点】（无限递归，重点！）**：
  - setter 里写 `self.age = age` 会**再次触发 setter → 无限递归 → RecursionError**，必须存到 `self.__age`。
  - getter 里写 `return self.age` 同样会触发 getter 无限递归，必须 `return self.__age`。
  - 只写 `@property` 不写 `@xxx.setter` → 只读属性。
  - 抛异常不能写 `raise '字符串'`（非法语法），要 `raise ValueError('...')`。

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age          # 会触发 setter 校验

    @property
    def age(self):
        return self.__age       # 绝不能 return self.age

    @age.setter
    def age(self, age):
        if not (0 <= age <= 100):
            raise ValueError('age不合规范')
        self.__age = age        # 绝不能 self.age = age

s = Student('小明', 18)
print(s.age)      # 18
# s.age = 200     # ValueError
```

### 6. 只读 property（最佳实践）

- **核心概念**：只写 `@property`、不写 `@xxx.setter` 的属性是**只读**的，赋值会抛 `AttributeError: can't set attribute`。典型用途是把"由内部数据计算得出的结果"暴露为属性，并做**懒加载 + 缓存**。
- **关键原理**：内部用一个缓存变量（如 `self.__area`）保存计算结果，首次访问 `s.area` 才真正计算；一旦源数据（`width`）改变，setter 里把缓存**清空为 None**，下次访问重新计算。
- **【易错点】**：
  - setter/getter 内写自身同名属性会无限递归（同第 5 节），必须用 `self.__xxx`。
  - 修改源数据后**忘记清空缓存**，读到的会是旧值。
  - 缓存存在实例上（`self.__area`），不同实例各自独立。

```python
class Square:
    def __init__(self, width):
        self.width = width
        self.__area = None          # 缓存：None 表示未计算

    @property
    def width(self):
        return self.__width

    @width.setter
    def width(self, width):
        if width < 0:
            raise ValueError('width不能小于0')
        self.__width = width
        self.__area = None          # 源数据变了，清空缓存

    @property
    def area(self):                 # 只读：没有 setter
        if self.__area is None:
            self.__area = self.__width * self.__width
        return self.__area

s = Square(10)
print(s.area)       # 100（首次计算并缓存）
s.width = 20        # 缓存被清空
print(s.area)       # 400（重新计算）
# s.area = 999      # AttributeError
```

### 7. 删除 property（@xxx.deleter）

- **核心概念**：property 除了 getter、setter，还有 deleter（`@xxx.deleter`），用来定义 `del obj.属性` 时执行的逻辑。
- **关键原理**：`del sq.area` → 调用 deleter → 把缓存的 `self.__area` 删掉 → 下次访问时 getter 发现缓存不存在，**重新计算并重新缓存**。
- **【易错点】**：
  - deleter 方法名必须与 property 同名，用 `@area.deleter` 绑定。
  - deleter 删的是"缓存属性"，不是删整个 property；要删整个 property 得 `delattr(类, 'area')`。
  - 缓存可能被 deleter 删除（属性不存在），getter 读取时要用 `try/except` 或 `getattr` 兜底，否则直接写 `self.__area is None` 会抛 `AttributeError`。

```python
class Square:
    def __init__(self, width):
        self.__width = width
        self.__area = None

    @property
    def area(self):
        try:
            cached = self.__area      # 可能已被 del 删除
        except AttributeError:
            cached = None
        if cached is None:
            self.__area = self.__width * self.__width
            cached = self.__area
        return cached

    @area.deleter
    def area(self):
        del self.__area               # 只删缓存，不是删整个属性

sq = Square(4)
print(sq.area)      # 16
del sq.area         # 触发 deleter，删缓存
print(sq.area)      # 16（缓存没了，重新计算）
```

### 8. 继承

- **核心概念**：子类继承父类的属性和方法，表达"is-a"关系（Student 是一种 Person），是 OOP 三大特性（封装、继承、多态）之一。
- **关键原理**：
  - 语法 `class Student(Person):`；属性/方法查找沿继承链向上直到 `object`。
  - `super()` 不是简单地调"父类"，而是按 **MRO** 找"当前类的下一个类"；单继承下即父类。子类重写 `__init__` 后父类 `__init__` **不会自动调用**，必须 `super().__init__(...)`。
  - 方法重写（Override）是"多态"的基础：同一个方法名对不同对象表现不同行为。
  - `isinstance(obj, 类)` 判断"是某类或其子类的实例"；`type(obj) == 类` 判断"精确类型"。
- **【易错点】**：
  - 子类重写了 `__init__` 却忘记调 `super().__init__()`，父类属性未定义。
  - 重写方法后仍需要父类逻辑时，用 `super().方法()` 先调父类版本。

```python
class Person:
    def __init__(self, name, age):
        self.name, self.age = name, age
    def say(self):
        print('Person')

class Student(Person):
    def __init__(self, name, age):
        super().__init__(name, age)      # 必须显式初始化父类属性
    def say(self):                        # 方法重写（多态）
        print('Student')

st = Student('ff', 12)
print(isinstance(st, Person))   # True
print(type(st) == Person)       # False（精确类型不匹配）
st.say()                        # Student
```

### 9. 抽象类

- **核心概念**：抽象类是不能被实例化的类，用于定义一组子类必须实现的"规范/契约"；抽象方法只声明不实现（`pass` 占位）。
- **关键原理**：`from abc import ABC, abstractmethod`，`class Action(ABC)` 即成抽象类，`@abstractmethod` 装饰的方法即抽象方法。抽象类本身不能实例化；**子类必须实现全部抽象方法**，否则子类也无法实例化。
- **鸭子类型**：调用方法不强制要求对象是某类的实例，只要它有同名方法就能被调用（`def say(action: Action)` 的类型标注只是提示，运行时不做强制检查）。
- **【易错点】**：漏实现任意一个抽象方法，子类实例化时抛 `TypeError: Can't instantiate abstract class ...`。

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass          # 只声明，不实现

class Circle(Shape):              # 实现了全部抽象方法，可实例化
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14 * self.r ** 2

c = Circle(2)
print(c.area())       # 12.56
# Shape()  # TypeError：抽象类不能实例化
```

### 10. 枚举（Enum）

- **核心概念**：枚举是一组"命名常量"的集合，每个成员由 `name`（名字）和 `value`（值）两部分组成，把固定取值集中定义、避免"魔法数字"。
- **关键原理**：
  - `class Gender(Enum):` 创建枚举类；成员是类的属性，每个成员都是枚举类的实例。
  - 枚举类不能直接实例化；成员值不可变；不能动态添加属性。
  - **反向查找**：按名字 `Gender['MALE']`，按值 `Gender(1)`。
  - 枚举类可迭代，`for` 可遍历出所有成员。
- **【易错点】**：同一值只允许一个名字，值相同的后定义成员会成为"别名"（见下一节）；成员是单例对象，比较用 `is` 或 `==` 一致。

```python
from enum import Enum

class Gender(Enum):
    MALE = 1
    FEMALE = 2

print(Gender.MALE.name)          # MALE
print(Gender.MALE.value)         # 1
print(Gender['MALE'])            # Gender.MALE（按名字反向查找）
print(Gender(1))                 # Gender.MALE（按值反向查找）
for g in Gender:
    print(g.name, g.value)       # 遍历所有成员
```

### 11. 枚举别名与 @enum.unique

- **核心概念**：枚举中若两个成员值相同，后定义的会成为先定义成员的**别名（alias）**，与主成员指向同一个对象；`@enum.unique` 装饰器强制值必须唯一。
- **关键原理**：
  - 遍历时**只显示主成员**，别名不单独出现；`Status.__members__`（有序字典）包含包括别名在内的所有名字。
  - 别名与主成员 `is` 和 `==` 都为 True。
  - `@enum.unique` 在**类定义阶段**发现重复值即抛 `ValueError: duplicate values found ...`，把错误提前暴露。
- **【易错点】**：拼写错误（如把 SUCCESS 写成 SUCESS）会造成难以察觉的别名；需要拿全部名字要用 `__members__`。

```python
import enum
from enum import Enum

class Status(Enum):
    OK = 1
    SUCESS = 1          # 别名：值与 OK 相同，指向同一对象
    FAIL = 2

print(Status.__members__)         # 包含别名 SUCESS
for i in Status:                  # 只遍历出 OK、FAIL
    print(i.name)
print(Status.OK is Status.SUCESS) # True（别名是同一对象）

@enum.unique
class Gender(Enum):               # 值必须唯一
    MALE = 1
    FEMALE = 2
```

### 12. 定制和扩展枚举

- **核心概念**：枚举成员本质是类的实例，可在枚举类内定义 `__str__`、`__eq__`、`__lt__` 等魔法方法，定制打印格式、比较逻辑、排序规则。
- **关键原理**：`__str__` 定制 `print(成员)` 显示；`__eq__` 定制 `==`（可与整数比 value、与字符串比 name、与成员比身份）；`__lt__` 定制 `<` 用于排序。**`@total_ordering`** 只需实现 `__eq__` + 一个基础比较方法（如 `__lt__`），自动补齐 `__le__`/`__ne__`/`__gt__`/`__ge__`。
- **【易错点】**：
  - 与字符串比较应写 `self.name == other`，**不能写 `self.name == str`**（`str` 是类型对象，恒为 False）。
  - 比较对象要传"成员实例"，如 `Status.MEAL < Status.FEMALE`，而不是把类本身 `Status` 当比较对象。

```python
from enum import Enum
from functools import total_ordering

@total_ordering
class Status(Enum):
    MEAL = 1
    FEMALE = 2

    def __str__(self):
        return f'{self.name}({self.value})'

    def __eq__(self, other):
        if isinstance(other, int):  return self.value == other
        if isinstance(other, str):  return self.name == other   # 不是 str
        if isinstance(other, Status): return self is other
        return False

    def __lt__(self, other):
        if isinstance(other, (int, Status)): return self.value < other.value if isinstance(other, Status) else self.value < other
        return False

print(Status.MEAL == 1)           # True
print(Status.MEAL == 'MEAL')      # True
print(Status.MEAL < Status.FEMALE)# True
print(Status.MEAL)                # MEAL(1)
```

### 13. 多继承（不建议使用）

- **核心概念**：一个子类可以同时继承多个父类，复用多个父类的属性和方法，但逻辑复杂、易出问题，**日常不建议使用**。
- **关键原理**：
  - **MRO（方法解析顺序）** 用 C3 线性化算法：子类优先、多个父类按"从左到右"、每个父类只出现一次。可用 `类.__mro__` / `类.mro()` 查看。
  - `super()` 按 MRO 找"当前类的下一个类"；`父类名.方法(self)` 是显式指定、不走 MRO。
  - **钻石继承问题**：D 继承 B、C，而 B、C 都继承 A 时，MRO 为 `D -> B -> C -> A -> object`，C3 保证 A 只被处理一次。
- **【易错点】**：多个父类有同名方法时调用结果依赖 MRO，容易困惑；super() 协作不当会导致方法重复调用。推荐替代方案：**单继承 + 组合**或 Mixin。

```python
class A:
    def greet(self):
        print('A.greet')

class B(A):
    def greet(self):
        print('B.greet'); super().greet()

class C(A):
    def greet(self):
        print('C.greet'); super().greet()

class D(B, C):
    def greet(self):
        print('D.greet'); super().greet()

d = D()
d.greet()                  # D → B → C → A（A 只被调用一次）
print(D.__mro__)           # (D, B, C, A, object)
```

### 14. 描述符（Descriptor）

- **核心概念**：描述符是一种可复用的"属性访问控制"机制，通过实现 `__get__`/`__set__`/`__delete__`/`__set_name__` 协议方法，拦截对属性的读取/设置/删除，执行自定义逻辑（校验、转换、缓存等）。
- **关键原理**：
  - 协议方法：`__get__(self, instance, owner)`（instance 是访问实例，类访问时为 None）、`__set__(self, instance, value)`、`__delete__(self, instance)`、`__set_name__(self, owner, name)`（Python 3.6+，赋值给类属性时自动调用）。
  - property 本质上就是基于描述符实现的便捷工具；描述符更适合"多个类复用同一套属性逻辑"。
  - **数据描述符**（同时实现 `__get__` 和 `__set__`）优先级**高于**实例 `__dict__` 中的同名属性；非数据描述符（只实现 `__get__`）优先级低于实例属性。
- **【易错点】**：描述符对象被所有实例共享，存值必须存到 `instance.__dict__`，不能存到描述符的 `self` 上；抛异常要用 `raise TypeError(...)`/`raise ValueError(...)`，不能 `raise 字符串`；触发 `__set_name__` 需要把描述符赋值给**类属性**。

```python
class RequiredString:
    def __set_name__(self, owner, name):
        self.prop = name                     # 记录属性名
    def __set__(self, instance, value):
        if not isinstance(value, str):
            raise TypeError('不是字符串')
        instance.__dict__[self.prop] = value.strip()   # 存到实例上
    def __get__(self, instance, owner):
        return instance.__dict__.get(self.prop)

class Student:
    name = RequiredString()                  # 赋给类属性，触发 __set_name__

s = Student()
s.name = '  dad  '
print(s.name)   # dad（自动去空白）
```

### 15. __new__ 方法

- **核心概念**：`__new__` 是真正"创建对象"的方法，`__init__` 只是"初始化对象"的方法。一句话：**`__new__` 负责"造出来"，`__init__` 负责"装进去"**。
- **关键原理**：
  - 调用 `类名(参数)` 时：先执行 `__new__(cls, 参数)` 创建并返回实例；**只有当 `__new__` 返回的是当前类的实例时**，Python 才自动调用 `__init__` 初始化。
  - `__new__` 是静态方法（第一个参数是 `cls`），必须返回实例，否则对象创建失败且 `__init__` 不执行。
  - 典型用途：继承不可变类型（int/str/tuple）时定制创建过程（如求平方）、实现**单例模式**、对象池/缓存复用。
- **【易错点】**：`__new__` 第一个参数写 `cls` 而非 `self`；不 `return` 会导致 `__init__` 不被调用；调用父类用 `super().__new__(cls, ...)`，不可变类型还要传构造参数。

```python
class Singleton:
    _instance = None
    def __new__(cls):
        if cls._instance is None:            # 只创建一次
            cls._instance = super().__new__(cls)
        return cls._instance                 # 之后总是返回同一个

s1, s2 = Singleton(), Singleton()
print(s1 is s2)   # True（单例）

class SquareNumber(int):                     # 继承不可变类型
    def __new__(cls, value):
        return super().__new__(cls, value ** 2)
print(SquareNumber(10))   # 100
```

### 16. 异常类

- **核心概念**：异常是程序运行时的错误信号，用 `try/except` 捕获避免程序崩溃；自定义异常类继承内置异常来表达业务含义。
- **关键原理**：
  - **异常体系**：`BaseException` 是根（一般不要直接继承），多数异常继承 `Exception`，自定义异常通常继承 `Exception`。
  - `try`（可能出错的代码）/ `except 类型 as e`（捕获，`as e` 取异常对象）/ `else`（无异常才执行）/ `finally`（无论是否异常都执行，用于释放资源）。
  - `raise 异常类型('信息')` 主动抛出；自定义异常里要 `super().__init__(*args, **kwargs)` 展开传参。
- **【易错点】**：
  - except 要**先写具体异常、再写宽泛异常**（自上而下匹配，先写 `except Exception` 后面的 `ZeroDivisionError` 永远不执行）。
  - 自定义异常构造时误写 `super().__init__(args)`（整个元组当一个参数），应 `super().__init__(*args)`。

```python
class MyError(Exception):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)    # 展开传参

def divide(x, y):
    if y == 0:
        raise MyError('除数不能为 0')        # 主动抛出
    return x / y

try:
    result = divide(10, 0)
except MyError as e:                          # 具体异常在前
    print(f'捕获到：{e}')
except Exception as e:                        # 宽泛异常在后
    print(f'其他异常：{e}')
else:
    print(f'结果：{result}')
finally:
    print('finally 一定执行')                 # 用于关闭资源
```

## 三、高级知识

### 1. 装饰器（Decorator）

- **核心概念**：装饰器本质是"接收函数、返回新函数"的可调用对象（高阶函数），在不改动原函数的前提下给函数附加额外功能（日志、计时、校验、缓存等）。
- **关键原理**：
  - `@welcome('tom')` 等价于 `sad = welcome('tom')(sad)`。
  - **带参数装饰器要包三层**：第 1 层接收装饰器参数、第 2 层接收被装饰函数、第 3 层 `wrapper(*args, **kwargs)` 真正包装。外层参数通过**闭包**传给内层。
  - `@wraps(fn)` 把原函数的 `__name__`、`__doc__` 复制到 wrapper，避免调试时函数名变成 `wrapper`。
  - **叠放多个装饰器**：从下往上装饰、从上往下执行（`@d1 @d2 def f` 等价 `f = d1(d2(f))`）。
- **【易错点】**：装饰器在 **import/定义阶段**就执行，不是调用时才执行；忘 `return wrapper` 或忘返回调用结果 `result`，函数会丢返回值；写带参装饰器容易少包一层。

```python
from functools import wraps

def timer(fn):                        # 两层：不带参装饰器
    @wraps(fn)
    def wrapper(*args, **kwargs):
        import time
        start = time.perf_counter()
        result = fn(*args, **kwargs)  # 调用原函数
        print(f'{fn.__name__} 耗时 {time.perf_counter() - start:.4f}s')
        return result                 # 必须返回结果
    return wrapper

@timer
def add(a, b):
    return a + b

print(add(3, 5))    # 8（并打印耗时）
```

### 2. 生成器（Generator）

- **核心概念**：函数体内出现 `yield`，函数就变成生成器函数。调用它**不会立即执行**，而是返回生成器对象；生成器是迭代器，可交给 `for`/`next()` 使用。
- **关键原理**（惰性求值/暂停-恢复）：
  - 第一次 `next(g)` 执行到第一个 `yield`，产出值并**暂停**；下次 `next(g)` 从暂停处**继续**执行到下一个 `yield`。
  - 执行完（或 `return`）后抛 `StopIteration`，`for` 循环捕获后自动结束。
  - **省内存**：每次只产生一个值，适合大文件逐行读、无限序列（斐波那契）、流水线处理。
  - **生成器表达式**：`(i*2 for i in range(5))` 是圆括号的惰性版本，对比列表推导式省内存。
- **【易错点】**：调用生成器函数不执行任何代码，必须迭代才执行；生成器**只能用一次**（耗尽后要重新调用函数创建）；`return` 的值不会作为迭代值输出。

```python
def fibonacci():              # 无限斐波那契
    a, b = 0, 1
    while True:
        yield a               # 每次暂停返回 a
        a, b = b, a + b

fib = fibonacci()
print([next(fib) for _ in range(8)])   # [0, 1, 1, 2, 3, 5, 8, 13]

gen = (i * 2 for i in range(5))        # 生成器表达式（省内存）
print(list(gen))                       # [0, 2, 4, 6, 8]
```

### 3. 上下文管理器（Context Manager）

- **核心概念**：上下文管理器用于"进入/退出"代码块时自动做资源管理，典型就是 `with` 语句（如 `with open(...) as f`，文件自动关闭）。
- **关键原理**：
  - `with 表达式 as 变量:` 流程：① 调用 `__enter__()`，返回值赋给 `as` 后的变量；② 执行代码块；③ 无论正常结束还是抛异常，**都会**调用 `__exit__(exc_type, exc_val, exc_tb)`。
  - `__exit__` 三个参数：正常退出时都是 `None`；发生异常时携带异常信息。
  - `__exit__` 返回 `True` 表示**吞掉异常**（调用方无感知）；返回 `False`/`None` 则异常继续抛出。
  - `@contextlib.contextmanager` 装饰生成器函数：`yield` 之前相当于 `__enter__`，之后相当于 `__exit__`（即使抛异常也执行）。
- **【易错点】**：`__enter__` 必须返回值，否则 `as` 拿到 `None`；`__exit__` 记得返回 `True/False` 决定是否吞异常；多个 with 可连写 `with A() as a, B() as b:`。

```python
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self              # 返回值赋给 as 后的变量
    def __exit__(self, exc_type, exc_val, exc_tb):
        self.elapsed = time.perf_counter() - self.start

with Timer() as t:
    time.sleep(0.2)
print(f'耗时 {t.elapsed:.3f}s')   # 自动记录耗时
```

### 4. type 类动态创建类

- **核心概念**：在 Python 中，"类"本身也是对象，它的类型是 `type`。`class People: ...` 底层等价于 `People = type('People', (object,), {命名空间字典})`。type 的三参形式可动态创建类：`type(类名, 父类元组, 类体字典)`。
- **关键原理**：
  - 三个参数：`name` 类名（字符串）、`bases` 父类元组、`dict` 命名空间（方法/属性的名字→对象）。
  - 配合 `exec(代码字符串, globals(), class_dict)` 把字符串形式的类体代码执行进命名空间字典，实现"从字符串/配置动态生成类"（ORM、工厂模式、插件系统的基础）。
  - `type` 三参形式与 metaclass 是"同一件事的两种写法"：一个手动建类、一个让元类建类。
- **【易错点】**：单父类元组**别漏逗号**——`(People)` 是类本身，`(People,)` 才是元组；exec 里用到全局名字需要 `globals()`。

```python
def __init__(self, x, y):
    self.x, self.y = x, y

def dist(self, other):
    return ((self.x - other.x) ** 2 + (self.y - other.y) ** 2) ** 0.5

Point = type('Point', (object,), {'__init__': __init__, 'dist': dist})
p1, p2 = Point(0, 0), Point(3, 4)
print(p1.dist(p2))      # 5.0
print(Point.__bases__)  # (<class 'object'>,)
```

### 5. metaclass 元类

- **核心概念**：元类是"创建类的类"。普通对象由类创建，**类本身由元类创建**。内置 `type` 是最基础的元类：`type(Student)` 是 `<class 'type'>`。
- **关键原理**：
  - `class Student(metaclass=Human): ...` 时，Python 实际执行：收集类体命名空间 → 调用元类的 `__new__(meta, name, bases, namespace)` 创建类对象 → 调用元类的 `__init__` 初始化类对象。
  - 元类必须继承自 `type`；重写 `__new__` 可在类"生出来"时统一加工（加属性、注册类、校验等）。
  - 元类也会被继承：子类的元类由最近的父类元类决定。
  - 使用场景：类创建时统一加属性、自动注册子类（插件系统）、ORM/API 框架的底层基石。
- **【易错点】**：元类 `__new__` 的第一个参数是**元类自身**；`super().__new__(cls, *args)` 中 `cls` 是要创建的**新类**；99% 的场景不需要自己写元类。

```python
class Human(type):                      # 元类必须继承 type
    @staticmethod
    def __new__(cls, *args, **kwargs):
        class_ = super().__new__(cls, *args)   # 创建类对象
        class_.freedom = True                  # 统一加属性
        for k, v in kwargs.items():            # class 语句的额外关键字参数
            setattr(class_, k, v)
        return class_

class Student(object, metaclass=Human, country='china'):
    pass

print(Student.freedom, Student.country)  # True china
print(type(Student))                     # <class '__main__.Human'>
```

### 6. metaclass 实战实例（自动生成 property）

- **核心概念**：用元类 + 描述符，在**类创建时**自动为声明在 `props` 列表里的每个属性生成 property，省去手写大量 getter/setter。
- **关键原理**：
  - 元类 `__new__` 里先 `super().__new__` 创建类，再读取类属性 `props`（如 `['name', 'age']`），遍历每个名字：用描述符封装读写底层 `_name` 的逻辑，用 `property(fget=..., fset=...)` 生成 property，`setattr` 挂回类上。
  - 之后 `stu.name` 自动读写内部 `_name`，读写逻辑集中在描述符里。
  - 换一个类只需声明 `props`，即"约定优于配置"；这是元类最有价值的实战用法。
- **【易错点】**：元类里要先创建类再 `setattr` 加工；描述符内部存值用带下划线的 `_attr`，避免与 property 同名冲突（无限递归）。

```python
class Prop:
    def __init__(self, attr):
        self._attr = f'_{attr}'
    def get(self, obj):
        return getattr(obj, self._attr, None)
    def set(self, obj, value):
        setattr(obj, self._attr, value)

class Human(type):
    @staticmethod
    def __new__(cls, *args, **kwargs):
        class_ = super().__new__(cls, *args)
        for name in class_.props:                    # 遍历声明列表
            p = Prop(name)
            setattr(class_, name, property(fget=p.get, fset=p.set))
        return class_

class Student(object, metaclass=Human):
    props = ['name', 'age']                          # 只需声明即可

s = Student()
s.name = 'lisi'          # 自动写入内部 _name
print(s.name)            # lisi（自动生成 property 生效）
```

### 7. nonlocal 与作用域

- **核心概念**：`nonlocal` 用于在**内层函数中修改外层函数的局部变量**；`global` 用于修改**模块顶层**的全局变量。
- **关键原理**：**LEGB 查找规则**：Local（当前函数）→ Enclosing（外层函数）→ Global（模块顶层）→ Built-in（内置）。普通只读会自动逐层向外找；但**修改外层函数变量必须 `nonlocal` 声明**。
- **【易错点】**：
  - 不加 `nonlocal` 就在内层函数给外层变量赋值，Python 会认为在创建"局部变量"，要么只影响局部、要么报 `UnboundLocalError`。
  - `nonlocal` 只能指向外层函数的变量，找不到报 `SyntaxError: no binding ...`；不能用于模块级。
  - `nonlocal`/`global` 都要在**赋值语句之前**声明。

```python
def make_counter():
    count = 0                 # 外层变量（Enclosing 层）
    def add(step=1):
        nonlocal count        # 声明修改外层函数的 count
        count += step
        return count
    return add

c = make_counter()
print(c())    # 1
print(c(5))   # 6（状态被保存并累加）
```

### 8. 变量作用域与 UnboundLocalError

- **核心概念**：Python 是"先编译、后执行"的语言。编译函数时，只要发现某个名字在函数体**任意位置**被赋值（包括 if/for 分支里），就把它标记为**该函数的局部变量**——这与运行时那一行是否执行**无关**。
- **关键原理**：所以 `if flag: count = 20` 后 `print(count)`，当 `flag=False` 时 `count` 这个"局部变量"从未初始化 → `UnboundLocalError: local variable 'count' referenced before assignment`。
- **修复方式**：① 函数内加 `global count`（修改全局）；② 先把全局值读进"确定已初始化"的局部变量再在分支中覆盖。
- **局部变量遮蔽全局**：函数内对同名名字赋值且无 `global` 声明，函数内访问到的是局部那份，全局不受影响。
- **【易错点】**：只读全局变量不需要 `global`（LEGB 自动找到）；一出现赋值就可能触发局部变量判定，导致 UnboundLocalError。

```python
count = 10

def task(flag):
    local = count            # 先读全局值，确定已初始化
    if flag:
        local = 20           # 覆盖局部
    print(local)             # flag=False 也不报错

task(False)    # 10
task(True)     # 20
```

### 9. 正则表达式

- **核心概念**：正则表达式是一种描述"字符串匹配模式"的语言，用模式串在文本中搜索、匹配、替换符合规则的内容，Python 通过 `re` 模块支持。
- **常用 API**：
  - `re.search`：在整个字符串中搜第一个匹配（不要求开头）；`re.match`：只从开头匹配；`re.fullmatch`：整个字符串完全匹配；`re.findall`：找出所有匹配返回列表；`re.finditer`：返回惰性迭代器（省内存）；`re.compile`：编译成 Pattern 对象反复用（性能好）。
  - **分组提取**：`m.group(0)` 整个匹配，`group(1)`/`group(2)` 各分组，`groups()` 返回全部分组元组。
  - **flags**：`re.I` 忽略大小写、`re.M` 让 `^ $` 匹配每行、`re.S` 让 `.` 匹配换行、`re.X` 允许注释。
- **常用元字符**：`\d` 数字、`\w` 字母数字下划线、`\s` 空白、`.` 任意字符（除换行）、`*` 0+ 次、`+` 1+ 次、`?` 0/1 次、`{n}`/`{n,}`/`{n,m}` 次数、`[]` 字符集、`()` 分组、`|` 或、`^` 开头、`$` 结尾。
- **【易错点】**：`\d{*}` 是**非法写法**（`{}` 里必须写数字），会报 `re.error`；`match` 与 `search` 的区别（是否要求开头）常被混淆。

```python
import re

text = '今天是 2026-08-19'
m = re.search(r'(\d{4})-(\d{2})-(\d{2})', text)   # 3 个分组
print(m.group(0))   # 2026-08-19
print(m.group(1))   # 2026
print(m.groups())   # ('2026', '08', '19')

# findall + 分组提取
info = '张三 138-1234-5678'
print(re.findall(r'(\d{3}-\d{4}-\d{4})', info))   # ['138-1234-5678']
# flags 忽略大小写
print(re.findall(r'hello', 'Hello HELLO', re.I))  # ['Hello', 'HELLO']
```

### 10. 闭包（Closure）

- **核心概念**：闭包 = 内层函数 + 它引用的外层函数变量（"自由变量"）。外层函数返回内层函数，且内层函数用到外层局部变量，就形成闭包。
- **关键原理**：外层函数执行完，普通局部变量本该销毁，但被内层函数引用的变量会被打包进内层函数的 `__closure__`（cell 元组）保存下来，因此**外层返回后内层仍能访问并保持状态**（"记忆能力"）。
- **用途**：延迟计算、计数器/有状态函数（配合 `nonlocal`）、**装饰器的底层原理**、数据隐藏。
- **【易错点】（闭包陷阱）**：在**循环中**创建闭包时，内层函数引用循环变量，多个闭包**共享同一个变量**（循环结束后变量停留在最后一个值），所有闭包读到同一最终值。解决办法：用默认参数绑定当前值 `lambda i=i: i`。

```python
# 闭包陷阱
funcs_wrong = [lambda: i for i in range(3)]
print([f() for f in funcs_wrong])          # [2, 2, 2]（共享同一个 i）

# 修复：默认参数把当前值复制一份
funcs_right = [lambda i=i: i for i in range(3)]
print([f() for f in funcs_right])          # [0, 1, 2]

# 查看闭包保存的变量
def make():
    x = 42
    return lambda: x
f = make()
print(f.__closure__[0].cell_contents)      # 42
```

## 四、并发编程

### 1. 线程基础（threading.Thread）

- **核心概念**：进程是操作系统中正在运行的任务，有独立内存、数据默认隔离；线程是进程内的一条执行流，同一进程的线程**共享内存**，可直接读写同一份全局数据（线程安全问题的根源）。
- **关键原理**：
  - `.py` 文件运行时入口默认是主线程（MainThread）；`Thread(target=fn, args=(...,))` 创建子线程，`start()` 启动，`join()` 阻塞等待子线程结束。
  - **I/O 密集**（网络/文件/等待）：多线程利用等待空档提升吞吐，效果显著。
  - **CPU 密集**（纯计算）：受 **GIL（全局解释器锁）** 限制，同一时刻只有一条线程执行 Python 字节码，多线程几乎无法提速，应改用多进程。
- **【易错点】**：参数必须用 `args=` 传**元组**，单参数要写 `args=(100,)`（逗号不能丢）；线程执行顺序由操作系统调度，不确定，别假设"先 start 先执行完"；线程 start 后不能再次 start。

```python
from threading import Thread
import time

def io_task(name):
    time.sleep(0.5)          # 模拟 I/O 等待
    print(f'{name} 完成')

ts = [Thread(target=io_task, args=(f'并发{i}',)) for i in range(4)]
for t in ts: t.start()       # 同时启动 4 个线程
for t in ts: t.join()        # 等待全部完成（总耗时约 0.5s 而非 2s）
print('Main thread end')
```

### 2. 线程进阶（继承 Thread、daemon、join）

- **核心概念**：创建线程的第二种方式是**继承 `threading.Thread` 并重写 `run()`**，`start()` 后会自动调用 `run()`。线程分**守护线程（daemon）**和**非守护线程**。
- **关键原理**：
  - `self.name` 是 Thread 内建属性（线程名），子类里覆盖它会丢失线程身份信息；更规范用 `super().__init__(name='自定义名')`，业务标识放独立属性。
  - **守护线程**：主线程结束后被强制终止（无论是否执行完），适合日志、心跳等非关键任务；**非守护线程**：主线程结束不会杀它，程序会等所有非守护线程执行完才退出。
  - `join()`：谁调用谁阻塞等待"被 join 的线程"结束。
- **【易错点】**：`run()` 不要手动调用；`run()` 没有返回值（要拿结果用 `queue.Queue` 或线程池）；守护线程里避免操作共享资源（可能随时被"掐断"）；漏掉 `join()` 会导致输出不完整。

```python
from threading import Thread
import time

class MyThread(Thread):
    def __init__(self, label, count):
        super().__init__(name=f'线程-{label}')   # 线程名交给父类
        self.count = count
        self.daemon = True                        # 守护线程
    def run(self):                                # start 后自动调用
        for n in range(self.count):
            print(f'{self.name}-{n}')
            time.sleep(0.01)

t = MyThread('A', 5)
t.start()
t.join()    # 等待结束，保证输出完整
print('主线程结束')
```

### 3. 线程安全队列（生产者-消费者）

- **核心概念**：**生产者-消费者模式**中，生产者把数据放进队列，消费者从队列取数据处理，两者通过队列解耦。标准库 `queue.Queue` 内部自动加锁，**线程安全**，可放心多线程共享。
- **关键原理**：
  - `put(item)`：队列满且 `block=True`（默认）时阻塞等待空位；`get()`：队列空时阻塞等待数据。
  - `Queue(maxsize=N)` 限流/背压，防止生产者无限生产撑爆内存；`maxsize <= 0` 表示无限。
  - 消费者通常 `while True get` 死循环等消息，要设 `daemon=True`，否则程序永远无法退出。
  - 更规范的退出方式：生产完放入**哨兵值**（如 `None`）通知消费者结束，而不是依赖守护线程强杀。
- **【易错点】**：普通 list/dict 多线程并发读写有竞争条件，需要自己加锁（见下一节）；`get(timeout=N)` 超时会抛 `queue.Empty`；有 N 个消费者就要放 N 个哨兵值。

```python
from queue import Queue
from threading import Thread

q = Queue(3)                       # 容量 3 的线程安全队列

def producer():
    for i in range(5):
        q.put(f'data-{i}')
    q.put(None)                    # 哨兵：通知消费者结束

def consumer(name):
    while True:
        item = q.get()
        if item is None:           # 收到结束信号
            print(f'{name} 退出')
            break
        print(f'{name} 处理 {item}')

tp = Thread(target=producer); tp.start()
tc = Thread(target=consumer, args=('C1',)); tc.start()
tp.join(); tc.join()
```

### 4. 线程锁（Lock 与 Condition）

- **核心概念**：多个线程同时读写同一份数据会产生**竞争条件（Race Condition）**和数据不一致；锁（Lock）保证同一时刻只有一个线程执行被保护代码段（互斥访问）。
- **关键原理**：
  - **Lock 两种写法**：手动 `lock.acquire() ... lock.release()`（必须成对，忘 release 会死锁）；推荐 `with lock:`（退出自动释放，即使抛异常）。
  - **死锁**：多个线程互相持有对方需要的锁、互不相让。避免：尽量用 with、锁粒度小/持锁时间短、多把锁保持一致的加锁顺序、用 `acquire(timeout=...)` 限时。
  - **Condition（条件变量）**：`wait()` 释放锁并阻塞、被唤醒后自动重新获取锁；`notify()` 唤醒一个等待线程；`notify_all()` 唤醒所有。典型用于有界队列的生产者-消费者。
- **【易错点】**：`wait()` 必须在持锁状态下调用（`with cond:` 内），否则 `RuntimeError`；条件判断要用 `while` 而不是 `if`（防止**虚假唤醒**，唤醒后要重新检查条件）；普通 Lock **不可重入**（同一线程重复 acquire 会死锁，可重入用 `RLock`）。

```python
from threading import Thread, Lock

count = 0
lock = Lock()

def add(n):
    global count
    for _ in range(n):
        with lock:        # 进入自动上锁，退出自动解锁
            count += 1    # 读-改-写被保护，避免数据丢失

ts = [Thread(target=add, args=(100000,)) for _ in range(5)]
for t in ts: t.start()
for t in ts: t.join()
print(count)              # 500000（加锁后结果正确）
```

### 5. 线程池（ThreadPoolExecutor）

- **核心概念**：线程创建/销毁开销大，线程池预创建一批线程复用，避免反复创建销毁。可理解为"线程一直循环等任务"。
- **关键原理**：
  - `submit(fn, *args)` 提交单个任务，返回 **Future** 对象；`future.result()` 阻塞等待任务完成并返回结果。
  - `map(fn, iterable)` 用同一函数批量处理多个元素，返回按传入顺序产出结果的迭代器。
  - `max_workers=N` 指定池中线程数（默认 `min(32, cpu+4)`，适合 I/O 密集）。
  - **with 语句**：退出时自动 `shutdown(wait=True)`——不再接收新任务并等待所有已提交任务完成。
  - `as_completed(futures)`：按"完成先后"而非提交顺序取结果。
- **【易错点】**：`result()` 不传超时可能无限阻塞（可传 `result(timeout=N)`）；任务内异常延迟到 `result()` 时才抛出。

```python
from concurrent.futures import ThreadPoolExecutor
import time

def task(name):
    time.sleep(1)
    return f'{name} 完成'

with ThreadPoolExecutor(max_workers=3) as pool:
    f1 = pool.submit(task, 'a')        # submit：单个任务 → Future
    f2 = pool.submit(task, 'b')
    print(f1.result())                 # result() 阻塞取结果
    for r in pool.map(task, ['c', 'd']):   # map：批量
        print(r)
```

### 6. 多进程（multiprocessing.Process）

- **核心概念**：由于 GIL，多线程对 CPU 密集任务几乎无法提速；**多进程**每个进程有独立解释器和 GIL，可真正利用多核并行计算，适合 CPU 密集任务。
- **关键原理**：
  - `Process(target=fn, args=(...,))` 创建进程，`start()`/`join()` 用法类似线程；多个进程先全部 start 再统一 join 实现并行。
  - **进程内存独立**：子进程是主进程的"副本"，各自修改全局变量互不影响；跨进程共享数据要用 `Queue`/`Pipe`/`Value`/`Array` 等专门工具。
  - **必须写在 `if __name__ == '__main__':` 里**：Windows 用 spawn 方式创建子进程，子进程会"重新导入"当前脚本，若创建进程代码在模块顶层会无限递归创建进程。
- **【易错点】**：进程启动昂贵，数量别开太多（多时用进程池）；子进程打印顺序不可控。

```python
from multiprocessing import Process
import time

def cpu_task(n):
    total = 0
    for i in range(n):
        total += i * i
    return total

if __name__ == '__main__':            # 跨平台必须保护
    ps = [Process(target=cpu_task, args=(10_000_000,)) for _ in range(4)]
    for p in ps: p.start()            # 先全部启动（真正并行）
    for p in ps: p.join()             # 再统一等待
    print('4 个进程并行完成（利用多核，绕过 GIL）')
```

### 7. 进程池（ProcessPoolExecutor）

- **核心概念**：启动进程比启动线程昂贵得多，进程池预创建一批进程复用，控制进程数量、避免耗尽系统资源。用法与线程池几乎一致，只是底层用"进程"。
- **关键原理**：
  - `submit`/`map`/`result` 用法与 `ThreadPoolExecutor` 相同；`with` 退出时等待所有任务完成。
  - **多进程 vs 多线程选择**：CPU 密集 → 多进程（绕过 GIL 真正并行）；I/O 密集 → 多线程（开销小、切换快）；资源紧张用多线程更稳妥。
  - 进程池代码同样必须放在 `if __name__ == '__main__':` 内（Windows spawn 避免无限递归）。
- **【易错点】**：传给进程池的函数（含参数）**必须能被 pickle 序列化**——不能是 lambda、闭包或嵌套函数，必须定义在模块顶层；任务异常要等 `result()` 才暴露；`max_workers` 默认按 CPU 核心数，别盲目开太多。

```python
from concurrent.futures import ProcessPoolExecutor

def heavy(x):                      # 必须定义在模块顶层（可序列化）
    return sum(i * i for i in range(x))

if __name__ == '__main__':
    with ProcessPoolExecutor(max_workers=4) as pool:
        futures = [pool.submit(heavy, 2_000_000) for _ in range(6)]
        for f in futures:
            print(f.result())
```

## 五、异步 IO

### 1. 协程（Coroutine）

- **核心概念**：协程是可被"挂起"和"恢复"的函数，用 `async def` 定义。调用协程函数**不会立即执行**，而是返回协程对象，必须由**事件循环**驱动执行。`await` 等待可等待对象，执行到 `await` 时挂起并让出控制权。
- **关键原理**：
  - **事件循环**是异步编程的核心调度器：单线程内不断挑选"可继续执行"的协程运行，遇到 `await` 就切走，实现"单线程内的并发"。
  - `asyncio.run(main())`：创建事件循环 → 运行 main 协程 → 关闭事件循环。
  - 适合"耗时等待"密集操作（网络 IO、数据库、文件读写），不适合 CPU 密集计算。
  - **对比**：生成器用 yield、`next()` 手动驱动；协程用 async/await、事件循环自动调度；线程由操作系统调度、切换开销大，协程切换开销极小。
- **【易错点】**：
  - 协程对象**不会自动执行**，必须 await / `asyncio.run` / `create_task` 驱动，否则 `RuntimeWarning: coroutine was never awaited`。
  - 只有在 `await` 处才让出控制权；协程里一段无 await 的密集计算会阻塞整个事件循环。
  - 一个协程对象只能被 await 一次。
  - **异步代码里禁用 `time.sleep()`**（阻塞整个事件循环），要用 `asyncio.sleep()`。

```python
import asyncio

async def task(name, sec):
    print(f'{name} 开始')
    await asyncio.sleep(sec)      # 挂起，让出控制权给事件循环
    print(f'{name} 结束')

async def main():
    t1 = asyncio.create_task(task('A', 2))   # 并发启动
    t2 = asyncio.create_task(task('B', 3))
    await t1
    await t2

asyncio.run(main())    # 总耗时约 3 秒（取最长者），而非 5 秒
```

### 2. 创建任务（asyncio.create_task）

- **核心概念**：`asyncio.create_task(coro)` 把协程包装成 **Task** 并立即交给事件循环调度，实现真正的并发。
- **关键原理**：
  - **`await coro` 是串行**：await 完一个才轮到下一个，总耗时 = 各任务耗时之和。
  - **`create_task` 是并发**：多个任务在事件循环内协作式切换，总耗时 ≈ 最长的那个任务。
  - `asyncio.sleep(n)` 模拟耗时等待（网络请求/数据库查询），必须 `await` 挂起，否则不让出控制权。
  - `time.perf_counter()` 返回高精度单调计时器（纳秒级），比 `time.time()` 更适合测耗时。
- **【易错点】**：create_task 创建的任务必须 await（或加入 gather），否则程序可能提前退出；任务在创建后的下一个循环点才开始执行（不是立即同步执行）；不要在协程里用 `time.sleep()` 模拟等待。

```python
import asyncio, time

async def work(name, sec):
    await asyncio.sleep(sec)
    return name

async def main():
    t0 = time.perf_counter()
    t1 = asyncio.create_task(work('A', 2))   # 两个任务并发启动
    t2 = asyncio.create_task(work('B', 3))
    await t1
    await t2
    print(f'并发总耗时: {time.perf_counter() - t0:.2f} 秒')  # 约 3 秒

asyncio.run(main())
```

### 3. 任务进阶（取消、超时、并发等待）

- **核心概念**：对异步任务进行**取消、超时控制、并发批量等待**的常用工具。
- **关键原理**：
  - `task.cancel()`：发出取消请求，任务内部会抛 `asyncio.CancelledError`；`task.done()` 判断任务是否结束。
  - `asyncio.wait_for(aw, timeout)`：设置超时，超时后**默认取消任务**并抛 `TimeoutError`。
  - `asyncio.shield(aw)`：给任务"套护盾"，`wait_for` 超时想取消时会被挡下，任务继续后台运行（适合不想被超时中断的后台任务，如写文件、上报数据）。
  - `asyncio.gather(*aws, return_exceptions=False)`：并发等待多个任务，返回按传入顺序的结果列表；`return_exceptions=True` 时某个任务异常不会打断整体，而是把异常对象作为对应位置的结果返回。
- **【易错点】**：
  - 取消本质是注入 `CancelledError`；若捕获后**不重新抛出**，取消会失效。
  - 对被取消的任务调用 `result()` 会抛 `CancelledError`。
  - `wait_for` 超时默认取消任务；不想取消就配合 `shield`。
  - 用了 `shield` 后仍需 `await` 原任务，确保后台任务真正结束。
  - `gather` 用 `return_exceptions=True` 时，正常任务返回结果、出错任务返回异常对象，要自己区分。

```python
import asyncio

async def work(name, sec):
    await asyncio.sleep(sec)
    return name

async def main():
    t = asyncio.create_task(work('A', 3))
    try:
        await asyncio.wait_for(t, 2)          # 2 秒超时 → 自动取消任务
    except TimeoutError:
        print('超时，任务已被取消')
    # await asyncio.shield(t) 可保护任务不被取消，继续后台运行
    # gather：并发等待多个任务
    r = await asyncio.gather(work('B', 1), work('C', 1), return_exceptions=True)
    print(r)                                   # ['B', 'C']

asyncio.run(main())
```
