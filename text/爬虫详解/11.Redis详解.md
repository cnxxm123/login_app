# Redis 详解

## 一、Redis 是什么？

**Redis** 是一个基于**内存**的键值对（Key-Value）数据库，读写速度极快，常用于缓存、去重、队列、分布式协调等场景。

在爬虫中，Redis 的典型应用：

- **URL 去重**（增量爬虫：记录哪些 URL 抓过了）；
- **分布式调度队列**（scrapy-redis 用 Redis 当请求队列和去重集合）；
- **代理 IP 池**（用有序集合按分数管理 IP 可用性）。

### 启动与客户端

```bash
# 启动 redis-server
redis-server

# 命令行客户端
redis-cli
```

> Redis 默认端口：**6379**。

---

## 二、Redis 常见数据类型

Redis 有 5 种核心数据类型：**String、Hash、List、Set、ZSet（有序集合）**。

---

## 1. String（字符串）

Redis 中一切存取的数据底层都是字符串。

| 命令 | 说明 |
| ---- | ---- |
| `SET key value` | 添加一条数据 |
| `GET key` | 查看一条数据 |
| `INCR key` | 让 key 的值自增 1（**原子性，安全**） |
| `INCRBY key count` | 让 key 的值自增 count |
| `TYPE key` | 查看数据类型（set 进去的一律是字符串） |

```bash
SET name zhangsan      # 添加数据 name = zhangsan
GET name               # zhangsan
SET age 10
GET age                # 10
INCR age               # 11
GET age                # 11
INCRBY age 5           # 16
GET age                # 16
```

> `INCR/INCRBY` 是原子操作，非常适合做计数器（访问量、点赞数）。

---

## 2. Hash（哈希）

Hash 类似字典/对象，一个 key 下可以存多个字段：

```
key => {k1: v1, k2: v2, ...}
```

| 命令 | 说明 |
| ---- | ---- |
| `HSET key k1 v1` | 把 k1, v1 存储在 key 上 |
| `HGET key k1` | 取出 key 上的 k1 |
| `HMSET key k1 v1 k2 v2 k3 v3` | 一次性存多个 k,v |
| `HMGET key k1 k2` | 一次性取多个 |
| `HGETALL key` | 取出 key 中所有内容 |
| `HKEYS key` | 取出所有字段名 |
| `HVALS key` | 取出所有值 |

```bash
HMSET stu id 1 name sylar age 18
HMGET stu name age      # sylar 18
HGETALL stu             # id 1 name sylar age 18
HKEYS stu               # id name age
HVALS stu               # 1 sylar 18
```

> 适合存储一个对象的多个属性，如用户信息 `user:1 => {name, age, email}`。

---

## 3. List（列表）

List 底层是**双向链表**，可以从左右两端插入/删除。

```
key => [数据1, 数据2, 数据3, ...]
```

| 命令 | 说明 |
| ---- | ---- |
| `LPUSH key 数据1 数据2 ...` | 从左边插入 |
| `RPUSH key 数据1 数据2 ...` | 从右边插入 |
| `LRANGE key start stop` | 取 start 到 stop 区间数据 |
| `LLEN key` | 列表长度 |
| `LPOP key` | 从左边弹出一个并返回 |
| `RPOP key` | 从右边弹出一个并返回 |

```bash
LPUSH banji yiban erban sanban siban
LRANGE banji 0 -1     # yiban erban sanban siban
RPUSH ban ban1 ban2 ban3
LRANGE ban 0 -1       # ban1 ban2 ban3
LPOP ban              # ban1
LLEN ban              # 2
```

> List 常用来做**消息队列**：生产者 `LPUSH`，消费者 `RPOP`。`BLPOP`（阻塞版）可实现生产者-消费者模式。

---

## 4. Set（集合）

Set 是**无序、不重复**的集合。最大的作用是**去重**。

```
key => {元素1, 元素2, ...}
```

| 命令 | 说明 |
| ---- | ---- |
| `SADD key 值` | 向集合存入数据（重复存不进） |
| `SMEMBERS key` | 查看集合所有元素 |
| `SCARD key` | 查看元素个数 |
| `SISMEMBER key val` | 判断是否包含 val（1 在 / 0 不在） |
| `SUNION key1 key2` | 并集 |
| `SDIFF key1 key2` | 差集（在 key1 但不在 key2） |
| `SINTER key1 key2` | 交集 |
| `SPOP key` | 随机删除一个 |
| `SRANDMEMBER key count` | 随机查看 count 个 |

```bash
SADD stars 柯震东 吴亦凡 张默 房祖名    # 4
SADD stars 吴亦凡                      # 0（重复存不进去）
SMEMBERS stars                        # 柯震东 吴亦凡 张默 房祖名
SISMEMBER stars 吴亦凡                 # 1
SADD my 周杰伦 吴亦凡 房祖名
SINTER stars my                       # 吴亦凡 房祖名（交集）
SPOP my                               # 随机删除一个
SRANDMEMBER my 2                      # 随机查看 2 个
```

> 爬虫中最经典的用途：**URL 去重**。把抓过的 URL `SADD` 进一个 set，下次用 `SISMEMBER` 判断是否抓过。

---

## 5. ZSet（有序集合）

有序集合同样不可重复，但每个元素还带一个 **score（分数）**，Redis 按 score 排序。

```
key => {(数据, score), (数据, score), ...}
```

| 命令 | 说明 |
| ---- | ---- |
| `ZADD key score1 member1 score2 member2` | 存入（带分数） |
| `ZRANGE key start stop [WITHSCORES]` | 正序查看 |
| `ZREVRANGE key start stop [WITHSCORES]` | 倒序查看 |
| `ZCARD key` | 元素个数 |
| `ZCOUNT key min max` | 分数在 min~max 之间的数量 |
| `ZSCORE key member` | 查看某元素分数 |
| `ZRANK key member` | 判断是否存在（返回排名/空） |
| `ZINCRBY key score member` | 给某元素增加分数 |
| `ZREM key member` | 删除某元素 |

```bash
ZADD fam 1 sylar 2 alex 3 tory     # 添加三个
ZRANGE fam 0 -1 WITHSCORES         # 正序查看（含分数）
ZREVRANGE fam 0 -1 WITHSCORES      # 倒序查看
ZINCRBY fam 10 alex                # 给 alex 加 10 分
ZADD fam 100 alex                  # 把 alex 分数改为 100
ZSCORE fam alex                    # 查看 alex 分数
ZCARD fam                          # 元素个数
```

> ZSet 的经典应用：**排行榜**，以及**代理 IP 池**（用分数表示 IP 的可用性，越高越可靠）。

---

## 三、键的通用操作与过期时间

无论哪种数据类型，以下命令都通用：

| 命令 | 说明 |
| ---- | ---- |
| `EXISTS key` | 判断 key 是否存在（1 存在 / 0 不存在） |
| `DEL key1 key2` | 删除一个或多个 key |
| `TYPE key` | 查看 key 的类型 |
| `KEYS 模式` | 按模式查找 key（如 `KEYS user:*`，**生产慎用**，会阻塞） |
| `EXPIRE key 秒` | 设置过期时间（秒） |
| `TTL key` | 查看剩余过期时间（-1 永不过期，-2 已过期/不存在） |
| `RENAME old new` | 重命名 key |

```bash
SET code abc123
EXPIRE code 60        # 60 秒后自动删除
TTL code              # 剩余秒数（如 58）
EXISTS code           # 1（还在）
DEL code              # 删除
```

> 过期时间非常适合：**验证码、临时 token、登录态**等"临时数据"。缓存数据也常配合过期时间使用（`SET key val EX 60`）。

## 四、持久化与布隆过滤器（了解）

### 1. 持久化：RDB 与 AOF

Redis 默认把数据存在内存中，重启会丢。持久化有两种方式：

| 方式 | 原理 | 特点 |
| ---- | ---- | ---- |
| RDB（快照） | 定期把内存数据**存成文件** | 文件小、恢复快，可能丢最近几分钟数据 |
| AOF（追加） | 把每次写操作**追加记录**到文件 | 数据更安全，文件大、恢复慢 |

> 生产环境常两者结合。爬虫场景里 Redis 主要用于去重/队列，丢失可容忍时可不开启。

### 2. 布隆过滤器（Bloom Filter）

爬虫 URL 去重如果数据量极大（几亿个 URL），用 Set 存会非常占内存。**布隆过滤器**用多个哈希函数 + 位数组，用很小的内存判断"大概率不在"。

```bash
# 需要安装 Redis 布隆过滤器模块（redisbloom）
BF.ADD urls http://a.com      # 加入
BF.EXISTS urls http://a.com   # 1（存在）
BF.EXISTS urls http://b.com   # 0（不存在）
```

> 特点：**可能有误判（把没去过的判成去过），但绝不会漏判**。scrapy-redis 等框架在数据量极大时会用它做去重。初学者了解概念即可。

## 五、Python 操作 Redis

### 安装

```bash
pip install redis
```

### 连接方式一：直接连接

```python
from redis import Redis

red = Redis(
    host="127.0.0.1",   # 地址
    port=6379,          # 端口
    db=0,               # 数据库（0-15）
    password="123456",  # 密码
    decode_responses=True,  # 自动解码为字符串（推荐，否则返回 bytes）
)
```

### 连接方式二：连接池（推荐）

```python
import redis

pool = redis.ConnectionPool(
    host="127.0.0.1",
    port=6379,
    db=0,
    password="123456",
    decode_responses=True,
)

r = redis.Redis(connection_pool=pool)
print(r.keys())
```

### 基本增删查

```python
# 字符串
red.set("sylar", "邱彦涛")
print(red.get("sylar"))            # 邱彦涛

# 列表
lst = ["张三丰", "张无忌", "张翠山", "张娜拉"]
red.lpush("names", *lst)           # 用 * 展开传入
result = red.lrange("names", 0, -1)
print(result)

# 有序集合
red.zadd("proxy", {"192.168.1.1": 10, "192.168.1.2": 10})
red.zadd("proxy", {"192.168.1.3": 10, "192.168.1.4": 10})

# 给某 IP 加到 100 分（xx=True：存在才更新，不存在不操作）
red.zadd("proxy", {"192.168.1.4": 100}, xx=True)

# 给某 IP 扣 10 分
red.zincrby("proxy", -10, "192.168.1.4")

# 分扣没了，删除
red.zrem("proxy", "192.168.1.4")

# 可用代理数量
print(red.zcard("proxy"))

# 按分数区间查询（0~100）
print(red.zrangebyscore("proxy", 0, 100))

# 倒序取前 100（分页）
print(red.zrevrange("proxy", 0, 100))

# 查询某 IP 是否还在（None 表示不存在）
print(red.zscore("proxy", "192.168.1.4"))
```

> 从上面可以看出，**Python 的 redis 方法与 redis-cli 命令几乎一一对应**，会命令就会用 Python。

## 七、Redis 进阶应用（爬虫/工程高频）

### 1. Python 通用方法（key 级别）与 scan_iter

无论什么类型，这些 key 级方法最常用：

```python
r = Redis(password="123456", decode_responses=True)

r.set("temp", "1")
r.expire("temp", 60)        # 设置过期时间（秒）
print(r.ttl("temp"))        # 剩余秒数；-1 永不过期，-2 已过期
print(r.exists("temp"))     # 1 存在 / 0 不存在
print(r.type("temp"))       # 'string'
r.delete("temp")            # 删除一个或多个 key
print(r.keys("*"))          # 列出所有 key
```

> **`keys()` 生产环境千万别用**：会全库扫描，数据量大时直接卡死 Redis。遍历 key 用 `scan_iter`（游标分批取）：

```python
# scan_iter：分批迭代，不阻塞，适合生产
for key in r.scan_iter("user:*", count=100):
    print(key)

# 匹配删除：把匹配到的 key 批量删掉
for key in r.scan_iter("temp:*"):
    r.delete(key)
```

### 2. Pipeline 管道批量操作（性能神器）

爬虫批量写入时，一个个命令往返网络很慢。`pipeline` 把**多个命令攒在一起一次性发送**，能大幅提速：

```python
r = Redis(password="123456", decode_responses=True)

# 普通：n 次命令 = n 次网络往返
for i in range(1000):
    r.set(f"k{i}", i)

# pipeline：所有命令攒起来，最后一次性发送执行
pipe = r.pipeline()          # 或 r.pipeline(transaction=False)
for i in range(1000):
    pipe.set(f"k{i}", i)
pipe.execute()               # 一次性执行，速度快几倍~几十倍
```

> `pipeline` 默认包在事务里（`transaction=True`），中途出错会整体回滚；只想"批量快"不要求原子性可传 `transaction=False`。`redis` 库还提供 `pipeline(transaction=True)` 时的管道+事务特性。

### 3. 分布式锁（SETNX + EXPIRE）

多台机器/多个进程同时操作同一资源时，需要**分布式锁**保证只有一个在执行。Redis 用 `SET key value NX EX 秒` 实现"原子地拿到锁 + 自动过期"：

```python
import time
import uuid
from redis import Redis

r = Redis(password="123456", decode_responses=True)

lock_key = "lock:task1"
token = str(uuid.uuid4())      # 唯一标识，防止误删别人的锁

# NX：key 不存在才设置成功（拿锁）；EX：设置过期时间（防死锁）
ok = r.set(lock_key, token, nx=True, ex=30)
if ok:
    try:
        print("拿到锁，执行任务...")
        time.sleep(5)
    finally:
        # 释放锁：只有 token 是自己才删（避免删掉别人新拿的锁）
        # 简单做法：Lua 脚本判断+删除（原子）
        lua = "if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end"
        r.eval(lua, 1, lock_key, token)
else:
    print("没拿到锁，任务已被其他进程执行")
```

> 两个要点：① `nx=True` 保证"同时只有一个能拿到"；② `ex=30` 保证"进程挂了锁也会自动释放"，避免死锁。这是分布式爬虫调度最常见的写法。

### 4. Redis 事务（MULTI / EXEC / WATCH）

Redis 事务用 `MULTI` 开始、`EXEC` 执行、`DISCARD` 取消；`WATCH` 可做"乐观锁"：

```bash
MULTI                 # 开启事务
SET a 1
INCR a
EXEC                  # 依次执行上面命令
```

```python
# Python 里用 pipeline(transaction=True) 即可开启事务
with r.pipeline() as pipe:
    pipe.set("a", 1)
    pipe.incr("a")
    pipe.execute()     # 批量原子执行
```

> 注意：Redis 事务**不保证回滚**（某个命令报错，其他命令照常执行），只保证"打包执行"。绝大多数爬虫场景用 pipeline 就够，事务用得少。

### 5. 消息队列模式（List + BLPOP 阻塞消费）

List 的 `LPUSH` + `BRPOP` 就是最朴素的队列：生产者放、消费者阻塞取。

```python
import threading
from redis import Redis

r = Redis(password="123456", decode_responses=True)

# 生产者：往队列塞任务
def producer():
    for i in range(10):
        r.lpush("task:queue", f"任务{i}")
        print("生产:", i)

# 消费者：阻塞取出（队列空就一直等，不空转烧 CPU）
def consumer():
    while True:
        # brpop 返回 (key, value)；timeout 为等待秒数
        item = r.brpop("task:queue", timeout=30)
        if item:
            print("消费:", item[1])

threading.Thread(target=producer, daemon=True).start()
consumer()
```

> `BRPOP` 比 `RPOP` 好在：队列空时**挂起等待**而不是返回 None，配合多消费者还能自动负载均衡。scrapy-redis 的分布式调度底层就是这么做的。

### 6. 缓存三大问题（穿透/击穿/雪崩）

用 Redis 做缓存时的经典问题（面试常问，也影响爬虫缓存设计）：

| 问题 | 现象 | 解决思路 |
| ---- | ---- | -------- |
| **缓存穿透** | 查一个**不存在**的 key，每次都打到数据库 | 布隆过滤器拦截；或把"空结果"也缓存（空值缓存，过期短） |
| **缓存击穿** | 一个**热点 key 过期**瞬间，大量请求打到数据库 | 热点数据不过期；或加锁只让一个请求去重建缓存（分布式锁） |
| **缓存雪崩** | **大量 key 同时过期**，请求全部打到数据库 | 过期时间加随机值分散；多级缓存 |

```python
import random
from redis import Redis

r = Redis(password="123456", decode_responses=True)

# 过期时间加随机偏移，避免雪崩
for i in range(1000):
    r.setex(f"page:{i}", 3600 + random.randint(0, 600), data)
```

## 八、实战：用 Redis 做 URL 去重（增量爬虫核心）

```python
from redis import Redis

red = Redis(password="123456", db=6, decode_responses=True)

url = "http://bbs.tianya.cn/post-123.shtml"

# 1. 判断是否抓取过
if red.sismember("tianya:details", url):
    print("该 URL 已经抓取过，跳过")
else:
    # 2. 执行抓取...
    # 3. 抓取完成后把 URL 加入集合，下次就不会重复抓
    red.sadd("tianya:details", url)
    print("开始抓取:", url)
```

## 九、小结

- Redis 5 种类型：**String / Hash / List / Set / ZSet**，各自对应不同场景（缓存、对象、队列、去重、排行榜）；
- 关键特性：**内存存储（快）、数据不重复（Set/ZSet）、命令原子性（INCR）、过期时间（EXPIRE/TTL）**；
- Python 用 `redis` 库，`decode_responses=True` 可让返回值为字符串；遍历 key 用 `scan_iter` 而非 `keys()`；
- 批量操作用 **pipeline**；跨进程/跨机器互斥用**分布式锁**（`SET nx ex` + Lua 释放）；
- 消息队列用 **List + BRPOP**；缓存注意**穿透/击穿/雪崩**三大问题；
- 爬虫中最重要的用途：**URL 去重**（Set/布隆过滤器）、**代理 IP 池**（ZSet 分数管理）、**分布式队列**（List）。
