# 多线程与多进程 详解

## 一、为什么爬虫需要并发？

爬虫的本质是"大量请求 + 大量解析"。如果**串行**执行，一个请求要等它完全返回后才发下一个请求，非常浪费时间。

```python
# 串行示例：发 10 个请求，总耗时 ≈ 10 × 每个请求耗时
import requests

for url in urls:
    requests.get(url)
```

而**并发**（多线程/多进程/异步）可以让多个请求"同时"进行，大幅提升抓取效率。

**三者对比**：

| 方式 | 特点 | 适用场景 |
| ---- | ---- | -------- |
| 多线程 | 线程间共享内存，开销小，受 GIL 限制 | **IO 密集**（爬虫网络请求） |
| 多进程 | 进程间独立，能利用多核 CPU，开销大 | **CPU 密集**（大量计算） |
| 异步协程 | 单线程内切换，开销最小，效率最高 | **IO 密集**（大并发请求） |

> 爬虫是典型的 **IO 密集型**任务（大量时间花在等待网络响应上），所以多线程和异步协程是主流方案。

# 二、多线程

## 1. 直接用 Thread 创建线程

```python
from threading import Thread

def func():
    for i in range(1000):
        print("func", i)

if __name__ == '__main__':
    t = Thread(target=func)   # 指定线程执行的目标函数
    t.start()                 # 启动线程（非阻塞，立即返回）
    for i in range(1000):
        print("main", i)
```

> 主线程和子线程交替打印，说明两个线程在"同时"执行。

## 2. 继承 Thread 类

适合需要在线程中保存状态/多方法的场景：

```python
from threading import Thread

class MyThread(Thread):
    def __init__(self, name):
        super().__init__(name=name)   # 给线程命名，方便排查日志
        self.count = 0                # 可以在子类里存自己的状态

    def run(self):          # 重写 run 方法，线程启动时执行
        for i in range(1000):
            self.count += 1
            print(self.name, i)       # self.name 是线程名

if __name__ == '__main__':
    t = MyThread("抓取线程")
    t.start()               # start() 内部会调用 run()
    for i in range(1000):
        print("main", i)
```

## 3. 线程的常用控制方法与属性

除了 `start()`，`Thread` 对象还提供这些常用方法，用来查询/控制线程状态：

```python
import threading
import time

def worker():
    time.sleep(1)

t = threading.Thread(target=worker, name="worker-1")
print(t.name)            # 线程名，调试日志里能区分是谁
print(t.is_alive())      # False：还没 start
t.start()
print(t.is_alive())      # True：正在运行
t.join(timeout=3)        # 主线程阻塞，等 t 结束（最多等 3 秒）

# 查看当前正在运行的线程
print(threading.current_thread().name)   # MainThread
print(threading.active_count())          # 当前存活的线程数
for th in threading.enumerate():         # 枚举所有存活线程
    print(th.name)
print(threading.main_thread().name)      # 主线程的引用
```

### daemon（守护线程）

主线程结束时，**非守护线程**会被强制等完；**守护线程**则直接被打断：

```python
import threading, time

def worker():
    time.sleep(2)
    print("worker 完成")

t = threading.Thread(target=worker, daemon=True)   # 守护线程
t.start()
print("主线程结束")    # 程序直接退出，worker 的 print 可能不执行
```

> 爬虫里用 `ThreadPoolExecutor` 的 `with` 自动管理等待，一般不需要手动 `join`。

### threading.Timer（定时执行的线程）

```python
import threading

def task():
    print("3 秒后执行我")

t = threading.Timer(3, task)   # 3 秒后自动启动一个线程执行 task
t.start()
print("主线程继续...")
```

## 4. 线程池（推荐）

手动创建线程要管理创建/销毁，线程太多还会拖垮系统。**线程池**是更优雅的方案：复用固定数量的线程执行大量任务。

### 基本使用（submit 提交任务）

```python
from concurrent.futures import ThreadPoolExecutor

def fn(name):
    for i in range(1000):
        print(name, i)

if __name__ == '__main__':
    # 创建 10 个线程的线程池
    with ThreadPoolExecutor(10) as t:
        for i in range(100):
            t.submit(fn, name=f"线程{i}")
    # with 语句退出时自动等待所有任务完成
```

### 任务有返回值怎么办？——Future 对象

`submit` 会返回一个 **Future 对象**，代表"未来的结果"。它是理解线程池的核心：

```python
import time
from concurrent.futures import ThreadPoolExecutor, as_completed

def func(name):
    time.sleep(2)
    if name == "坏数据":
        raise ValueError("解析失败")
    return name

with ThreadPoolExecutor(10) as t:
    futures = [t.submit(func, name) for name in ["线程1", "线程2", "坏数据"]]

    # Future 的常用方法：
    for f in futures:
        print(f.done())      # 是否已完成（不管成功失败）
        print(f.running())   # 是否正在运行
        print(f.cancelled()) # 是否被取消
        # f.cancel()         # 取消未开始的任务，返回 True/False

    # 逐个拿结果（result 会阻塞，直到该任务完成）
    for f in futures:
        try:
            print(f.result(timeout=5))      # 拿到返回值；出错会抛异常
        except Exception as e:
            print("该任务出错:", e)

    # exception() 只拿异常不拿结果
    for f in futures:
        if not f.cancelled() and f.exception():
            print("发现异常:", f.exception())
```

**方案一：add_done_callback 回调**（任务完成时自动调用，不阻塞主线程）

```python
import time
from concurrent.futures import ThreadPoolExecutor

def func(name):
    time.sleep(2)
    return name

def do_callback(future):
    try:
        print("结果:", future.result())
    except Exception as e:
        print("任务出错:", e)

if __name__ == '__main__':
    with ThreadPoolExecutor(10) as t:
        names = ["线程1", "线程2", "线程3"]
        for name in names:
            t.submit(func, name).add_done_callback(do_callback)
```

**方案二：map 统一返回结果**

```python
import time
from concurrent.futures import ThreadPoolExecutor

def func(name):
    time.sleep(2)
    return name

if __name__ == '__main__':
    with ThreadPoolExecutor(10) as t:
        names = [5, 2, 3]
        # map 会把每个元素作为参数调用 func，按传入顺序返回结果
        results = t.map(func, names)
        for r in results:
            print("result", r)
```

> `map` 的代价：结果**按传入顺序**返回，如果第一个任务没完成，后面的结果都拿不到（会被阻塞）。回调方案则无此问题。

**shutdown 的两个参数**：

```python
with ThreadPoolExecutor(10) as t:
    ...
# with 退出等价于 t.shutdown(wait=True)：等所有任务执行完才关闭

t.shutdown(wait=True, cancel_futures=True)   # 等正在执行的；没开始的任务直接取消
```

## 5. 多线程在爬虫中的应用（实战）

抓取 1994-2021 年的电影票房数据，用线程池并发请求：

```python
import requests
from lxml import etree
from concurrent.futures import ThreadPoolExecutor


def get_page_source(url):
    resp = requests.get(url)
    resp.encoding = "utf-8"
    return resp.text


def parse_html(html):
    try:
        tree = etree.HTML(html)
        trs = tree.xpath("//table/tbody/tr")[1:]
        result = []
        for tr in trs:
            year = tr.xpath("./td[2]//text()")
            year = year[0] if year else ""
            name = tr.xpath("./td[3]//text()")
            name = name[0] if name else ""
            money = tr.xpath("./td[4]//text()")
            money = money[0] if money else ""
            d = (year, name, money)
            if any(d):
                result.append(d)
        return result
    except Exception as e:
        print(e)


def download_one(url, f):
    page_source = get_page_source(url)
    data = parse_html(page_source)
    for item in data:
        f.write(",".join(item))
        f.write("\n")


def main():
    f = open("movie.csv", mode="w", encoding="utf-8")
    lst = [str(i) for i in range(1994, 2022)]

    with ThreadPoolExecutor(10) as t:
        # 方案一：submit
        # for year in lst:
        #     url = f"http://www.boxofficecn.com/boxoffice{year}"
        #     t.submit(download_one, url, f)

        # 方案二：map
        t.map(download_one,
              (f"http://www.boxofficecn.com/boxoffice{year}" for year in lst),
              (f for i in range(len(lst))))

    f.close()


if __name__ == '__main__':
    main()
```

> **注意**：多个线程同时往同一个文件 `f` 写入，Python 的写入是原子的（单次 write 不会被打断），此例可行。但如果追求更严谨，建议用 `threading.Lock` 加锁，或改用队列汇总后统一写入（见下文）。

## 6. 线程安全问题与 Lock 锁

多个线程同时修改**同一个全局变量**时，会因"操作不是原子"产生数据错乱。典型例子是多个线程对同一个数字累加：

```python
import threading

total = 0
lock = threading.Lock()   # 创建锁

def add():
    global total
    for _ in range(100000):
        # 加锁：同一时刻只有一个线程能进入下面的代码
        with lock:
            total += 1

ths = [threading.Thread(target=add) for _ in range(10)]
for t in ths:
    t.start()
for t in ths:
    t.join()              # join：等待所有线程执行完

print(total)   # 不加锁可能 < 1000000，加锁后一定是 1000000
```

> `total += 1` 实际上分三步（读值 → 计算 → 写回），并发时可能"读的都是同一个旧值"，导致少加。用 `with lock:` 包住临界区即可解决。

## 7. 锁的更多细节（RLock 与死锁）

```python
import threading

# RLock（可重入锁）：同一个线程可以重复 acquire 多次
# 适用：锁里再调用一个也需要锁的函数（递归/嵌套调用）
lock = threading.RLock()

def outer():
    with lock:
        inner()          # 如果这里用的是普通 Lock，会死锁；RLock 不会

def inner():
    with lock:
        print("内层也能加锁")

# Lock 的非阻塞获取：抢不到锁就立即返回，避免死等
l = threading.Lock()
if l.acquire(blocking=False):   # 拿不到返回 False，不阻塞
    try:
        print("拿到锁")
    finally:
        l.release()

# 带超时获取锁：最多等 2 秒，等不到就放弃（防死锁的兜底手段）
l2 = threading.Lock()
if l2.acquire(timeout=2):
    try:
        print("拿到锁")
    finally:
        l2.release()
```

> 死锁常见原因：两个线程互相等对方持有的锁（A 拿锁1 等锁2，B 拿锁2 等锁1）。避免办法：统一加锁顺序、用 `timeout` 获取、尽量缩小临界区。

## 8. 更多线程同步工具

除了 `Lock`，`threading` 还提供以下工具，控制多个线程的"协作"：

### Event（事件：让线程等待某个标志）

```python
import threading, time

event = threading.Event()

def worker():
    print("工作线程: 等待信号...")
    event.wait(10)            # 阻塞（最多 10 秒），直到 event.set()
    print("工作线程: 收到信号，开始干活")

t = threading.Thread(target=worker)
t.start()
time.sleep(2)
print("信号是否已设置:", event.is_set())   # False
event.set()                   # 发信号，唤醒等待的线程
print("信号是否已设置:", event.is_set())   # True
event.clear()                 # 清除信号，再次 wait 又会阻塞
```

### Semaphore（信号量：限制同时执行的线程数）

```python
import threading, time

sem = threading.Semaphore(3)   # 最多 3 个线程同时进入

def task(i):
    with sem:
        print(f"线程{i} 进入临界区")
        time.sleep(1)

ths = [threading.Thread(target=task, args=(i,)) for i in range(10)]
for t in ths: t.start()
for t in ths: t.join()
```

> Semaphore 和协程里的 `asyncio.Semaphore` 作用相同：控制并发度，防止同时发出太多请求被封。

### 用 Semaphore 控制爬虫并发速率（限流实战）

抓取时若并发太高容易被封 IP，用信号量限制"同时在飞的请求数"：

```python
import time
import requests
import threading
from concurrent.futures import ThreadPoolExecutor

sem = threading.Semaphore(5)   # 最多 5 个请求同时进行

def fetch(url):
    with sem:                  # 拿不到信号量就排队等
        resp = requests.get(url, timeout=5)
        return resp.status_code, url

with ThreadPoolExecutor(20) as pool:
    futures = [pool.submit(fetch, f"http://example.com/page/{i}") for i in range(100)]
    for f in futures:
        print(f.result())
```

### Barrier（集合点：等所有线程到齐才一起继续）

```python
import threading

barrier = threading.Barrier(3)   # 等 3 个线程都到齐才放行

def worker(i):
    print(f"线程{i} 到达")
    barrier.wait()               # 3 个都到齐后一起继续
    print(f"线程{i} 一起出发")
```

### Condition（条件变量：生产者-消费者在线程内的实现）

`Condition` 是"锁 + 等待/通知"的结合：某个线程条件不满足就 `wait()` 挂起，生产者满足条件后 `notify()` 唤醒。比 Lock 更适合"等待某个条件成立"的场景：

```python
import threading

cv = threading.Condition()
buffer = []        # 模拟缓冲区

def producer():
    with cv:
        for i in range(5):
            buffer.append(i)
            print("生产", i)
            cv.notify()          # 唤醒一个等待的消费者
        cv.notify_all()          # 全部唤醒

def consumer():
    with cv:
        while not buffer:
            cv.wait()            # 缓冲区空，挂起等待通知
        item = buffer.pop(0)
        print("消费", item)

t1 = threading.Thread(target=producer)
t2 = threading.Thread(target=consumer)
t1.start(); t2.start()
t1.join(); t2.join()
```

> 简单区分：`Lock` 只保证"互斥"（一次一个线程）；`Condition` 还能"按条件等待/唤醒"，线程内生产-消费用它比 Lock 更合适。跨进程的生产-消费则用 `multiprocessing.Queue`（见下文）。

### threading.local（线程局部变量：每个线程一份）

想让"每个线程拥有自己独立的变量"（互不干扰），用 `threading.local`。典型场景：多线程爬虫中，每个线程记录自己的请求次数/失败数：

```python
import threading
import time

local = threading.local()       # 全局一个对象，但每个线程独立存取

def worker(name):
    local.count = 0             # 每个线程各自的 count
    for _ in range(3):
        time.sleep(0.1)
        local.count += 1
    print(f"{name} 的 count = {local.count}")

ths = [threading.Thread(target=worker, args=(f"线程{i}",)) for i in range(3)]
for t in ths: t.start()
for t in ths: t.join()
# 输出三个线程各自的 count 都是 3，互不干扰
```

> `threading.local` 在 Flask 等框架里用于保存"每个请求"的数据。爬虫里常用于给每个线程维护独立的 Session 或计数，避免全局变量加锁的麻烦。

## 9. 多线程爬虫的统一出口：队列汇总

比起多个线程直接写文件，更规范的写法是**生产数据入队，单独一个线程写文件**（避免并发写文件的各种隐患）：

```python
import queue
import threading
from concurrent.futures import ThreadPoolExecutor

q = queue.Queue()

def fetch(url):
    q.put((url, "抓到的数据"))   # 只往队列里放，不碰文件

def save():
    while True:
        url, data = q.get()
        with open("out.txt", "a", encoding="utf-8") as f:
            f.write(f"{url} -> {data}\n")
        q.task_done()            # 标记这个任务处理完了

# 启动写文件的线程（守护线程，主流程结束即退出）
threading.Thread(target=save, daemon=True).start()

with ThreadPoolExecutor(10) as t:
    t.map(fetch, ["http://a.com", "http://b.com", "http://c.com"])

q.join()   # 等待队列里所有任务都处理完（内部计数器归零）
print("全部保存完成")
```

## 10. 生产者-消费者：哨兵值优雅退出

消费者循环是 `while True`，如何让它在"没任务时"退出？约定：生产者结束后放一个 **`None` 哨兵值**，消费者收到就退出：

```python
import queue
import time

q = queue.Queue()

def producer():
    for i in range(5):
        q.put(f"任务{i}")
        time.sleep(0.1)
    q.put(None)          # 哨兵：表示"没有更多任务了"

def consumer():
    while True:
        item = q.get()
        if item is None:   # 收到哨兵，退出循环
            print("消费者退出")
            break
        print("处理", item)

import threading
threading.Thread(target=producer).start()
threading.Thread(target=consumer).start()
```

## 11. requests.Session 线程安全性（爬虫高频坑）

`requests.Session` **不是线程安全的**（内部维护 cookie、连接池，并发读写会乱）。多线程爬虫的正确做法：**每个线程/每次任务独立创建 Session**：

```python
import requests
from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    # 每个任务自己建 Session，绝不共用全局 session
    with requests.Session() as s:
        s.headers.update({"User-Agent": "Mozilla/5.0"})
        resp = s.get(url, timeout=5)
        return resp.status_code

with ThreadPoolExecutor(10) as t:
    results = t.map(fetch, [f"http://example.com/{i}" for i in range(20)])
    print(list(results))
```

> 或者用上一节讲的 `threading.local` 为每个线程缓存一个独立 Session，避免每次新建的开销。

## 12. concurrent.futures 的高级用法（wait / as_completed）

线程池/进程池除了 `submit` / `map`，还能用 `wait` 和 `as_completed` 精细管理：

```python
import time
from concurrent.futures import ThreadPoolExecutor, wait, as_completed

def work(i):
    time.sleep(2 - i * 0.5)
    return f"任务{i}完成"

with ThreadPoolExecutor(3) as pool:
    futures = [pool.submit(work, i) for i in range(3)]

    # wait：等待全部（或部分）完成
    done, not_done = wait(futures, timeout=5, return_when="ALL_COMPLETED")
    print("完成数量:", len(done), "未完成:", len(not_done))
    # return_when 还有 FIRST_COMPLETED / FIRST_EXCEPTION

    # as_completed：谁先完成先处理谁（适合"先到先写"）
    for f in as_completed(futures):
        print(f.result())
```

> `map` 按传入顺序返回结果（慢任务会堵住后面的）；`as_completed` 按完成顺序返回（更灵活）。爬虫抓取后用 `as_completed` 边完成边入库很合适。

## 13. 线程池大小怎么定

线程池不是越大越好（线程切换也有开销、请求太频繁会被封）：

```python
import os
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

# 常用经验值
cpu_count = os.cpu_count()          # CPU 核数

# IO 密集（爬虫）：通常是 CPU 核数的 5~10 倍，或直接按目标网站承受能力设 5~30
io_pool = ThreadPoolExecutor(max_workers=cpu_count * 5)

# CPU 密集：核数或核数+1
cpu_pool = ProcessPoolExecutor(max_workers=cpu_count)
```

> 实际值要靠测试调：先用小并发（如 5）试，观察请求成功率/是否被限流，再逐步加大。小心"并发越高越容易被封"。

## 14. Python 的 GIL 锁（重要概念，深入理解）

**GIL（Global Interpreter Lock，全局解释器锁）**：CPython 在同一时刻**只有一个线程**能执行 Python 字节码。

因此：

- 多线程无法真正利用多核 CPU 来加速**纯计算**任务；
- 但对于**IO 密集型**任务（网络请求、文件读写），因为等待 IO 时会释放 GIL，多线程依然能显著提速——这正是爬虫用多线程的原因。

**GIL 为什么对 IO 密集有效？**

```python
import requests

# 线程A 发请求后，CPU 空转等待网络返回。
# 等待期间 Python 会释放 GIL，线程B 趁机拿到 GIL 去发自己的请求。
# 于是多个请求的"等待时间"被重叠了，总耗时接近单个请求。
resp = requests.get("http://example.com")
```

**几个关于 GIL 的冷知识**：

- 线程默认每 **5ms**（`sys.getswitchinterval()`）切换一次，用 `sys.setswitchinterval()` 可调；
- `time.sleep()`、`requests` 等待响应时都会**主动释放 GIL**；
- 想真正吃满多核做纯计算，要么用多进程（每进程独立解释器、独立 GIL），要么用 C 扩展（如 numpy，计算在 C 层不持 GIL）。

```python
import sys
print(sys.getswitchinterval())    # 默认 0.005（5 毫秒）
sys.setswitchinterval(0.001)      # 改小→切换更频繁，响应更及时但更耗性能
```

> 结论：爬虫的并发首选多线程/协程（IO 密集）；CPU 密集计算才考虑多进程。

## 15. queue 模块全解（线程安全的队列）

`queue.Queue` 是线程安全的，还有几种变体：

```python
import queue

# 1. Queue：普通 FIFO 队列（先进先出），最常用
q = queue.Queue(maxsize=10)     # 限定最大长度（满了 put 会阻塞）

q.put("任务")                    # 放入
item = q.get()                   # 取出（队列空会阻塞等待）
print(q.empty(), q.full(), q.qsize())   # 是否空 / 是否满 / 当前数量

# 非阻塞取出：队列空返回 None（注意 get_nowait 空时会抛 queue.Empty）
try:
    item = q.get_nowait()
except queue.Empty:
    print("队列是空的")

# 超时取出：等 3 秒，取不到抛 queue.Empty
try:
    item = q.get(timeout=3)
except queue.Empty:
    print("等 3 秒也没有任务")

# 2. LifoQueue：后进先出（栈），适合"后加入的任务优先处理"
q2 = queue.LifoQueue()
q2.put(1); q2.put(2)
print(q2.get())      # 2

# 3. PriorityQueue：按优先级取出（值越小越优先）
q3 = queue.PriorityQueue()
q3.put((2, "普通任务"))
q3.put((1, "VIP任务"))
print(q3.get()[1])   # VIP任务

# 4. SimpleQueue：极简版，无 maxsize、无 task_done/join，更快
q4 = queue.SimpleQueue()
q4.put("任务")
print(q4.get())
```

> 生产者-消费者模式中，"消费者循环"要小心死循环：可以约定生产者结束后 put 一个 `None` 哨兵值，消费者收到 `None` 就退出循环（见第 10 节）。

# 三、多进程

## 1. 直接用 Process 创建进程

```python
from multiprocessing import Process

def func():
    for i in range(1000):
        print("func", i)

if __name__ == '__main__':
    p = Process(target=func)
    p.start()               # 启动子进程
    for i in range(1000):
        print("main", i)
```

> 注意：**必须在 `if __name__ == '__main__':` 下创建进程**（Windows 上尤其如此，否则会递归创建进程导致报错）。

## 2. 继承 Process 类

```python
from multiprocessing import Process

class MyProcess(Process):
    def run(self):
        for i in range(1000):
            print("MyProcess", i)

if __name__ == '__main__':
    t = MyProcess()
    t.start()
    for i in range(1000):
        print("main", i)
```

## 3. 进程的常用控制方法

`Process` 对象除了 `start()`，还有这些方法（很多和线程类似，另有 terminate/kill 是线程没有的）：

```python
from multiprocessing import Process
import time

def worker():
    for i in range(100000000):
        pass

p = Process(target=worker)
p.start()
print("是否在运行:", p.is_alive())    # True
time.sleep(1)
# p.terminate()   # 强制终止子进程（Linux 发 SIGTERM；注意会有残留资源风险）
# p.kill()        # 3.7+，直接 SIGKILL，无法被捕获
p.join(timeout=2)                      # 等待子进程结束（最多等 2 秒）

# p.daemon = True   # 守护进程：父进程结束，子进程自动结束（须在 start 前设置）
print("主进程结束")
```

> 对比：`join()` 等待结束、`is_alive()` 查状态、`terminate()/kill()` 强杀、`daemon` 守护。线程没有 terminate/kill（想停线程只能靠 Event 等协作式退出）。

## 4. 进程池（ProcessPoolExecutor）

多进程能真正吃满多核 CPU，适合 CPU 密集任务。用法和线程池完全一致：

```python
import time
from concurrent.futures import ProcessPoolExecutor

def task(name: str):
    print(f'{name} - set1\n', end='')
    time.sleep(1)
    print(f'{name} - set2\n', end='')
    return f'{name} - 完成'

if __name__ == '__main__':
    with ProcessPoolExecutor(4) as executor:
        future = executor.submit(task, 'a')   # submit 返回 Future
        print(future.result())                 # 拿到返回值

        # map：按顺序拿结果
        results = executor.map(task, ['b', 'c'])
        for r in results:
            print(r)
```

> `ProcessPoolExecutor` 的 `map` / `submit` 用法和 `ThreadPoolExecutor` 完全一致，只是底层用多个进程，能跑满多核 CPU 做计算。默认 `max_workers` 为 `os.cpu_count()`。

## 5. 旧版进程池 multiprocessing.Pool（了解，老项目常见）

`ProcessPoolExecutor` 出现之前的经典写法，功能更细：

```python
from multiprocessing import Pool
import time

def square(n):
    time.sleep(1)
    return n * n

if __name__ == '__main__':
    with Pool(4) as pool:
        # apply：同步阻塞执行一个任务
        print(pool.apply(square, (3,)))              # 9

        # apply_async：异步执行，立即返回结果对象，之后 .get() 拿结果
        res = pool.apply_async(square, (4,))
        print(res.get())                             # 16

        # map：同步，全部做完才返回（按顺序）
        print(pool.map(square, [1, 2, 3]))           # [1, 4, 9]

        # imap：返回迭代器，出一个拿一个（省内存）
        for r in pool.imap(square, [1, 2, 3]):
            print(r)

        # imap_unordered：谁先完成先返回（不保证顺序，更快）
        for r in pool.imap_unordered(square, [1, 2, 3]):
            print(r)
```

> `apply` / `map` 是阻塞的；`apply_async` / `imap` / `imap_unordered` 是异步/懒加载的。新代码推荐 `ProcessPoolExecutor`，但老项目代码里常看到 `Pool`。

## 6. 进程间通信：Queue（生产者与消费者）

进程间**不共享内存**（除非用特殊机制），需要通过 `Queue`、`Pipe` 等通信。

最经典的应用：**生产者-消费者模式**。

> 场景：进程 1 负责抓取页面、提取图片下载地址（生产者）；进程 2 负责下载图片（消费者）。两者通过队列传递数据。

```python
from multiprocessing import Process, Queue
from concurrent.futures import ThreadPoolExecutor
import requests
from lxml import etree
from urllib import parse


# 生产者：从页面提取图片地址，放入队列
def get_pic_src(q):
    print("start main page spider")
    url = "http://www.example.com/mntt/"
    resp = requests.get(url)
    tree = etree.HTML(resp.text)
    child_hrefs = tree.xpath("//div[@class='MeinvTuPianBox']/ul/li/a/@href")
    print("get hrefs from main page", child_hrefs)
    for href in child_hrefs:
        href = parse.urljoin(url, href)
        resp_child = requests.get(href)
        tree = etree.HTML(resp_child.text)
        pic_src = tree.xpath("//div[@id='picBody']//img/@src")[0]
        print(f"put {pic_src} to the queue")
        q.put(pic_src)          # 放入队列
    q.put(None)                 # 哨兵：告诉消费者"生产完了"


# 消费者：从队列取出地址并下载
def download(url):
    print("start download", url)
    name = url.split("/")[-1]
    resp = requests.get(url)
    with open(name, mode="wb") as f:
        f.write(resp.content)
    resp.close()
    print("downloaded", url)


def start_download(q):
    with ThreadPoolExecutor(20) as t:
        while True:
            url = q.get()
            if url is None:      # 收到哨兵，退出
                print("all downloaded")
                break
            t.submit(download, url)


def main():
    q = Queue()
    p1 = Process(target=start_download, args=(q,))
    p2 = Process(target=get_pic_src, args=(q,))
    p1.start()
    p2.start()
    p1.join()                    # 等消费者退出
    p2.join()


if __name__ == '__main__':
    main()
```

**生产-消费模式的意义**：

- 抓取和下载两个功能**完全独立**，可并行执行；
- 通过队列解耦，生产者只管生产，消费者只管消费；
- 常用于代理 IP 池维护（一个进程抓 IP、一个进程校验 IP）等场景。

### JoinableQueue（带 task_done/join 的进程队列）

跨进程版的生产-消费，可以用 `JoinableQueue` 精确等待所有任务处理完：

```python
from multiprocessing import Process, JoinableQueue
import time

def consumer(q):
    while True:
        item = q.get()
        if item is None:
            q.task_done()          # 哨兵也要 task_done，否则 join 卡死
            break
        time.sleep(0.1)
        print("处理:", item)
        q.task_done()              # 标记处理完成

if __name__ == '__main__':
    q = JoinableQueue()
    ps = [Process(target=consumer, args=(q,)) for _ in range(3)]
    for p in ps: p.start()
    for i in range(10):
        q.put(f"任务{i}")
    for _ in ps:
        q.put(None)                # 每个消费者一个哨兵
    q.join()                       # 等队列里所有任务都 task_done
    print("所有任务处理完毕")
```

## 7. 进程间通信：Pipe（管道）

Pipe 是"一对一"的通信方式，两端分别 `send` / `recv`：

```python
from multiprocessing import Process, Pipe

def child(conn):
    conn.send("子进程发来消息")     # 发
    data = conn.recv()             # 收
    print("子进程收到:", data)
    conn.close()

if __name__ == '__main__':
    parent_conn, child_conn = Pipe()
    p = Process(target=child, args=(child_conn,))
    p.start()
    print("主进程收到:", parent_conn.recv())
    parent_conn.send("主进程回复")
    p.join()
```

> 简单说：**Queue 适合"一对多"任务分发**（生产者消费者），**Pipe 适合"一对一"双工通信**。爬虫中用 Queue 最多。

## 8. 进程间共享内存：Value / Array

进程默认不共享内存，但可以用 `multiprocessing.Value` 和 `Array` 显式共享一块内存：

```python
from multiprocessing import Process, Value, Array

def add(shared_num):
    for _ in range(100):
        with shared_num.get_lock():   # 也要加锁，防止并发写错乱
            shared_num.value += 1

if __name__ == '__main__':
    shared_num = Value("i", 0)        # "i" 表示整数类型
    ps = [Process(target=add, args=(shared_num,)) for _ in range(4)]
    for p in ps: p.start()
    for p in ps: p.join()
    print(shared_num.value)           # 400
```

> `Value` / `Array` 需要传入类型码：`"i"` 整数、`"f"` 浮点、`"d"` 双精度。注意：共享内存同样有并发写问题，要加锁（`Value` 自带 `get_lock()`）。

## 9. 进程间共享高级容器（Manager）

`Value`/`Array` 只能共享简单的数值/数组，想共享 `list`、`dict`、`Queue` 等高级对象要用 `multiprocessing.Manager`。它通过后台进程代理这些对象，多进程都能读写：

```python
from multiprocessing import Process, Manager

def worker(shared_list, shared_dict, name):
    shared_list.append(name)            # 直接像普通 list 一样操作
    shared_dict[name] = len(name)

if __name__ == '__main__':
    with Manager() as mgr:
        shared_list = mgr.list()        # 共享 list
        shared_dict = mgr.dict()        # 共享 dict

        ps = [Process(target=worker, args=(shared_list, shared_dict, f"进程{i}"))
              for i in range(3)]
        for p in ps: p.start()
        for p in ps: p.join()

        print(shared_list)   # ['进程0', '进程1', '进程2']
        print(shared_dict)   # {'进程0': 2, '进程1': 2, '进程2': 2}
```

> **对比**：`Queue`/`Pipe` 是"传递消息"（数据流），`Manager` 是"共享对象"（都去改同一个 list/dict）。爬虫做"多进程共享的去重集合/统计"时，用 `Manager().list()` 比 `Value` 灵活得多。注意 Manager 对象会慢一些，别用它做高频热数据。

## 10. 进程同步：Lock / Event / Semaphore

多进程同样有 `Lock`、`Event`、`Semaphore`（来自 `multiprocessing`），用法和 `threading` 几乎一样，用于跨进程的互斥与协作：

```python
from multiprocessing import Process, Lock, Event, Semaphore

def worker(lock, event, sem, i):
    with sem:                 # 控制同时进入的进程数
        with lock:            # 互斥写共享资源（如打印到同一终端）
            print(f"进程{i} 开始")
        event.wait()          # 等主进程发信号
        print(f"进程{i} 继续")

if __name__ == '__main__':
    lock, event, sem = Lock(), Event(), Semaphore(2)
    ps = [Process(target=worker, args=(lock, event, sem, i)) for i in range(4)]
    for p in ps: p.start()
    event.set()               # 统一放行
    for p in ps: p.join()
```

> 进程间要互斥修改"同一份共享数据"时，`Lock` 不能省。比如多个子进程都往 `Manager().list()` 里写，理想情况下也要加锁（Manager 内部有锁，但复合操作仍需自己加）。

## 11. 多进程的启动方式（Windows 必须注意）

- **fork**（Linux 默认）：子进程直接复制父进程内存，快；
- **spawn**（Windows 默认 / macOS 3.8+）：子进程重新导入主模块，慢，但更安全。

Windows 下用多进程的**三条铁律**：

1. 创建进程/进程池的代码必须写在 `if __name__ == '__main__':` 里（否则无限递归创建进程）；
2. 传给子进程的参数必须是**可 pickle 序列化**的（不能传 lambda、不能传局部函数外的类实例等）；
3. 把程序打包成 exe 运行时，主模块入口要加 `multiprocessing.freeze_support()`。

```python
from multiprocessing import freeze_support, Process

def worker():
    print("子进程执行")

if __name__ == '__main__':
    freeze_support()          # 打包 exe 时必须有
    p = Process(target=worker)
    p.start()
    p.join()
```

> 反爬脚本打包成 exe 交给别人跑时，多进程代码经常会因为忘了 `freeze_support()` 或没包 `if __name__` 而出诡异问题，注意排查。

## 12. 子进程/子任务的异常处理

子进程里抛异常不会直接炸掉主进程，但要用对方式拿到异常：

```python
from concurrent.futures import ProcessPoolExecutor

def risky(x):
    if x == 3:
        raise ValueError("x 不能是 3")
    return x * 2

if __name__ == '__main__':
    with ProcessPoolExecutor(4) as pool:
        futures = [pool.submit(risky, i) for i in range(5)]
        for f in futures:
            try:
                print(f.result())      # 出错时这里会抛异常
            except ValueError as e:
                print("子进程任务出错:", e)
```

> 建议：爬虫的每个任务函数内部自己 try/except，把"成功结果"或"错误信息"都以返回值形式返回，由主进程统一收集，比依赖异常机制更好排查。

## 四、多线程 vs 多进程 总结

| 对比项 | 多线程 | 多进程 |
| ------ | ------ | ------ |
| 资源开销 | 小 | 大 |
| 数据共享 | 共享全局变量（注意加锁） | 需要 Queue/Pipe 通信 |
| 是否受 GIL 限制 | 是 | 否 |
| 能利用多核 CPU | 不能（纯计算时） | 能 |
| 适合任务类型 | IO 密集型（爬虫网络请求） | CPU 密集型 |
| 爬虫中使用频率 | 高 | 低 |

**爬虫开发建议**：

- 首选**线程池 `ThreadPoolExecutor`**（IO 密集，简单高效）；
- 线程/进程的 `submit` 返回 **Future**：用 `result()` 拿值、`exception()` 拿异常、`add_done_callback()` 挂回调、`done()/running()/cancel()` 查状态；
- 并发修改共享变量/文件时用 **Lock** 或**队列汇总**，保证数据安全；`RLock` 可重入、`acquire(blocking=False/timeout=)` 防死锁；
- 线程协作工具：`Event`（信号）、`Semaphore`（限流）、`Barrier`（集合点）、`Condition`（条件等待/唤醒）、`threading.local`（线程局部变量）；
- 精细管理任务：`wait`（等待）、`as_completed`（先完成先处理）；
- **`requests.Session` 不是线程安全的**，多线程爬虫每个线程要独立 Session；
- 线程池大小：IO 密集 ≈ 核数×5~10，靠实测调整；
- `queue` 模块：`Queue`（FIFO）、`LifoQueue`（栈）、`PriorityQueue`（优先级）、`SimpleQueue`（极简）；`get_nowait()` / `get(timeout=)` / 哨兵值退出；
- 追求极致效率用**异步协程（aiohttp）**；
- 涉及独立功能拆分（如生产-消费）才考虑**多进程**；进程通信用 `Queue`/`JoinableQueue`/`Pipe`，共享内存用 `Value`/`Array`（记得加锁），共享 list/dict 等高级对象用 `Manager`；
- Windows 下多进程：必须 `if __name__ == '__main__'`、参数可 pickle、打包 exe 加 `freeze_support()`。
