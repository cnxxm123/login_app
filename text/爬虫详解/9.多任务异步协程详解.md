# 多任务异步协程 详解

## 一、什么是协程（Coroutine）？

**协程**是一种比线程更轻量的并发方案。它**在单线程内**通过"遇到 IO 就主动挂起、让出 CPU"的方式，实现任务的交替执行。

### 与线程的对比

| 对比项 | 线程 | 协程 |
| ------ | ---- | ---- |
| 运行载体 | 线程（OS 管理） | 单线程内（程序自己管理） |
| 切换开销 | 较大 | 极小 |
| 并发量 | 几百 ~ 几千 | 几万 ~ 几十万 |
| 控制权 | 由操作系统调度 | 由 `await` 主动让出 |
| 适用 | IO 密集 | **大规模 IO 密集（爬虫首选）** |

> 爬虫中 90% 的时间在等待网络响应。协程让"等待时间"被其他任务利用，从而极大提升并发效率。

## 二、协程基础语法

### 1. 最简单的协程

```python
import asyncio

async def func():
    print("我是协程")

if __name__ == '__main__':
    coroutine = func()          # 调用 async 函数得到协程对象（不会立即执行）
    asyncio.run(coroutine)      # 用 asyncio.run 运行协程
```

> `async def` 定义协程函数；`asyncio.run()` 是运行协程的入口（Python 3.7+）。
>
> 老式写法（了解）：`asyncio.get_event_loop().run_until_complete(coroutine)`。

### 2. await 挂起（核心）

```python
import asyncio

# await：遇到 await 时，任务被挂起，CPU 自动切换到其他任务
async def func1():
    print("func1, start")
    await asyncio.sleep(3)      # 模拟 IO 等待 3 秒
    print("func1, end")

async def func2():
    print("func2, start")
    await asyncio.sleep(4)
    print("func2, end")

async def func3():
    print("func3, start")
    await asyncio.sleep(2)
    print("func3, end")

async def main():
    # 创建任务（Task），让它们并发执行
    tasks = [
        asyncio.create_task(func1()),
        asyncio.create_task(func2()),
        asyncio.create_task(func3()),
    ]
    # 一次性等待所有任务完成
    done, pending = await asyncio.wait(tasks)

if __name__ == '__main__':
    asyncio.run(main())
```

**执行逻辑**：三个任务并发执行，`func1` 挂起 3 秒期间，`func2`、`func3` 也在同时计时，总耗时约为最长的 4 秒，而不是 3+4+2=9 秒。

### 2.5 什么是 awaitable（可等待对象）？

`await` 后面只能跟**可等待对象（awaitable）**，常见有三种：

| 可等待对象 | 说明 |
| ---------- | ---- |
| 协程对象 | `func()` 调用 async 函数得到 |
| Task 任务 | `asyncio.create_task()` 包装后的任务 |
| Future | 低层对象，Task 是其子类，一般不用直接操作 |

```python
import asyncio

async def coro():
    return "hello"

async def main():
    # 1. 直接 await 一个协程对象
    print(await coro())

    # 2. await 一个 Task
    task = asyncio.create_task(coro())
    print(await task)

    # 3. 判断一个对象能否被 await
    print(asyncio.iscoroutine(coro()))                              # True
    print(asyncio.isfuture(asyncio.create_task(coro())))            # True

asyncio.run(main())
```

> 在协程内部 `await coro()` 会**阻塞等待**该协程执行完（同步等待）；而 `create_task()` 是**异步提交**，不等它，立刻返回 Task 让你稍后 `await task` 拿结果——两者用途完全不同。

### 3. 获取协程的返回值

```python
import asyncio

async def faker1():
    await asyncio.sleep(1)
    return "任务1结束"

async def faker2():
    await asyncio.sleep(2)
    return "任务2结束"

async def faker3():
    await asyncio.sleep(3)
    return "任务3结束"

async def main():
    tasks = [
        asyncio.create_task(faker3()),
        asyncio.create_task(faker1()),
        asyncio.create_task(faker2()),
    ]

    # 方案一：wait 返回 (完成的任务集合, 未完成的任务集合)
    done, pending = await asyncio.wait(tasks)
    for r in done:
        print(r.result())          # 结果在 r.result() 中

    # 方案二：gather 按任务添加顺序返回结果
    # return_exceptions=True 时，任务报错会返回异常信息而不中断
    result = await asyncio.gather(*tasks, return_exceptions=True)
    for r in result:
        print(r)

if __name__ == '__main__':
    asyncio.run(main())
```

> `gather` 与 `wait` 的区别：`gather` 按传入顺序收集结果，`wait` 返回一个 set（顺序不固定）。

### 4. asyncio.wait_for：给单个任务设置超时（重点）

爬虫中"某个请求卡住"很常见，用 `wait_for` 给任务设超时，超时就抛 `asyncio.TimeoutError`：

```python
import asyncio

async def slow():
    await asyncio.sleep(10)
    return "数据"

async def main():
    try:
        # 最多等 2 秒，超时抛异常
        result = await asyncio.wait_for(slow(), timeout=2)
        print(result)
    except asyncio.TimeoutError:
        print("任务超时，已放弃")

asyncio.run(main())   # 输出：任务超时，已放弃
```

> 与 `asyncio.to_thread` 结合使用，可以给"同步库请求"也加上超时控制。

### 5. asyncio.as_completed：谁先完成先处理谁

和线程池的 `as_completed` 类似，按**完成顺序**处理任务结果（适合"边抓边入库/边写文件"）：

```python
import asyncio

async def work(i):
    await asyncio.sleep(3 - i)    # 任务 0 最慢，任务 2 最快
    return f"任务{i}完成"

async def main():
    tasks = [asyncio.create_task(work(i)) for i in range(3)]
    # 按完成顺序逐个处理，而非传入顺序
    for coro in asyncio.as_completed(tasks):
        print(await coro)

asyncio.run(main())
# 输出顺序：任务2完成 → 任务1完成 → 任务0完成
```

> 对比：`gather` 按添加顺序返回（慢任务会堵住后面的处理）；`as_completed` 谁先完成先处理，适合数据量大、边抓边存的场景。

### 6. TaskGroup（Python 3.11+，更优雅的并发写法）

Python 3.11 新增 `asyncio.TaskGroup`，语法更简洁、异常统一处理：

```python
import asyncio

async def work(i):
    await asyncio.sleep(1)
    return i * 2

async def main():
    async with asyncio.TaskGroup() as tg:   # 自动等待所有任务
        results = [tg.create_task(work(i)) for i in range(5)]
    # 退出 with 时所有任务已完成
    print([t.result() for t in results])    # [0, 2, 4, 6, 8]

asyncio.run(main())
```

> `TaskGroup` 的优点是：不用手动 `gather`/`wait`，异常会自动传播；Python 3.11 以下版本用 `gather` 即可。

### 7. create_task 与 ensure_future 的区别

两者都能把协程包装成 Task，区别在于 `ensure_future` 兼容更多类型：

```python
import asyncio

async def coro():
    return 42

async def main():
    # create_task：只能接收协程对象（推荐写法，语义清晰）
    t1 = asyncio.create_task(coro())

    # ensure_future：能接收协程/Future/Task，老代码常见
    t2 = asyncio.ensure_future(coro())

    print(await t1, await t2)

asyncio.run(main())
```

> 新代码统一用 `create_task` 即可；`ensure_future` 在官方文档和旧教程里经常出现，认识一下别懵。

### 8. 任务取消：task.cancel() 与 CancelledError

某个任务不需要了，或想实现"超时强杀"，可以调用 `task.cancel()`：

```python
import asyncio

async def long_task():
    try:
        await asyncio.sleep(100)
    except asyncio.CancelledError:
        print("任务被取消了")
        raise          # 一定要重新抛，否则任务状态不正常

async def main():
    task = asyncio.create_task(long_task())
    await asyncio.sleep(1)
    task.cancel()              # 请求取消该任务
    try:
        await task             # await 会抛 CancelledError
    except asyncio.CancelledError:
        print("捕获到取消异常")
    print("已取消:", task.cancelled())   # True

asyncio.run(main())
```

> 注意：`cancel()` 只是"请求取消"，真正生效在下次 `await` 时；任务内部可用 `try/except asyncio.CancelledError` 做清理工作（如关闭文件），但记得 `raise` 传播。

### 9. async with 与 async for（异步上下文/迭代器）

aiohttp 里 `async with session.get(url)` 就是**异步上下文管理器**。它们的作用：

```python
import asyncio

# 1. async with：进入/退出时做异步操作（比如打开/关闭连接、释放资源）
#    session.get() 返回的对象需要 await 才能释放连接，所以必须 async with

# 2. async for：迭代时每取一个元素都可能 await（比如边收边解析流式数据）
async def gen():
    for i in range(3):
        await asyncio.sleep(0.1)
        yield i

async def main():
    async for x in gen()      # 每次迭代内部都会 await
        print(x)

asyncio.run(main())
```

> 记法：`async with` / `async for` 里**都可以用 await**，专门用于"异步资源的获取与释放""异步流的遍历"。协程里凡是看到 `async with`，都要想到"这里可能挂起、需要等待"。

## 三、aiohttp：异步 HTTP 请求库

`requests` 是同步库，不能用于协程。异步爬虫需要 **aiohttp**。

### 安装

```bash
pip install aiohttp
pip install aiofiles   # 异步文件写入（可选，能进一步提升效率）
```

### 基本使用：异步下载图片

```python
import asyncio
import aiohttp
import aiofiles


async def download(url):
    name = url.split("/")[-1]
    async with aiohttp.ClientSession() as session:      # 创建会话
        async with session.get(url) as resp:           # 发送请求（注意：有 async with）
            content = await resp.content.read()        # 读取字节内容（要 await）
            async with aiofiles.open(name, mode="wb") as f:
                await f.write(content)
                return "OK"


async def main():
    url_list = [
        "https://example.com/img/1.jpg",
        "https://example.com/img/2.jpg",
        "https://example.com/img/3.jpg",
        "https://example.com/img/4.jpg",
    ]
    tasks = []
    for url in url_list:
        tasks.append(asyncio.create_task(download(url)))
    await asyncio.wait(tasks)

if __name__ == '__main__':
    asyncio.run(main())
```

**aiohttp 与 requests 的对应关系**：

| requests | aiohttp（异步） |
| -------- | --------------- |
| `requests.get(url)` | `session.get(url)`（需 `async with`） |
| `resp.text` | `await resp.text()`（方法，加括号） |
| `resp.content` | `await resp.content.read()` |
| `proxies={...}` | `proxy="http://..."` |
| `resp.encoding` | `await resp.text(encoding="utf-8")` |

> **注意**：aiohttp 中 `resp.text` 是**方法**，要加括号；读取网络内容几乎都要 `await`。

### aiohttp 会话复用（重要）

不要在**每个请求**里都新建 `ClientSession`——会话复用 TCP 连接，性能差异巨大。正确做法：创建一个 session，作为参数传给各任务：

```python
import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as resp:   # 复用传入的 session
        return await resp.text()

async def main():
    # 只创建一个 session
    async with aiohttp.ClientSession() as session:
        tasks = [asyncio.create_task(fetch(session, url)) for url in url_list]
        results = await asyncio.gather(*tasks)
    # 退出 with 后 session 自动关闭
```

> 错误示范：`async with aiohttp.ClientSession() as s: s.get(url)` 写在每个请求函数里 → 每个请求都新建会话，慢且浪费。

### aiohttp 超时设置（ClientTimeout）

`ClientSession` 或单个请求都可设置超时：

```python
import aiohttp

# 方式一：整个会话统一超时
timeout = aiohttp.ClientTimeout(
    total=10,        # 整个请求总超时（秒）
    connect=5,       # 连接超时
    sock_read=5,     # 读取单个数据块超时
)
async with aiohttp.ClientSession(timeout=timeout) as session:
    ...

# 方式二：单个请求单独设置（覆盖会话默认）
async with session.get(url, timeout=aiohttp.ClientTimeout(total=3)) as resp:
    ...
```

> `total` 是最常用的一个参数；不设置时默认 5 分钟，可能让爬虫"卡住"很久。

### aiohttp 异常处理与自动重试

```python
import asyncio
import aiohttp
from aiohttp import ClientError

async def fetch_with_retry(session, url, retries=3):
    for attempt in range(retries):
        try:
            async with session.get(url, timeout=10) as resp:
                resp.raise_for_status()          # 4xx/5xx 抛异常
                return await resp.text()
        except (aiohttp.ClientError, asyncio.TimeoutError) as e:
            print(f"第{attempt + 1}次失败: {url} -> {e}")
            if attempt == retries - 1:
                raise                            # 重试完仍失败则抛出
            await asyncio.sleep(1 * (attempt + 1))   # 退避重试

async def main():
    async with aiohttp.ClientSession() as session:
        tasks = [asyncio.create_task(fetch_with_retry(session, u)) for u in url_list]
        results = await asyncio.gather(*tasks, return_exceptions=True)  # 失败不中断整体
```

> 常用异常：`aiohttp.ClientError`（所有请求异常的父类）、`asyncio.TimeoutError`（超时）、`aiohttp.ClientConnectionError`（连接失败）、`aiohttp.ClientResponseError`（HTTP 状态码错误）。

### aiohttp 连接数限制（TCPConnector）

默认并发太高可能被封，用 `TCPConnector` 限制连接数：

```python
import asyncio
import aiohttp

async def main():
    connector = aiohttp.TCPConnector(
        limit=100,            # 同一主机最多同时 100 个连接
        limit_per_host=10,    # 每个 host 最多 10 个
        ssl=False,            # 关闭 SSL 校验（测试环境，可选）
    )
    async with aiohttp.ClientSession(connector=connector) as session:
        ...
```

> 也支持 `TCPConnector` 打开后手动 `connector.close()`；配合 `Semaphore` 双保险控制并发。

### aiohttp 代理与 Cookie 携带

```python
import asyncio
import aiohttp

async def main():
    # 代理：单个请求/整个会话都支持（付费代理带账号密码）
    proxy = "http://user123:pass456@112.74.90.1:8080"

    async with aiohttp.ClientSession() as session:
        # 单个请求带代理
        async with session.get("https://httpbin.org/ip", proxy=proxy) as resp:
            print(await resp.text())

    # 会话统一代理：所有请求都走该代理
    async with aiohttp.ClientSession(
        proxy="http://112.74.90.1:8080",
        trust_env=False,               # 忽略系统环境变量代理（等同 requests 的 trust_env）
    ) as session:
        ...

    # 手动携带 Cookie：与 requests 的 cookies={} 一样
    async with session.get("https://example.com", cookies={"token": "abc123"}) as resp:
        print(await resp.text())

asyncio.run(main())
```

> aiohttp 的会话（`ClientSession`）和 requests 的 `Session` 一样会**自动保存服务器下发的 Cookie**，登录后直接复用即可；`trust_env=False` 可绕过本机代理软件（Clash/VPN），避免请求意外走进系统代理。

### asyncio.Queue：异步生产者-消费者（爬虫常用）

协程爬虫常见的"队列分发"写法：一个协程产 URL，多个协程并发消费：

```python
import asyncio
import aiohttp

async def producer(q, urls):
    for url in urls:
        await q.put(url)              # 放入队列
    await q.put(None)                 # 哨兵：告诉消费者"没有了"

async def consumer(q, session):
    while True:
        url = await q.get()
        if url is None:               # 收到哨兵退出
            q.task_done()
            break
        async with session.get(url) as resp:
            print(url, "->", resp.status)
        q.task_done()

async def main():
    q = asyncio.Queue()
    async with aiohttp.ClientSession() as session:
        urls = [f"https://example.com/{i}" for i in range(20)]
        # 一个生产者 + 5 个消费者（控制并发度）
        producers = [asyncio.create_task(producer(q, urls))]
        consumers = [asyncio.create_task(consumer(q, session)) for _ in range(5)]
        await asyncio.gather(*producers, *consumers)

asyncio.run(main())
```

> `asyncio.Queue` 是线程安全的异步队列，`await q.put()` / `await q.get()` 支持挂起等待；用 `None` 作为**哨兵值**结束消费者循环，是生产者-消费者模式的标准收尾写法。

### asyncio.Queue 的更多方法（put_nowait / get_nowait / maxsize）

```python
import asyncio

async def main():
    q = asyncio.Queue(maxsize=3)     # 限定容量，满了 put 会挂起等待

    # 非阻塞版本：放不下/取不到时抛异常（不挂起）
    try:
        q.put_nowait("任务1")
        q.put_nowait("任务2")
        q.put_nowait("任务3")
        q.put_nowait("任务4")        # 已满，抛 asyncio.QueueFull
    except asyncio.QueueFull:
        print("队列满了")

    try:
        item = q.get_nowait()        # 空队列会抛 asyncio.QueueEmpty
    except asyncio.QueueEmpty:
        print("队列空了")

    print(q.qsize(), q.empty(), q.full())   # 当前长度 / 是否空 / 是否满

asyncio.run(main())
```

> `await q.put()`/`await q.get()` 会挂起等待；`put_nowait()`/`get_nowait()` 立即返回或抛 `asyncio.QueueFull`/`asyncio.QueueEmpty`。爬虫里常用 `maxsize` 限流：生产者塞满后自动等待，消费者消费后继续。

### aiohttp 响应常用操作（json / 流式 / 状态）

```python
import asyncio
import aiohttp

async def handle_resp(session, url):
    async with session.get(url) as resp:
        print(resp.status)                 # 状态码（int）
        print(resp.url)                    # 最终 URL
        print(resp.headers.get("Content-Type"))   # 响应头

        # 1. 接口返回 JSON → 直接用 await resp.json()（等价 requests 的 resp.json()）
        data = await resp.json()
        print(data.get("code"))

        # 2. 状态码判断（模拟 raise_for_status）
        resp.raise_for_status()            # 4xx/5xx 抛 aiohttp.ClientResponseError

        # 3. 大文件流式读取：async for 边读边写（等价 requests 的 stream + iter_content）
        async with aiohttp.ClientSession() as s2:
            async with s2.get("https://example.com/big.zip") as r:
                with open("big.zip", "wb") as f:
                    async for chunk in r.content.iter_chunked(8192):  # 每次 8KB
                        f.write(chunk)
```

> 要点：`await resp.json()` 会自动按 `Content-Type` 解析；流式下载用 `resp.content.iter_chunked(size)` + `async for`，避免一次性读入内存。

### aiohttp POST 与 JSON 提交（登录场景）

```python
import asyncio
import aiohttp

async def login(session, username, pwd):
    # 方式一：表单提交（等价 requests 的 data=）
    async with session.post(
        "https://example.com/login",
        data={"username": username, "password": pwd},
        headers={"User-Agent": "Mozilla/5.0"},
    ) as resp:
        print(await resp.text())

    # 方式二：JSON 提交（等价 requests 的 json=，会自动设置 Content-Type）
    async with session.post(
        "https://api.example.com/login",
        json={"username": username, "password": pwd},
    ) as resp:
        data = await resp.json()
        token = data.get("token")
        print("登录返回:", token)
    return token

async def main():
    async with aiohttp.ClientSession() as session:   # 会话复用，cookie 自动携带
        token = await login(session, "alex", "123")
        # 之后的请求自动带上登录 cookie/token
        async with session.get("https://example.com/member") as resp:
            print(await resp.text())

asyncio.run(main())
```

> 和 requests 一样：表单用 `data=`，JSON 用 `json=`。会话（session）会自动保存服务器下发的 Cookie，维持登录态。

### aiohttp 与 requests 参数对照速查

| 功能 | requests | aiohttp |
| ---- | -------- | ------- |
| 查询参数 | `params={}` | `params={}` |
| 表单数据 | `data={}` | `data={}` |
| JSON | `json={}` | `json={}` |
| 请求头 | `headers={}` | `headers={}` |
| Cookie | `cookies={}` / Session | `cookies={}` / 会话自带 |
| 代理 | `proxies={}` | `proxy="http://..."` |
| 超时 | `timeout=3` | `ClientTimeout(total=3)` |
| SSL 关闭 | `verify=False` | `ssl=False` |
| 编码 | `resp.encoding` | `await resp.text(encoding="utf-8")` |
| 二进制 | `resp.content` | `await resp.content.read()` |
| 会话 | `requests.Session()` | `aiohttp.ClientSession()` |

## 四、实战案例：异步扒取整本小说

目标：用协程并发下载"明朝那些事儿"的所有章节。

```python
import requests          # 用 requests 获取章节列表（一次性，无所谓）
import aiohttp
import aiofiles
import asyncio
from lxml import etree
from urllib.parse import urljoin

my_headers = {
    "user-agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/127.0.0.0 Safari/537.36",
    "referer": "http://www.sharereading.cc/0/254/",
}


def get_all_chapter_url():
    """同步获取所有章节的 URL 列表"""
    url = "http://www.sharereading.cc/0/254/"
    session = requests.session()
    session.headers = my_headers
    resp = session.get(url)
    tree = etree.HTML(resp.text)
    a_list = tree.xpath("//div[@class='info-chapters flex flex-wrap']/a")
    result = []
    for a in a_list:
        href = a.xpath("./@href")[0].strip()
        text = a.xpath("./text()")[0].strip()
        result.append({"name": text, "chapter_url": urljoin(url, href)})
    return result


async def download_one(name, c_url):
    """异步下载单个章节"""
    async with aiohttp.ClientSession(headers=my_headers) as session:
        async with session.get(c_url) as resp:
            txt = await resp.text(encoding="utf-8")
            tree = etree.HTML(txt)
            content = tree.xpath("//article[@id='article']//text()")
            content = "".join(content)
            async with aiofiles.open(f"{name}.txt", mode="w", encoding="utf-8") as f:
                await f.write(content)
                print(f"下载{name}完成!")


async def download_all_chapter(chapter_urls):
    """并发下载所有章节"""
    tasks = []
    for chapter in chapter_urls:
        t = asyncio.create_task(download_one(chapter["name"], chapter["chapter_url"]))
        tasks.append(t)
    await asyncio.wait(tasks)


def main():
    # 1. 先同步拿到所有章节 URL
    chapter_urls = get_all_chapter_url()
    # 2. 启动协程并发下载
    asyncio.run(download_all_chapter(chapter_urls))


if __name__ == '__main__':
    main()
```

> **经验总结**：
> 1. 章节列表页只有一个 URL → 用同步 `requests` 拿；
> 2. 大量章节页面 → 用异步 `aiohttp` 并发抓；
> 3. 避免为每个请求新建 `ClientSession`，尽量复用；大并发可考虑 `asyncio.Semaphore` 限流（防止被封）。

### 协程限流（信号量 Semaphore）

```python
import asyncio
import aiohttp

# 最多同时 10 个并发请求
semaphore = asyncio.Semaphore(10)

async def fetch(session, url):
    async with semaphore:            # 超过 10 个时等待
        async with session.get(url) as resp:
            return await resp.text()

async def main():
    async with aiohttp.ClientSession() as session:
        tasks = [asyncio.create_task(fetch(session, url)) for url in url_list]
        results = await asyncio.gather(*tasks)
```

## 五·五、事件循环与"线程 + 协程"的配合

### 1. 事件循环（EventLoop）是什么

asyncio 的核心是**事件循环**：它像一个调度器，不断检查"哪个任务可以继续执行"，遇到 `await` 就把控制权交还给循环，去跑别的任务。

```python
import asyncio

# 获取当前事件循环（大多数场景无需手动操作，asyncio.run 已封装）
loop = asyncio.get_event_loop()

async def main():
    print("hello")

asyncio.run(main())
```

> 一句话理解：**事件循环 = 协程的"操作系统"**，负责协程的创建、挂起、恢复与销毁。

### 2. 在协程中调用同步代码（run_in_executor / to_thread）

`requests`、`pymysql` 等是同步库，不能在协程里直接 `await`。如果必须调用，用 `asyncio.to_thread` 把它们丢到线程池里执行，避免阻塞事件循环：

```python
import asyncio
import requests

async def main():
    # 把同步的 requests.get 放到线程池执行，不阻塞事件循环
    resp = await asyncio.to_thread(requests.get, "https://example.com", timeout=5)
    print(resp.status_code)

asyncio.run(main())
```

### 3. 线程与协程谁更快？

| 方案 | 并发上限 | 写代码难度 | 推荐场景 |
| ---- | -------- | ---------- | -------- |
| 多线程 | 几百 ~ 几千 | 低 | 中小规模爬虫 |
| 协程 | 几万 ~ 几十万 | 中 | 大规模爬虫、接口轮询 |

> 实践中很多爬虫是"**线程池（管理 URL 队列） + 协程（处理每个请求）**"的混合方案，取两者之长。对初学者，先掌握其中一种即可。

### 4. 事件循环阻塞陷阱：time.sleep 会卡死整个协程

在协程里**绝不能**用 `time.sleep()`，它会阻塞整个线程，事件循环也停摆；要用 `await asyncio.sleep()`：

```python
import asyncio
import time

async def bad():
    time.sleep(3)          # 阻塞整个事件循环：期间其他任务全停
    print("bad 完成")

async def good():
    await asyncio.sleep(3) # 挂起当前任务，其他协程照常跑
    print("good 完成")

async def main():
    await asyncio.gather(bad(), good())

asyncio.run(main())
```

> 同理：`requests` 的同步请求也会阻塞事件循环。要么全用 aiohttp，要么用 `asyncio.to_thread` 把同步代码丢到线程池。

### 5. 协程里做 CPU 密集计算（run_in_executor + 进程池）

协程里直接跑大量计算会阻塞事件循环。CPU 密集任务应该丢到**进程池**：

```python
import asyncio
from concurrent.futures import ProcessPoolExecutor

def heavy_calc(n):
    total = 0
    for i in range(n):
        total += i * i
    return total

async def main():
    loop = asyncio.get_running_loop()
    with ProcessPoolExecutor(4) as pool:   # 多进程吃满多核
        # run_in_executor：把同步函数放到执行器里跑，不阻塞事件循环
        result = await loop.run_in_executor(pool, heavy_calc, 10000000)
        print(result)

asyncio.run(main())
```

> `asyncio.to_thread` 等价于 `run_in_executor(None, ...)`（默认线程池）；想用多进程就手动传 `ProcessPoolExecutor`。爬虫场景基本用不到，了解即可。

## 六、协程在爬虫中的完整套路

```
1. 同步阶段：用 requests 拿到列表页 → 解析出所有详情页 URL
2. 异步阶段：
   - 用 asyncio.create_task 为每个 URL 创建任务
   - 用 asyncio.gather / asyncio.wait 并发执行
   - 用 aiohttp 发送异步请求，aiofiles 异步写文件（可选）
   - 用 Semaphore 控制并发量，避免被封
3. 收尾：统一保存 / 入库
```

## 七、小结

- 协程在**单线程**内通过 `await` 让出控制权实现高并发；
- 三个核心：`async def`（定义）、`asyncio.create_task()`（创建任务）、`asyncio.gather()/wait()`（等待完成）；
- 精细控制：`wait_for`（单任务超时）、`as_completed`（按完成顺序处理）、`TaskGroup`（3.11+ 优雅并发）；
- 异步请求用 **aiohttp**（**会话要复用**、`ClientTimeout` 设超时、`TCPConnector` 限连接数、`ClientError` 捕获重试），异步写文件用 **aiofiles**；代理用 `proxy=`/`trust_env=False`，Cookie 会话自动携带；
- `asyncio.Queue` 生产者-消费者：一个协程产 URL、多个协程并发消费，用 `None` 哨兵结束循环；
- 事件循环负责协程的调度；同步库可用 `asyncio.to_thread` 丢到线程池执行；
- 爬虫并发效率：**协程 ≥ 多线程 >> 串行**，协程是高性能爬虫的首选。
