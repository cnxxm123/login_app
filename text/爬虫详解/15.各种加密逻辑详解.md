# 各种加密逻辑 详解

## 一、字符编码基础（先分清编码，再谈加密）

在做 JS 逆向时，我们经常看到一堆"看不懂"的密文，其中很多只是**编码**（可逆、可还原），并非真正的加密。先分清常用字符编码：

| 特性 | ASCII | GBK | UTF-8 |
| ---- | ----- | --- | ----- |
| 支持语言 | 仅英语 | 中文及少数东亚语言 | 全球所有语言 |
| 编码长度 | 固定 1 字节 | 英文 1 字节 / 中文 2 字节 | 1-4 字节（变长） |
| 兼容性 | 仅自身 | 兼容 ASCII 和 GB2312 | 兼容 ASCII，全球通用 |
| 应用场景 | 早期英语系统 | 中文 Windows、传统中文软件 | 互联网、编程、多语言 |

> Python 中编码转换口诀：**"字符串 → encode('编码') → 字节；字节 → decode('编码') → 字符串"**。出现乱码时，先确认是 GBK 还是 UTF-8。

# 二、摘要算法（哈希）：MD5 / SHA

## 1. 什么是摘要算法

MD5、SHA1、SHA256 都属于**摘要（hash）算法**：

- 输入任意长度数据，输出**固定长度**的散列值；
- 是**散列**，不是加密——**不可逆**，没有解密逻辑；
- 特点：小巧、速度快、难以破解，常用于**计算签名/指纹**。

> **MD5 特征**：标准十六进制结果只含 `0-9` 和 `a-f`（小写），固定 **32 位**长度。

## 2. Python 实现 MD5（可加盐）

```python
from hashlib import md5

s = 'alex'
salt = "我是盐，把我加进去就没人能破解了"

# 加盐（可选）：创建加密器对象时传入 salt，加盐后很难撞库
obj = md5(salt.encode("utf-8"))
obj.update(s.encode("utf-8"))     # 传入明文开始加密

bs = obj.hexdigest()              # 十六进制字符串（32 位）
print(bs)
```

不加盐的写法：

```python
from hashlib import md5

obj = md5()
obj.update(b"alex")
print(obj.hexdigest())
```

## 3. 扩展：SHA1 / SHA256

```python
from hashlib import sha1, sha256

# sha256（加盐）
sha = sha256(b"salt")
sha.update(b"alex")
print(sha.hexdigest())

# sha1
sha1_obj = sha1()
sha1_obj.update(b"alex")
print(sha1_obj.hexdigest())
```

> MD5 输出 32 位（128 bit）、SHA1 输出 40 位（160 bit）、SHA256 输出 64 位（256 bit）。散列程度（安全性）递增。

## 4. JS 实现 MD5（Node.js）

```js
var crypto = require("crypto");   // Node 自带，无需安装

function my_md5(s) {
    return crypto.createHash("md5").update(s).digest("hex");
}

console.log(my_md5("alex"));
```

## 5. HMAC（带密钥的哈希，接口签名常用）

HMAC 在哈希的基础上**混入一个密钥**，常用于接口签名（防篡改）。它比单纯 MD5 更安全。

### Python 实现 HMAC-SHA256

```python
import hmac
import hashlib

secret = b"my_secret_key"     # 密钥（双方约定）
message = "name=alex&age=18"  # 要签名的内容

h = hmac.new(secret, message.encode("utf-8"), hashlib.sha256)
print(h.hexdigest())          # 64 位十六进制
```

### JS 实现 HMAC-SHA256

```js
var crypto = require("crypto");

var secret = "my_secret_key";
var message = "name=alex&age=18";

var h = crypto.createHmac("sha256", secret).update(message).digest("hex");
console.log(h);
```

> 逆向中很多接口的 `sign` / `token` 参数就是 HMAC-SHA256 生成的签名。判断方法：服务器知道密钥，把参数按约定排序拼接后做 HMAC，**同样的输入永远得到同样的输出**，方便服务端校验。

## 6. 摘要算法速查（输出长度）

| 算法 | 输出长度（十六进制位数） | 安全性 |
| ---- | ------------------------ | ------ |
| MD5 | 32 | 弱（已可碰撞） |
| SHA1 | 40 | 弱（已可碰撞） |
| SHA256 | 64 | 较强（常用） |
| SHA512 | 128 | 强 |

> 一句话：**越长越安全，但 MD5/SHA1 因速度快仍是爬虫里最常见的"伪加密"参数**（很多网站只是拿它做防篡改，并不是真正保密）。

# 三、Base64（编码，不是加密）

## 1. 为什么需要 Base64

加密/传输的内容本质是**字节**。但 HTTP 协议里传输二进制（尤其是含不可打印字符）很麻烦，容易出错或被截断。Base64 把二进制数据变成"由可打印字符组成的字符串"，方便传输。

**Base64 字符集**：26 个大写字母 + 26 个小写字母 + 10 个数字 + `+` `/`，共 64 个字符。

> Base64 是一种**字符串格式**，可逆（能解码还原），属于编码而非加密。

## 2. Python 实现 Base64

```python
import base64

# 编码流程：字符串 -> 字节 -> b64编码 -> 字节 -> decode成字符串
bs = "我要吃饭".encode("utf-8")
bm = base64.b64encode(bs)      # 得到 bytes
s = bm.decode()                # 转成字符串
print(s)                       # 5oiR6KaB5ZCD6aWt

# 解码
print(base64.b64decode(s).decode("utf-8"))   # 我要吃饭
```

## 3. Base64 的长度问题（重点坑）

**Base64 编码后的字符串长度一定是 4 的倍数**（每 3 字节 → 4 字符）。如果长度不是 4 的倍数，解码会报错：

```python
import base64

s = "ztKwrsTj0b0"
bb = base64.b64decode(s)
```

报错：

```
binascii.Error: Incorrect padding
```

**解决：用 `=` 补齐到 4 的倍数**：

```python
import base64

s = "ztKwrsTj0b0"
s += ("=" * (4 - len(s) % 4))    # 补位
bb = base64.b64decode(s).decode("gbk")
print(bb)
```

## 4. Base64URL（URL 安全版）

标准 Base64 会产出 `+` 和 `/`，这两个字符在 URL 参数中不合法，于是有了 **Base64URL**：

- `+` → `-`，`/` → `_`；
- 末尾的 `=`（补位符）通常被去掉。

**解码时怎么还原**？—— 由于 Base64 长度必须是 4 的倍数，先把长度补齐为 4 的倍数再加 `=`，同时把 `-`/`_` 换回 `+/`：

```python
import base64

mi = "要解码的Base64URL字符串"
b64 = base64.b64decode(mi, b"-_")   # 第二个参数指定 +/ 被替换成了 -_
```

> 逆向时如果遇到带 `-` 和 `_` 的"Base64"，多半是 Base64URL，用上面的方式处理。

## 三·五、Node 中的编码转换（Buffer）

JS 逆向常用 Node 调试，Node 里所有编码转换都通过 **Buffer** 完成：

```js
// 字符串 -> base64
var s = "我爱Python";
console.log(Buffer.from(s, "utf8").toString("base64"));

// base64 -> 字符串
var b64 = "5oiR54ixUHl0aG9u";
console.log(Buffer.from(b64, "base64").toString("utf8"));

// 字符串 -> hex
console.log(Buffer.from(s, "utf8").toString("hex"));

// hex -> 字符串
var hex = "e68891e788b1";
console.log(Buffer.from(hex, "hex").toString("utf8"));
```

> 三者的相互转换：`Buffer.from(数据, 原编码).toString(目标编码)`。逆向还原密文时，先确认密文是 Base64 还是 Hex，再决定解码方式。

# 四、URLEncode（百分号编码）

## 1. 作用与原理

URL 参数中的中文、`&`、`=` 等特殊字符，会与 URL 原本的分隔符产生歧义，所以浏览器会自动把它们编码成 `%xx` 的形式（**只编码用户填入的参数部分，URL 原本的 `&`、`=` 不变**）。

例如搜索"吃饭睡觉打豆豆"：

```
https://www.sogou.com/web?query=%E5%90%83%E9%A5%AD%E7%9D%A1%E8%A7%89%E6%89%93%E8%B1%86%E8%B1%86&ie=utf8
```

原理：参数按字节编码，每字节转成 2 个十六进制数字，前面加 `%`。

## 2. Python 实现

```python
from urllib.parse import urlencode, unquote, quote

# 单个字符串编码
wq = "米饭怎么吃"
print(quote(wq))                      # %E7%B1%B3%E9%A5%AD%E6%80%8E%E4%B9%88%E5%90%83（utf-8 默认）
print(quote(wq, encoding="gbk"))      # %C3%D7%B7%B9%D4%F5%C3%B4%B3%D4

# 字典整体编码
dic = {"wq": "米饭怎么吃", "new_wq": "想怎么吃就怎么吃"}
print(urlencode(dic))

# 拼接完整 URL
base_url = "http://www.baidu.com/s?"
params = {"wd": "大王"}
url = base_url + urlencode(params)
print(url)   # http://www.baidu.com/s?wd=%E5%A4%A7%E7%8E%8B

# 解码
s = "http://www.baidu.com/s?wd=%E5%A4%A7%E7%8E%8B"
print(unquote(s))   # http://www.baidu.com/s?wd=大王
```

# 五、对称加密：AES / DES / 3DES

## 1. 什么是对称加密

**加密和解密使用同一个密钥**。常见算法：**AES、DES、3DES**。

| 算法 | 密钥长度 | 特点 |
| ---- | -------- | ---- |
| DES | 8 字节（64 bit） | 较老，已不够安全 |
| 3DES | 16/24 字节 | 内部是 DES，强度更高 |
| AES | 16/24/32 字节 | 现代标准，最常用 |

AES 密钥长度与型号对应：

```
16 字节 → AES-128
24 字节 → AES-192
32 字节 → AES-256
```

**加密模式（MODE）**：

- `ECB`：无 IV，把明文分成等长块分别加密，密文块之间无关联；
- `CBC`：**有 IV**，IV 长度与块大小相同（AES 为 16 字节）。前一个密文块与当前明文块异或后再加密，增强破解难度；
- `CFB / OFB`：反馈模式，同样增强破解难度；
- `GCM`：认证加密模式（AEAD），既加密又能校验完整性，现代接口常用。

**填充方式（Padding）**：

块加密算法要求明文长度是块大小（AES 为 16 字节）的整数倍，不足就要**填充**：

| 填充方式 | 说明 |
| -------- | ---- |
| `PKCS7` / `PKCS5` | 缺几个字节就补几个几（最常用） |
| `ZeroPadding` | 用 `\x00` 补足（不推荐） |
| `NoPadding` | 不填充（要求明文长度恰好是整数倍） |

> 逆向判断要点：**CryptoJS 默认是 `Pkcs7`；Python 的 `pad(明文, 16)` 默认也是 PKCS7**。只有看到特殊代码（如手动补 `\x00`）才是 ZeroPadding。

> 测试网站：https://the-x.cn/cryptography/Aes.aspx

pip install pycryptodome

## 3. AES 加密（CBC 模式）

```python
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
import base64

# 加密
s = "我爱你"
key = b"6666666666666666"            # 16 字节
iv = b"1234567887654321"              # CBC 模式必须有 iv（16 字节）

aes = AES.new(key=key, mode=AES.MODE_CBC, IV=iv)
bs = aes.encrypt(pad(s.encode("utf-8"), 16))   # 加密内容必须是字节，按 16 字节对齐填充
print(base64.b64encode(bs).decode())           # 密文通常转成 base64 传输
```

## 4. AES 解密

```python
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
import base64

s = "S3WGYGwaJ8CuofITEdLeew=="
key = b"6666666666666666"
iv = b"1234567887654321"

aes = AES.new(key=key, mode=AES.MODE_CBC, IV=iv)
ming_bs = aes.decrypt(base64.b64decode(s))
print(unpad(ming_bs, 16).decode("utf-8"))   # 去掉填充
```

## 5. JS 实现 AES（crypto-js）

```bash
npm install crypto-js
```

CryptoJS 的编码器：`enc.Utf8`（普通文本）、`enc.Hex`（十六进制）、`enc.Base64`。

```js
var CryptoJS = require("crypto-js");

// 加密
var key = "8888888888888888";
var key_bs = CryptoJS.enc.Utf8.parse(key);       // 全部处理成字节

var iv = "1234567887654321";
var iv_bs = CryptoJS.enc.Utf8.parse(iv);

var ming = "我是";
var ming_bs = CryptoJS.enc.Utf8.parse(ming);

var mi_bs = CryptoJS.AES.encrypt(ming_bs, key_bs, {
    iv: iv_bs,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.Pkcs7
});
console.log(mi_bs.toString());   // 默认输出 Base64 字符串

// 解密
var mi_s = "wGZgsMhXpyp1Th8aS7F31kNICAIvcCoVqn9WO11B2pk=";
var result = CryptoJS.AES.decrypt(mi_s, key_bs, {
    iv: iv_bs,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.Pkcs7
});
console.log(result.toString(CryptoJS.enc.Utf8));   // 还原成字符串
```

> 注意：JS 的 AES 与 Python 对应关系——`CryptoJS.mode.CBC` ↔ `AES.MODE_CBC`；`CryptoJS.pad.Pkcs7` ↔ Python 的 `pad(..., 16)`。

## 5·补、AES-ECB 模式（无 IV）

ECB 模式**不需要 IV**，代码比 CBC 更简单。逆向遇到"只有 key、没有 iv"的多半是 ECB：

```python
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
import base64

# 加密（ECB 不需要 IV）
s = "我爱你"
key = b"6666666666666666"
aes = AES.new(key=key, mode=AES.MODE_ECB)
bs = aes.encrypt(pad(s.encode("utf-8"), 16))
print(base64.b64encode(bs).decode())

# 解密
s = "密文base64"
aes = AES.new(key=key, mode=AES.MODE_ECB)
ming_bs = aes.decrypt(base64.b64decode(s))
print(unpad(ming_bs, 16).decode("utf-8"))
```

```js
// JS 版 AES-ECB：去掉 iv 和 IV 配置即可
var CryptoJS = require("crypto-js");
var key_bs = CryptoJS.enc.Utf8.parse("6666666666666666");

var mi_bs = CryptoJS.AES.encrypt("我爱你", key_bs, {
    mode: CryptoJS.mode.ECB,
    padding: CryptoJS.pad.Pkcs7
});
console.log(mi_bs.toString());          // Base64
```

> **ECB vs CBC 一句话**：ECB 无 IV、相同明文得到相同密文（安全性差，但代码简单）；CBC 有 IV、相同明文也得到不同密文。逆向看到 `encrypt(明文, key)`（只有两个参数）多半是 ECB。

## 5·补、AES-GCM 模式（现代接口常用）

GCM 是认证加密，除了密钥还需要 12 字节的 **nonce（IV）**，解密时还会校验 **tag（认证标签）**。Python 用法：

```python
from Crypto.Cipher import AES
import base64

# 加密
key = b"6666666666666666"      # 16 字节
nonce = b"123456789012"        # 12 字节（GCM 的 IV）
s = "我爱你"

cipher = AES.new(key=key, mode=AES.MODE_GCM, nonce=nonce)
ct, tag = cipher.encrypt_and_digest(s.encode("utf-8"))
print(base64.b64encode(ct).decode())   # 密文
print(base64.b64encode(tag).decode())  # tag（认证标签，16 字节）

# 解密（需要密文 + tag + nonce）
cipher = AES.new(key=key, mode=AES.MODE_GCM, nonce=nonce)
ming = cipher.decrypt_and_verify(ct, tag)
print(ming.decode("utf-8"))
```

```js
// JS 版 AES-GCM（Node 内置 crypto 即可）
var crypto = require("crypto");
var key = Buffer.from("6666666666666666", "utf8");
var nonce = Buffer.from("123456789012", "utf8");

// 加密
var cipher = crypto.createCipheriv("aes-128-gcm", key, nonce);
var enc = Buffer.concat([cipher.update("我爱你", "utf8"), cipher.final()]);
var tag = cipher.getAuthTag();
console.log(enc.toString("base64"));
console.log(tag.toString("base64"));

// 解密
var decipher = crypto.createDecipheriv("aes-128-gcm", key, nonce);
decipher.setAuthTag(tag);
var dec = Buffer.concat([decipher.update(enc), decipher.final()]);
console.log(dec.toString("utf8"));
```

> **GCM 逆向特征**：请求/响应里同时出现"密文"和"tag"两个字段，且代码里出现 `GCM`、`nonce`、`getAuthTag` 等关键字时，基本就是 AES-GCM。注意 node-jsencrypt / crypto-js 老版本不直接支持 GCM。

# 六、非对称加密：RSA

## 1. 什么是非对称加密

加密和解密使用**不同的密钥**：

- **公钥**：公开，用于加密；
- **私钥**：保密，用于解密。

常见算法：**RSA、DSA**。RSA 是最常见的方案。

> **RSA 特征**：公钥指数常为 `10001`（即 65537）——在网页代码里看到 `10001/65537` 基本可断定是 RSA。
>
> **RSA 每次加密结果都不一样**（因为随机填充），这是它与对称加密的一个直观区别。

## 2. Python 生成公钥/私钥

```python
from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_v1_5
from Crypto import Random
import base64

gen_random = Random.new

# 生成 1024 位密钥（生产推荐 2048）
rsakey = RSA.generate(1024)

# 导出公钥
with open("rsa.public.pem", mode="wb") as f:
    f.write(rsakey.publickey().exportKey())

# 导出私钥
with open("rsa.private.pem", mode="wb") as f:
    f.write(rsakey.exportKey())
```

## 3. Python 加密（用公钥）

```python
from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_v1_5
import base64

data = "我要吃饭了"

with open("rsa.public.pem", mode="r") as f:
    pk = f.read()
    rsa_pk = RSA.importKey(pk)
    rsa = PKCS1_v1_5.new(rsa_pk)
    result = rsa.encrypt(data.encode("utf-8"))

    # 处理成 base64 方便传输
    b64_result = base64.b64encode(result).decode("utf-8")
    print(b64_result)
```

## 4. Python 解密（用私钥）

```python
from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_v1_5
from Crypto import Random
import base64

gen_random = Random.new
data = "e/spTGg3roda+iqLK4e2bckNMSgXSNosOVLtWN+ArgaIDgYONPIU9i0rIeTj0ywwXnTIPU734EIoKRFQsLmPpJK4Htte+QlcgRFbuj/hCW1uWiB3mCbyU3ZHKo/Y9UjYMuMfk+H6m8OWHtr+tWjiinMNURQpxbsTiT/1cfifWo4="

with open("rsa.private.pem", mode="r") as f:
    prikey = f.read()
    rsa_pk = RSA.importKey(prikey)
    rsa = PKCS1_v1_5.new(rsa_pk)
    result = rsa.decrypt(base64.b64decode(data), gen_random)
    print(result.decode("utf-8"))
```

var JSEncrypt = require("node-jsencrypt");

## 6. 网页端常见的 RSA 逻辑（三套）

1. **网易云音乐那套**（古老库）：

# 七、JS 逆向找加密逻辑的完整流程

掌握了各种加密算法后，最关键的是**怎么在网页里找到加密逻辑**。完整流程如下：

## 1. 定位加密接口

打开浏览器开发者工具（F12）→ **Network** → 找到我们要分析的数据请求 → 查看 **Payload / Params**，确认哪些参数是加密的（通常是 `sign`、`token`、`enc`、`password` 等）。

## 2. 搜索关键字（全局搜索）

在 Sources 面板按 `Ctrl+Shift+F` 全局搜索加密参数名（如 `sign`），或搜索算法特征关键字：

```js
// 常见搜索词（按加密算法特征搜）
"md5"        "sha256"     "HmacSHA1"    "HmacSHA256"
"encrypt"    "decrypt"    "AES"         "DES"         "RSA"
"setPublicKey"   "JSEncrypt"   "CryptoJS"   "sign"
"10001"      "65537"      "charCodeAt"  "toString(16)"   // 手写加密的特征
```

> 看到 `charCodeAt` + `^`（异或）+ `toString(16)` 的组合，很可能是**手写异或加密**，没有现成库，需要照着算法用 Python 重写。

## 3. 打断点 / Hook 定位入口

- 在 `encrypt`、`sign` 生成处打断点，单步跟踪参数来源；
- 或直接在控制台 Hook `JSON.stringify` / `JSON.parse` / `XMLHttpRequest.prototype.open`，把加密前后数据都打出来（见 JS 进阶的 Hook 章节）。

## 4. 在 Node 中复现

把找到的加密 JS 代码放到 Node 里跑，逐行对照：

```js
// 1. 用浏览器环境变量补齐（window/document 等没有）
// 2. 缺失的函数用 Node 自带能力实现
var crypto = require("crypto");

function md5(s) {
    return crypto.createHash("md5").update(s, "utf8").digest("hex");
}

// 复现网页里的加密逻辑
var t = new Date().getTime();            // 时间戳（若算法用到）
var sign = md5("name=alex" + t + "密钥"); // 假设网页里是这种拼接
console.log(sign);
```

## 5. 用 Python 复现并在爬虫中调用

拿到算法后，用 Python 实现同样逻辑（或调用 Node 脚本），完成爬虫：

```python
import time, hashlib, requests

def make_sign(name):
    t = int(time.time() * 1000)
    sign = hashlib.md5(f"name={name}{t}密钥".encode()).hexdigest()
    return t, sign

t, sign = make_sign("alex")
resp = requests.post("https://example.com/api", json={
    "name": "alex", "t": t, "sign": sign
})
print(resp.text)
```

> **注意**：若加密逻辑过于复杂（依赖 window/document/DOM），可以用 `execjs`（PyExecJS）直接在 Python 里调用 Node 跑那段 JS，最省事。

## 6. 常见套路汇总

| 场景 | 判断 | 处理 |
| ---- | ---- | ---- |
| 密码加密后是 32 位 hex | MD5（可能加盐/多次） | 找到拼接规则用 md5 复现 |
| 请求体里有 `sign` 且用到密钥 | HMAC 或 MD5+盐 | 从 JS 里找到 key 和拼接顺序 |
| 大段 base64 密文 + 有 key/iv | AES-CBC | 用 AES 复现 |
| 密文固定不变（每次请求一样） | 无随机填充的 RSA 或 AES-ECB | 复现后结果可直接比对 |
| 密文每次都不一样 | 有随机填充（RSA/带IV的CBC/GCM） | 必须每次实时计算，不能缓存 |

# 八、加密识别速查表

| 密文特征 | 可能是 | 处理方式 |
| -------- | ------ | -------- |
| 32 位十六进制（`0-9a-f`） | MD5 | 不可逆，用于比对/签名 |
| 40 / 64 / 128 位十六进制 | SHA1 / SHA256 / SHA512 | 不可逆 |
| 需要密钥参与的 64 位十六进制 | HMAC-SHA256 | 用密钥复现签名 |
| 由 `A-Za-z0-9+/=` 组成、长度是 4 的倍数 | Base64 | `base64.b64decode` |
| 含 `-_` 且无 `=` 的"Base64" | Base64URL | `b64decode(mi, b"-_")` |
| URL 参数里的 `%xx` | URLEncode | `unquote` |
| 加密结果固定且用公钥 | RSA（无随机填充） | RSA 公钥加密复现 |
| 代码里有 `10001` / `65537` | RSA | 公钥加密复现 |
| 16 字节 key + IV + CBC | AES-128-CBC | AES 加密复现 |
| 16 字节 key + 12 字节 IV + tag | AES-GCM | AES-GCM 加密复现 |
| 8 字节 key + IV | DES | DES 加密复现 |

# 九、小结

- **编码**（可逆还原）：Base64、Base64URL、URLEncode、字符编码（GBK/UTF-8）、Node Buffer 编码互转；
- **摘要/哈希**（不可逆）：MD5、SHA1、SHA256、SHA512、HMAC（带密钥），用于签名和指纹；
- **对称加密**（同一密钥）：AES（CBC/ECB/GCM）、DES、3DES，注意密钥长度、模式和 IV、填充方式（PKCS7）；
- **非对称加密**（公钥加密/私钥解密）：RSA，特征是指数 `10001`，密文每次不同；
- **识别思路**：先看密文长度/字符集猜算法（32 位 hex→MD5，A-Za-z0-9+/=→Base64，含 `10001`→RSA，有 key+iv→AES）；
- 做 JS 逆向时：**定位接口 → 全局搜关键字 → 断点/Hook → Node 复现 → Python 调用**，完整流程见第七节。
